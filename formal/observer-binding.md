# Native observer release claim binding

Specification §12.3.1.1 adds two fixed composition ports to the existing trusted
publication observer: releaseBoundPublicationEvent and releaseBoundPublicationOutcome.
They bind a first-party lowered original claim before current loss processing.
They are not public request schemas, a new observer owner or a new result route.

## Original attribution and current authority

The actual opaque owner resolves its private retained scope. The lowered claim
must have the existing bounded native structure, original outcome epoch and equal
fixed scope fields. Unknown/copied/wrong-role owners and foreign claims return
unavailable before invoking trusted release. No public caller must discover or
submit private annotation identities to satisfy this native check; the facade
still needs original reference/issuer resolution and first-party lowering.

The independently supplied current context/facts must refer to this exact owner.
They retain the existing complete inert trusted-port premise; caller values cannot
authenticate policy truth or substitute another observer's facts. Genuine accepted
loss remains absorbing. Caller outcome flags are not a projection request and
grant no authority: the retained capture ceiling and trusted current policy still
govern the actual result. Temporary release/resource/retention/transfer pressure
preserves the existing queue/outcome behavior rather than establishing context loss.

The old trusted /2 helpers and their deliberate context-change fencing are unchanged.
The guarded ports cover release only, not public stream establishment, resync,
grant revocation or sampling from an independently established actual engine root.
The existing minimal publication-outcome handle is not an operation-specific
F13/F14/F16/F17 receipt, so U01 remains unselected.

## Preservation and bounds

Under finite prebounded normalized inert inputs, truthful complete independently
attributed current ports and serialized non-reentrant execution, the original-
claim guard reads only the retained original scope and bounded claim. No observer
write occurs on guard refusal. Original state therefore survives a refused claim;
on success the existing native release alone determines loss or delivery. No await,
provider I/O or caller callback separates those decisions.

The guard stores no new scope copy, handle or result hold. Fixed field comparison
and existing native context/projection limits bound its normalized reference work.
It does not establish hostile preallocation costs, physical memory/time, general
Proxy containment, actual policy/identity truth or concurrent/crash refinement.
Event dequeue and outcome release are separate calls; there is no newly promised
joint delivery transaction or refund of retained obligations.

## Executable evidence

Run node formal/observer-binding-mutations.mjs. The actual observer source is loaded
as one coherent module after resolving its existing dependencies. Its unchanged
baseline must pass before eight targeted mutations can count as assertion failures;
construction/import/tool failures are not semantic detections.

Five controls cover 44 foreign/malformed claims, 28 owner/outcome role substitutions,
sixteen independently attributed losses, sixteen temporary-pressure cases and six
policy-intersection cases. Actual common invocation publication supplies committed
producer roots and outcomes; both producer routes run. Exact observer usage and
producer frames are compared. This is not an F19 typed/dynamic facade test.

Mutants omit each release guard, omit original epoch/scope binding, replace each
trusted current context with caller claims, or widen each current authorization
fact. Existing ten-control/twelve-mutation observer semantics remain separate
regressions. Finite tests and this preservation argument do not prove whole-engine
categorical completeness, a general bounded lattice or independent certification.
