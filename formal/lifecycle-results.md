# Native lifecycle result products

Existing lifecycle and relation receipts use four closed structural shapes.
Construction and current release share the same immutable declarations and
validators. No command, public query, wire profile, receipt field or authority
handle is added.

| Shape | Existing fields | Correlation |
| --- | --- | --- |
| Document lifecycle and SaveAs | invocation, status, operation, document | Existing native operation and applied/unchanged vocabulary; per-operation feasibility remains a native semantic check |
| Source load | invocation, status, operation, activation, document | created maps to applied; joined and already-activated map to unchanged |
| Annotation load | invocation, status, operation, phase, disposition, document | restore admits restored/applied or unchanged/unchanged; adopt-baseline admits installed/applied or current/unchanged |
| Container lifecycle | invocation, status, kind, target | Existing view/workspace kinds and created/retired statuses |

The result envelope is exactly result plus receipt, or unavailable without a
receipt. Identities retain authority/id/incarnation with existing UTF-8 label and
safe-natural semantics. Ordinary/null prototypes and field-order variation are
accepted; unknown fields, accessors, symbols, non-enumerable fields, malformed
identities and unknown discriminators refuse. Validation does not coerce values
into discriminator keys. Internal binding/annotation/provenance discharge
receipts retain their native vocabulary without becoming public commands.

Shape is not capability authenticity, currentness, target ownership or permission.
A copied/foreign identity can be structurally valid. Original domain/ticket,
captured identifier ceiling, current recipient context, whole-outcome availability
and operation-specific current release facts remain independently required.
The existing maximum applies to the complete result envelope; no new numeric
default, parent reservation or physical bound is inferred.

Native construction checks the receipt before installing its stage or committing
the producer. A malformed native receipt first discards that preparation, then
raises a protocol fault through the existing invocation fence. The root remains
unchanged and the original ticket retains protected retirement. Issuance/start
history is not refunded. Current release refuses malformed retained values
without changing the authoritative operation outcome.

## Conditional preservation argument

Under the existing serialized native owner/profile premises, valid constructors
produce one of the declared shapes. Exact field sets distinguish the four
structures; explicit source-load and annotation phase/disposition maps reject
contradictory status combinations. Document status shape alone does not prove
that every operation/status combination is executable.

The guard precedes native stage installation and the corresponding producer
commit call. On its fault branch, the existing native discard removes the
prepared certificate before the coordinator fences the invocation. The scoped
fault witnesses inspect that discarded certificate while the domain is still
healthy, count calls at the five native producer commit sites, and check the
original root and ticket retirement. This is not rollback of external I/O,
physical reclamation or arbitrary native-fault containment.

Current release retains its existing authority/ceiling/whole-envelope checks.
Neither the shared declaration nor a successful structural validation supplies
an invocation handle, exposes a hidden operation, expands an old grant or
reclassifies unavailable as known nonapplication.

## Evidence and remaining boundaries

Six controls cover 48 actual native publications/results, including joined,
already-activated, unchanged restoration/current baseline and private discharge
cases; 1,136 malformed-value refusals; 56 current release cases; six complete
envelope byte boundaries; and 178 structural positives including field ordering
and null prototypes. Fourteen schema/validator mutants and ten constructor/
discard mutants fail semantic assertions in isolated copied graphs. Import,
construction and tool failures are not detections.

Twenty-eight fixed malformed-receipt cases span the fourteen selected public
forms through both routes. Native discard witnesses are true in all cases,
targeted producer commit-call count is zero, roots remain unchanged, and the
original tickets retire. The legacy native lifecycle/load/annotation/SaveAs/
container regression banks remain separate qualification obligations.

The selected engine graph is 96 modules and retains frontend exclusion and
clean-entrypoint checks. No architectural component/interface is added.
IF-01/03/08/10 and INS-01/02/03/08/12/13 distinguish preparation, publication,
result refusal, protocol fault and protected cleanup. Record bounded operation/
phase/disposition classes, not raw receipts, identity strings or hidden counts.
Schema refusal is not a new producer failure or a diagnostic content grant.

Northbound operation-specific result access, full F17 discovery/events,
additional profiles, actual-parent temporary/physical costs, installed telemetry,
host measurements and independent assurance remain open. Full frozen
qualification and endpoint reconciliation remain adoption gates. Finite
structural coverage does not establish whole-engine categorical completeness.
