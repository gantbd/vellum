# Initial native annotation restoration

Specification §16.5.11 restores an evidence-complete version 1 snapshot into an
explicitly known-empty managed annotation inventory. It composes the accepted
snapshot decoder/stager, host association shape, managed membership floors, shared
native publication boundary and reservation laws. The storage-boundary producer
in annotation-restoration.mjs decodes and validates serialized values; the
format-neutral owned participant in annotation-restoration-state.mjs seals native
records and validates publication without importing a snapshot parser/schema.
The native owner consumes only that typed participant, not JSON bytes. It does not
complete provider reads, loaded-baseline adoption, nonempty replacement or implicit
merging. Section 16.5.13 separately composes its actual owned-read/native path and
producing-read retention in annotation-native-load.md; this raw-input helper does
not infer provider provenance from bytes.

## Scope and identity boundaries

The boundary coordinator obtains the actual native owner's current root/domain/context. Live records and
lifecycle entries for the target must both be empty. Missing legacy metadata does
not establish emptiness; retained-absent and retired slots refuse. Existing retained
annotation history participants for the target also refuse. Source-only history
and unrelated peer history are preserved, not discarded to make restoration fit.

The version 1 decoder validates complete bounded syntax and semantic shape before
native translation. The host association reuses the capture profile's context,
document, sourceRevision, annotationSet, association, identities and sources fields.
An exact current restorationBasis binds context/document/full map/decoded snapshot;
sixteen restoration facts and the four existing membership facts must be exactly
true. These are current host authority/identity/history premises, not authority
inferred from the file or independent verification of the host registry.

External namespace/value aliases and native IDs are injective. The explicit native
incarnation must equal the exact incoming incarnation. The current source row
equals actual native source bytes and current snapshot evidence; each historical
authored target requires its own revision/evidence/byte row and current historical
attestation. No extra unrelated source rows or alias rows are accepted. All target
positions are checked against the corresponding actual supplied UTF-8 source unit,
not merely a declared length. The same source token cannot masquerade as another
length to evade the current-source checks.

Missing historical evidence refuses this native profile intact. This is not a
promise to restore every syntactically valid snapshot whose historical source is
unavailable, nor permission to repair a target by guessing a quote or adjacent
location. The input and existing managed state are preserved on refusal; a broader
missing-history/detached-import representation remains a separate profile decision.

## Exact native values and ownership

Accepted bodies, order, authored/current targets, attached/affected/detached states
and both independent position/content point profiles are preserved. Canonical
decimal strings translate exactly into the existing native reference's positive
safe-integer identity/version domain. Unsupported larger values refuse without
rounding, truncation or renumbering. This is a reference-domain boundary, not a
universal product integer width or rejection of the storage format's larger values.

Initial body/target floors come from independently attested restoration values in
fresh managed slots. They are not live edit preconditions accepted from a file.
Local emptiness is necessary but cannot prove cross-process identity continuity or
global registry floors; current identity/history facts must establish those. A
retired local slot is never silently treated as fresh absence or reidentified.
Document identity, ordinary bindings/resource owners and permissions are unchanged.

The boundary validates parsed values and seals a format-neutral private plan with
immutable translated records, an opaque whole-proposal attestation, the
finite profile, association proof and target dependencies. Its complete logical
record must fit the existing plan budget. The normal native entry point prepares,
consumes and discards it synchronously, exposing neither a plan nor a raw root.
Separate producer/consumer facets are confined trusted composition/testing seams,
not selected public token/request APIs. Actual package privacy remains a premise.

## Final publication and frames

Final consumption rechecks domain identity, current target basis, proof/grants,
membership/history readiness and historical evidence. Current target source/set,
inventory or binding changes refuse; unrelated peer edits can proceed and are
preserved by constructing from the latest actual collection.

Nonempty hydration replaces only the empty records/inventory with the complete
translated records/present slots and advances annotation set/publication once.
Both arithmetic and current version capacity are checked. Native consumption
independently restores those fields in a comparison frame and requires complete
equality with the before-root. Source/revision, views, peers, owners, bindings,
baselines, groups/frontiers and other fields therefore remain unchanged.

The actual attached baseline pool validates the complete candidate against every
remaining promise. A reserved last publication unit cannot be spent by restoration;
releasing its real obligation may permit the otherwise valid import. This closes
this new publication route's floor integration, not every other legacy host route.

Existing committed parser-source receipt identities carry through an exact
annotation-only frame without new transforms. Invalid/absent optional evidence is
not fabricated. Subsequent body edits and reversal advance restored version floors;
source undo maps loaded placements without erasing loaded authored bodies. Initial
hydration itself does not create an authored undo group or reset source history.

Empty input against a known-empty inventory is validated unchanged, including at
exhausted generations. It does not publish a metadata-only content change. Expected
refusal preserves original input/live root; malformed/unsupported data is not
rewritten or migrated. Final trusted assignments remain subject to serialized
bounded installation, not a proof of arbitrary concurrency/crash atomicity.

## Conditional preservation arguments

For finite normalized profiles/inputs, immutable captures, confined factories,
truthful current authority/association/registry/history facts and serialized final
transitions:

1. Decode/stage validates complete exact schema, associations and bounds before
   acceptance. Injective maps and exact numeric translation preserve supported
   identities/versions without collision, rollback or implicit reidentification.
2. Each target is translated through its unique evidenced source unit. Native
   offsets/profile/state and source revision preserve the accepted authored and
   placed meaning as data; current placement still depends on the host's actual
   mapping/continuity attestation rather than parsing alone.
3. Because both target live inventory and all lifecycle slots are empty and current
   annotation history is compatible, restoration cannot overwrite a concurrent
   comment or revive a retained/retired slot. Final target-basis revalidation closes
   the preparation/publication race; latest-root construction preserves peers.
4. Fresh present-slot floors equal the supported attested incoming values. Existing
   mutation/reversal rules thereafter increase those floors rather than treating
   persisted versions as reusable edit authority. Fresh source revisions remain
   separate from unchanged authored target intent.
5. The complete root frame permits only declared annotation state/counters. The
   existing reservation floor law prevents stealing other promised capacity.
   Exact parser receipt carry preserves source evidence without minting a source
   transform or importing executable behavior.
6. Applying existing capture to the restored state with the corresponding explicit
   association reproduces every accepted snapshot value, including record order,
   body strings, canonical numeric strings and independent point profiles.

These are authored conditional finite-state/frame/round-trip arguments plus actual
reference checks, not proof-assistant induction, new SMT conditions, independent
Cleanroom certification or whole-engine categorical closure. Semantic round trip
does not mean original JSON formatting/member order/escape spelling round trips
byte-for-byte; the original input is unchanged and source-file fidelity is separate.
