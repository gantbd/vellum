# Exact retained annotation output comparison

Specification §16.5.2 supplies a comparison dependency without choosing the pending
ordinary source/annotation destination-binding policy. Compare two actual retained
native annotation outputs in the existing codec owner. The result concerns those
bytes only; it establishes no saved baseline, binding, current external contents,
write acknowledgment, semantic identity, load applicability or restoration right.

## Operand and result contract

The helper accepts trusted normalized references, bases and current facts. Its
byte-work bound is not a hostile JavaScript object decoder/admission proof;
arbitrary getters, cyclic objects and unbounded caller-authored bases are outside
this reference boundary. Public decoding needs its own validated finite schema.

Both operands must be owned live annotation artifacts. Each must have its complete
original context/document/source/set basis and independent exact-true current
read/disclosure/resource/retention/transfer/reply and comparison facts. Stopped,
retired, foreign, cloned and source-artifact references refuse. Read permission
alone does not substitute for the separate comparison grant. Source-read authority
is not required and cannot replace annotation disclosure.

This helper compares only one document incarnation under one identical normalized
context. Separate grants for two contexts do not themselves establish authority to
correlate them in a third result. A future cross-context/document product would
need its own joint disclosure contract; none is selected here. Source revision
and annotation-set versions may differ across the two historical operands, but
each supplied basis must match its own capture exactly. Later edits do not refresh
either operand or its basis.

Bound work by the sum of both complete byte lengths against the existing codec
comparison budget. Compare the exact stored byte strings, not equal lengths,
revision tuples, text bodies, hashes or a normalized JSON projection. The reply
contains equal/different plus each operand's historical source/set versions and
byte length, not source/annotation bodies or a discrepancy offset. Bound its
complete frame and return owned metadata. Do not mutate artifacts, stop flags,
native roots, invocation state, held occupancy or lifetime issuance.

The static capture profile may already dominate a small comparison reply's size;
the final reply check remains present, but the checks do not claim an independent
reachable comparison-reply-exhaustion witness. Neither logical comparison units
nor frame size prove physical peak allocation or timing noninterference.

## Conditional arguments and executable evidence

For valid immutable finite codec rows and truthful current facts:

1. Successful comparison requires two owned annotation rows, their respective
   exact bases and both independent current grants. A missing grant, wrong kind,
   cross-context/document pairing or stopped/retired operand has no result path.
2. Byte equality is reflexive and symmetric. The reference's direct equality over
   admitted byte arrays yields equal exactly when lengths and every indexed octet
   agree. No parser equivalence, version equality or digest premise replaces it.
3. Complete source association and annotation versions are part of the approved
   serialized snapshot. Equal bodies after undo need not yield equal bytes, while
   duplicate captures of an unchanged root can. Both outcomes preserve the original
   artifact meaning; they do not change the adopted storage format.
4. Bounded operand lengths give a finite comparison scan. The result includes only
   copied historical metadata and all branches frame owner/native state. This is
   a conditional reference argument, not a native implementation or scheduler proof.

The actual-code checks exercise 42 native capture/undo/redo cases, 8,192 release
decisions (each operand's twelve-fact masks independently), twenty original-basis
negatives and ten controls. Controls include same-length changed native content,
identical generations with changed host association bytes, historical captures,
actual cross-context/document artifacts, kind/ownership/stop/retirement, strict
nonboolean refusal, both-operand work bounds and returned-value isolation.
The masks do not enumerate the full pairwise 24-fact cross-product.

Twelve assertion-detected mutations follow a passing dynamically rewired baseline.
Syntax/import failures are not detections. Existing source, annotation-retention
and writer suites retain their scopes/counts. Solver totals remain 223 conditions
in thirteen manifests; these tests do not manufacture additional solver theorems
or independent Cleanroom certification.

## Precedent and observations

[Rust slice equality](https://doc.rust-lang.org/src/core/slice/cmp.rs.html)
provides direct implementation precedent for length and element comparison,
including specialized byte comparison. This helper also follows the existing
§16.1.1 source codec's exact-byte comparison pattern; it selects no Rust version,
library/runtime dependency or differing-byte disclosure. Independent grants, retained bases
and bounded minimized replies derive from its adopted release/resource contracts,
not a claim to inherit a library's authority model or proof.

Reuse PATH-05/IF-01/13 and INS-01/03/07/08/12. MELT, RED/USE and golden signals
separate offered/permitted/refused comparisons, admitted byte-work size, latency,
reply refusal and retained occupancy from saves and useful persistence. STRIDE
covers type confusion, cross-context correlation, stale bases, one-sided grants
and quota bypass; LINDDUN covers equality/existence linkage and historical metadata.
No raw body, basis, resource path, identity or exact comparison outcome is an
ordinary high-cardinality label. Actual installed telemetry, overhead and timing
noninterference remain unproved.

Ordinary annotation destination/binding compatibility is fixed by specification
§16.2.3; this comparison helper neither selects nor enforces binding activation.
Its scope flag `annotationBindingPolicySelected: false` describes this helper,
not an unanswered user choice. Saved-baseline election/current-output integration, host alias/policy/
retention truth, restoration, provider behavior, global/physical accounting,
production/concurrency and independent assurance remain gates. This slice neither
chooses distinct versus shared source/annotation bindings nor closes D20/F21 or
the all-sections goal.
