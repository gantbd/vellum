# Lifecycle discovery products

The eight existing F17 variants have a fixed declarative descriptor under explicit
discovery profile owned-contract-discovery/10. It appends one row to profile /9;
profiles /1–/9 retain their pinned products. The fourteen existing input forms
cover scratch creation, attachment/detachment, membership, disposal, initial
source/annotation activation, baseline adoption, SaveAs/rebind and view/workspace
container creation/retirement. No executable operation, public result query,
event stream, wire encoding or deployment service is added.

## Structural products and native meaning

The descriptor consumes immutable native wrapper, field/profile and receipt
declarations lazily, after module initialization. Input schemas select exact
outer and selected inner fields using fixed contract/operation/profile/phase/
action discriminators. Container retirement retains its native generation tuple,
not a scalar revision. Four existing receipt shapes preserve source-load and
annotation phase/disposition status correlation. Private discharge operations
do not appear as public input or result branches.

The input coverage remains outer-structure-only. Nested object types do not
establish their native codecs, UTF-8 validity, authority, exact revisions,
dependency closure or resource budgets. Receipt structure does not authenticate
an original ticket, grant access or establish every operation/status pair as
executable. The descriptor states its existing-native-result-facet scope; it
does not silently add those receipts to F06 public queries.

The existing native owner, authority ports, preparation/publication/discharge
order, captured identifier ceiling and current summary/facet rights remain
mandatory. Positive advisory enablement is neither a reservation nor permission.
Recognizers accept the fixed generated schema/outcome trees only; no remote
reference loader, callback execution or generic engine schema interpreter exists.
The external standard validator is verification plumbing, not an engine component.

## Discovery ownership and resource boundaries

The existing context captures permitted metadata and disclosure ceilings.
Current loss stops the context without revival on regrant; unknown facts withhold
release without claiming known loss. Equal generic metadata cannot borrow fixed
builtin origin. Context, entry, variant and advice selectors cannot substitute
for native authority or invocation handles. Protected retirement preserves spent
issuance and requires retention release and delivery drain.

Existing entry/variant, metadata byte/node/depth, row, packet, capture and reply
envelopes apply independently. Failure to fit /10 leaves an admissible /9 usable.
No numeric default is raised. These are declared logical envelopes, not physical
allocation or actual-parent temporary reservation proofs.
