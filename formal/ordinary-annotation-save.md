# Ordinary annotation save admission

Specification §16.5.9 composes actual shared codec/writer ownership with the native
baseline capacity pool before admitting an ordinary annotation save. It follows
the existing ordinary-source-save distinction: use the active binding's resource
owner and shared destination FIFO, rather than allocating a copy-export destination
reservation or publishing an admission root. The external write remains a later,
separately attested effect; acknowledgment and baseline installation remain distinct.

## Scope and ownership

admitOrdinaryAnnotationSave takes an actual native domain and its attached pool.
The coordinator selects the actual current root, not a supplied state. The private
normalized annotation-save/1 descriptor has the existing annotation-export fields
with operation captured-annotation-save. Only its active ordinary, known-distinct
annotation destination is eligible. Presence is present and conditions retain the
existing pinned profile; this does not invent annotation causal-chain progression,
SaveAs, implicit rebind or an external location convention. The private descriptor
does not select a public request/token codec or a new native job kind.

The existing annotation writer's common candidate checks cover expected source/
set/source binding, registration, ownership, current ordinary pair, permissions,
receipt/capture bounds, duplicate origins, writer slots, destination FIFO pressure
and retained headroom. The ordinary branch captures the actual annotation binding
generation and omits copy-export receipt metadata. Active ownership is not an
external or distributed mutex, and no exportOrigins entry is created.

## Preparation and final commit

The shared codec prepares the exact native annotation bytes and reserves logical
preparation storage plus an artifact slot/future issuance unit. Its private
inspection facet returns copied original bytes/basis under current exact-true
grants, exact root identity and native health, never a mutable payload alias.
Inspection is an internal producer input, not recipient possession-based authority.

The writer builds a prospective queued ticket and future baseline claim without
registering either as live work. The complete claim descriptor is separately
charged. The actual native pool validates original domain/full binding/registration,
matching evidence limits, exact source/set and context, and runs the existing
capacity law against a private copy of its ledger. Only a copied new hold is
staged; existing live rows, charges, counters and producer pins are untouched.
The prospective charged record includes its actual nominal claim reference.

Before issuance, validate the attached actual pool, exact root, prepared claim,
live pool counters/charges/count, current gates and remaining root/counter floors.
In one serialized trusted segment, commit the prepared codec artifact, install
the actual writer ticket and consumed origin, link the actual claim and install
the actual hold. The coordinator returns a task only after that segment succeeds.
No root or publication generation changes at admission, so the promised future
publication unit remains available to baseline installation.

Expected refusal before issuance discards codec/claim/capacity preparations and
leaves all live ledgers and native state unchanged, including consumed lifetime
issuance. The same unpublished origin can later be admitted. This does not recycle
an already-issued identity. Temporary private copies rely on the existing parent
preparation reservation, not on a claim of complete global or physical accounting.

Under immutable normalized inputs, confined factories and serialized transitions,
bounded final assignments have no intervening host/user callback, await or effect
that could invalidate their validation. An unexpected post-issuance final-commit
failure faults the native domain and raises a trusted invariant failure, retaining
charged issued evidence. It is not reported as clean refusal or refunded. Actual
concurrency, allocator/crash atomicity and recovery after violated premises remain
implementation/supervision gates; fail-hard retention is not a rollback proof.

## Dispatch and lifecycle composition

The ordinary ticket enters the same writer/task/origin/codec accounting and FIFO
as existing source and annotation writes. Current dispatch requires the actual
native root, original source binding, current full annotation registration and
ordinary pair, overwrite/launch grants, a real linked hold and native health.
Historical queued bytes survive later authored edits without recapture.

Known written acknowledgment installs the actual baseline through §16.5.7 and
transfers its pending hold into retained actual producer ownership. Receipt
binding generation comes from the ordinary annotation binding, not an export
generation. Admission/dispatch do not change that binding or create an export
destination reservation. An explicit source copy-export can still share the same
destination FIFO under its separate authorization and supplied-root obligations.

A queued cancelled ordinary write can release its actual pending hold and retire
without a destination-root publication: its active resource ownership persists.
Dispatched nonapplication must still supply actual disposition and quiescence.
Unknown/written effects, destination quarantine, execution obligations and baseline
producer retention retain their existing independent gates. The ordinary path does
not weaken those facts into a single success, cancel or quiescence Boolean.

## Conditional preservation arguments

For the accepted finite normalized inputs and trusted serialized ownership:

1. Every admitted task originates in a checked native capture, a unique writer
   origin, current active ordinary binding and full provider registration. Its
   payload and future baseline derive from the same private bytes and basis.
2. Expected refusals precede issuance. Codec discard releases only unpublished
   preparation; private writer/claim records are not in the live registry and the
   capacity trial changes only its private ledger. Therefore original live roots,
   charges, task/artifact counts and lifetime issuance are preserved on refusal.
3. Writer admission includes ticket plus claim headroom. Codec commit consumes its
   reserved artifact/issuance unit once. Native hold commit consumes one checked
   pool slot/lifetime unit and exact charged record. No separate lane evades the
   existing quotas or destination FIFO.
4. Native capacity staging checks every remaining hold through the existing floor
   law. Admission changes no root/counter, so the new promised baseline unit is
   not spent by admission. Later publication must preserve those same floors.
5. Exact current native launch checks prevent supplied-state substitution. Pending
   historical bytes remain exact after later edits, and the existing installer
   retains their actual producer evidence. Control and nonapplication cleanup do
   not erase unknown effects or decrement consumed lifetime issuance.

These are authored conditional frame/accounting/ownership arguments and actual
reference-code checks, not proof-assistant induction, new SMT conditions,
independent Cleanroom certification or whole-engine categorical closure.

## Executable evidence

ordinary-annotation-save-checks.mjs covers fourteen native operation variants over
capture, undo and redo: 42 admitted/dispatched/acknowledged/installed stages. Each
checks actual shared writer/codec/pool issuance, absence of leaked preparation,
unchanged admission root, no export ownership record, actual baseline installation
and exact bytes. For each of 27 required fact gates, false, nonboolean and missing
values refuse with unchanged ledgers, followed by a positive sibling: 81 cases.
This is single-gate coverage, not the complete Cartesian product of all facts.

Nineteen controls cover pool refusal, unpublished origin reuse, writer/codec/pool
limits, distinct active destinations, foreign owners/domains/pools/bases, ordinary
receipt generations, actual-root/current dispatch, cancellation, nonapplication
disposition/quiescence, historical capture, FIFO, final publication-unit capacity,
native fault, stopped pools/evidence-limit mismatch, claim charges, closed request
kinds, current copied prepared-input inspection, mixed source-export/ordinary FIFO
and static package-private callsite confinement. The mixed FIFO test does not
prove installation of the legacy export's supplied destination root.

Twenty semantic mutants follow a passing dynamically rewired claim/pool/native/
artifact/codec/writer baseline. They spend origins early, leak failed preparation,
omit ticket/origin/claim charges or writer headroom, replace ordinary generation/
ownership with export semantics, weaken dispatch root/grants, omit hold linkage/
storage/charges/issuance, mutate the live trial ledger, ignore version limits or
all three native pool-ownership checks, open request kinds, omit artifact issuance
or substitute retained payload bytes. A trusted invariant sentinel on a positive
fixture is asserted as an unexpected commit failure; arbitrary runtime/import/
syntax/tool failures do not count as killed semantic mutants.
