# Existing discovery query self description

The F01 declaration describes the existing list, inspect and advisory-enablement
queries. It derives their fields from the declarations used by the native guards
and result validator. It adds no query, context issuer, public handle codec,
transport, schema evaluator or executable metadata. Access to the declaration is
lazy; importing the module does not invoke the declaration factory.

Input schemas describe the closed outer fields and scalar types. Opaque roles
remain object-valued: structural acceptance cannot prove original handle identity,
current authority, context acquisition or request-dependent reference equality.
Result schemas preserve unavailable, captured-permitted pages, descriptors with
hidden or complete visible facets, optional presentation, and strict Boolean
advice. Native UTF-8, metadata node/depth/byte bounds and current release checks
remain authoritative. Metadata slots accept inert JSON without recursively
expanding their contained schemas or fetching references.

Five controls cover three forms and variants. The corpus captures 237 actual
native replies across the twelve existing profiles, both decoded routes, paging,
hidden and partial disclosure, and copied-context/entry and foreign-profile
refusals. Verification-only JSON shadows replace opaque roles without inspecting
or serializing their contents. A hostile getter witness records zero reads.
Two additional structural witnesses cover the generic effect-request and
effect-observation kinds; these are shape-validator evidence, not native handler
registration or execution evidence.

The standard-schema corpus has 577 cases, including 87 syntax refusals. Eighteen
recognition refusals check the contract, variant and full fixed declaration.
Three native counterexamples demonstrate that schema-valid requests can lack
authority. Thirty-two pure descriptor mutations, partitioned into eight banks,
fail semantic assertions against a corpus constructed once per process.
Construction, import and tool errors do not count as mutation detections.

The standalone descriptor checks exclude native registration. The separate
integration corpus exercises explicit discovery /13: ten controls, ten native
typed/dynamic products, 43 metadata refusals, sixteen authority refusals and 27
independent minus/exact/plus boundaries across nine dimensions. All twelve older
catalog fingerprints remain unchanged. The /12 fingerprint was reproduced from
the frozen 0.197 candidate; qualification of that baseline remains required.
Twelve native integration mutations in three banks fail semantic assertions;
construction and unrelated exceptions do not count as detections.

The shared discovery substrate harness also exercises /13 without duplicating a
new owner or fault mechanism. It wraps 143 selected callable functions after
imports and fixture construction: fifteen baseline native products cause zero
substrate calls; three injected I/O/process attempts across direct, typed and
dynamic paths produce nine fault cases. The editing domain remains healthy and
original cleanup and temporary reservation refund remain available. This is
selected execution evidence, not import isolation or an all-API sandbox.

Integration preserves native authority, disclosure, bounded ownership and cleanup.
Current cold-initialization, frozen-suite qualification and endpoint adoption
remain required. Neither descriptor nor integration evidence closes the F01 family
or the complete public-products residual.

The existing IF-01/02, PATH-02 and INS-01/03/08/09/12/13 distinctions apply to
metadata release, refusal, loss, fault and cleanup. Diagnostics must not expose
document content, opaque roles or payload-derived labels. No new instrumentation
pathway, physical resource guarantee or independent certification is established.
