# Native owner attachment reference contract

This reference refines specification §17.4.2. Actual opaque handles and original
leases bind selected native owners to their invocation domains. The role catalog
is closed; factory/dependency completeness and whole shutdown are not inferred.

`invocation-publication.mjs` reserves a complete additional-child envelope and a
metadata frame covering pending, retained and one captured inventory form before
native exposure. Parent-funded pools keep their own existing charge and add only
edge metadata. Pending commit/abort and protected release require original identity.
Refused or throwing acquisition either unwinds or retains a genuinely surviving
native pool with its funding. Inventory requires the original domain context and
strict supervision; it is not a public query or total physical-cost report.

The shared writer's first actual sponsor funds the declared node; peers fund
distinct edges. No automatic transfer/refund or whole-writer retirement is claimed.
Historical source capture requires a genuine exposed immutable root belonging to
an attached, currently admitting domain; copied roots are refused. Annotation
provenance staging and ordinary ingress retain their actual binding checks.

The checks distinguish new tasks, contexts, cuts, search results, bases and plans
from exact retained lookup/retry and qualified evidence/bookkeeping. Root installers
deny authored activation across the fence while retaining guarded baseline and
disposed binding/provenance progress. Ordinary annotation-save capacity staging
uses the original admission section. Search/result/issuer discharge captures strict
facts once where composed and rechecks original retained identities after possible
reentry. Native publication wrappers derive roots and local terminal summaries
from actual domain/ticket state; unsupported producer facets remain unsupported.

`owner-attachment-native-checks.mjs` composes the actual factories, parent-funded
pools, shared writer, observation, existing-owner admission and root-installation
cases. `owner-attachment-mutations.mjs` uses coherent copied graphs and separates
construction failures from semantic detection. Mutation banks preserve the same
baseline and original scenario identities. Existing context/search, lifecycle,
read/write, annotation, catalog, settings and observer regressions remain required.
The dependency suites include reproduced recursive-release failures, exact charge/
refund boundaries, original issuer holds and the established finite search traces.

These checks do not establish a complete public dispatcher, all native ingress,
complete dependency inventory, shutdown consent/acceptance or a bounded controller.
Owners, unknown work, pins and spent origins without a demonstrated discharge
remain retained. Supplier authorization, service, clocks, physical accounting,
production Rust refinement and independent Cleanroom certification remain gates.
