# Acknowledged clipboard continuations and local invocation publication

Specification 0.213 §1.1 makes this an integration composition, not a mandatory
clipboard task registry or clipboard workflow command inside the semantic engine.
The combined reference's internal clipboard job, task pin and joint decision
remain scoped evidence for the stated observable invariants; they are not the
production core vocabulary or proof that implementation packages are separated.
Integration must preserve these invariants through the engine behavior facade.

Specification §6.5.3 joins an already acknowledged cut/paste task to the shared
root/invocation ledger. The local edit, terminal outcome and task disposition
agree in one serialized trusted decision. Provider acknowledgment and quiescence
remain independent. This reference does not close the public request/dispatch
replay gateway, copy operations, native provider truth or crash/concurrent refinement.

## Precedent and boundary

[Neovim nvim_paste](https://neovim.io/doc/user/api/#nvim_paste()) separates bulk
paste from mapped input. The [W3C clipboard working draft](https://www.w3.org/TR/2026/WD-clipboard-apis-20260624/#clipboard-actions)
separates copying, cut deletion and paste insertion. Neither establishes an atomic
transaction between a native clipboard and an editor ledger. Vellum retains its
adopted literal, original-target, exact-validation and layered-evidence contracts;
the joint local boundary is their composition, not a new external guarantee.

## Original continuation ownership

Issue the local invocation reference before the original transfer request. After
an accepted uncontested receipt, prepare one owned continuation capsule for that
same invocation, original task, request, registration, captured selection/export
and accepted receipt. No new continuation invocation is invented. Early preparation
before acknowledgment refuses without consuming local execution eligibility.
Quiescence alone is insufficient. Copy has no source-edit continuation here.

Only the original registry resolves a capsule. A matching retry needs its original
identity and complete bounded semantic value; a lookalike or new preparation is
not interchangeable. The ledger also bounds the kind/descriptor envelope, reserves
terminal result shapes and claims the capsule for exactly one owned ticket before
acceptance. Unknown, copied and differently claimed capsules refuse. Global engine
uniqueness remains the existing truthful-host premise, not a string comparison proof.
Current stop, conflict and quiescence are evidence/eligibility, not rewritten intent.

The capsule pins its task. The legacy standalone publisher cannot bypass that pin.
The private release helper rejects a claimed capsule until its local disposition
is terminal, even if owner/retention/drain flags are supplied prematurely.
Drained terminal ledger retirement releases the capsule binding, not provider work,
effect evidence, origin issuance or unknown local obligations. An unclaimed private
preparation may be released only under the same explicit owner/retention/drain
premises; it is not an automatic timeout or a recipient cleanup capability.

## Stage and joint local decision

One task holds at most one owned stage. Preparing the actual ordinary-edit candidate
does not mark the task published. Current target, registration, edit authority and
all existing annotation/view/history/resource checks still run. A successful stage
retains the exact before root, actual candidate root identity and their semantic signatures plus
bounded current eligibility facts. A copied stage, root/result mutation, changed
eligibility, stop or contested receipt cannot commit that candidate. Byte-equal root
clones cannot replace the owned candidate or its private journal bindings. The whole-root
guard is private staging integrity, not an admission dependency blocking unrelated
work for the lifetime of a clipboard task. Preparation and commit occur within the
same serialized engine decision; no provider call or arbitrary callback intervenes.

The outer ledger validates candidate protocol, its own root capacity and reserved
minimal outcome before the task disposition changes. An outer-capacity refusal
discards the candidate stage and stages known local nonpublication. A minimal
refusal stage holds no root copy and needs no fresh source-write grant. Explicit
stop or normal stale/permission/capacity refusal consumes local eligibility; it
does not become an implicit future retry. Legacy standalone validation refusal,
outside this ledger composition, does not itself terminalize an invocation.

After root freezing and complete validation, the trusted stage commit records
Applied, Unchanged or known NotApplied. Only owned root/fact/done assignments remain.
Under serialized, non-reentrant, nonthrowing trusted installation, no observer can
see a terminal task success without the matching root and retained terminal facts.
Unexpected preparation/protocol failure retains the prior root, records Unknown/
faulted, fences the domain and retains a local unknown obligation. Stop or ledger
retirement cannot erase that obligation. Real interruption, allocator failure,
concurrent/native installation and crash recovery require implementation refinement.

Reserve one additional maxEnvelopeBytes per admitted task for terminal-stage
bookkeeping. A successful stage additionally charges four maxRootBytes units for
declared before/candidate roots and semantic signatures, with checked arithmetic
and owner-held-capacity validation before candidate work. Minimal refusal uses
reserved bookkeeping without another root hold. Discard/commit releases staging
only, not external work; task retirement cannot release a live stage. These are
logical serialized-value units, not physical allocation/copy peaks or cross-owner
memory accounting. Existing producer/view/parser reservations remain required.

## Publication and external evidence are different facts

An acknowledged export followed by refused/stopped cut is local NotApplied with
confirmed external acceptance under its named profile, not effect None. Paste
acceptance likewise remains separate from insertion. A contested receipt yields
unknown effect; it never authorizes a cut. Terminal preflight reserves confirmed
and unknown effect variants for all five terminal shapes and 32 minimal-policy
combinations. Current release cannot widen the captured ceiling.

Retained invocation outcomes describe the local decision as of that decision.
Later contradiction updates the transfer owner's current evidence without rolling
back source or rewriting a delivered report. Live aggregation of all execution/
event products remains separate work. No-op paste is recorded as Unchanged, not
Applied. A copied-not-cut report requires accepted uncontested export and known
absence of local publication; unknown local disposition cannot be labeled that way.
Quiescence, delivery drain, session-reference release and retention discharge remain
independent retirement premises even after a successful or refused local decision.

## Conditional arguments and executable evidence

Assume normalized finite owned values, truthful current host grants/retention/
reservations, one authoritative engine and serialized non-reentrant decisions.
Capsule resolution and single-ticket claim prevent a second coordinator from
publishing the same task. Existing pending→running→done induction gives at most
one eligible start. Stage creation preserves task disposition; validation checks
its original receipt, root, candidate and eligibility. Candidate/outcome checks
precede task commit; only trusted assignments follow. Thus successful local root,
task disposition and terminal fact agree at the observable boundary. Known refusal
preserves the prior root and spends eligibility. Unexpected failure preserves
uncertainty rather than asserting a false rejection or discharging effects.

The fixed cut/paste sum, bounded descriptor/result tables and finite existing
ordinary-edit traversals give conditional per-run halting. They prove neither
provider halting, scheduler fairness, whole-engine categorical completeness nor
bounded-lattice closure. No new SMT law or proof-assistant refinement is claimed.

Checks cover 512 admission, 1,024 publication and 256 release combinations, all
720 six-action permutations for each continuation: 1,440 traces/8,640 edges.
Sixteen controls and eighteen assertion-rejected semantic mutants exercise original
ownership/acknowledgment, complete intent, single claim, outer root refusal, current
rights/stop, stage integrity/charge, pin/drain lifetime, no-op, current versus historical
evidence, fault containment, policy ceilings, actual equal-byte structured annotation
mapping and competing continuations on the shared current root. Existing clipboard,
pure-editing and base ledger suites remain separately revalidated evidence. Finite
traces and authored conditional arguments are not unbounded code verification or
independent Cleanroom certification.

## Instrumentation and remaining gates

PATH-01/06, DF-11 and existing IF-01/03/04/08 distinguish original provider work,
acknowledgment, local continuation binding, stage/validation, local disposition,
current outcome release, late evidence and retirement. INS-01 counts first binding
versus retry; INS-02 distinguishes stage from installation; INS-03 protects release;
INS-04 separates acknowledgment/unknown/quiescence; INS-06 covers actual history;
INS-11/13 cover capability and pin/stage/work retention. MELT/RED/golden signals
separate local useful completion from provider/observation latency. USE tracks stage
and pin saturation without treating discard as worker completion. STRIDE covers
forged capsules, claim substitution, stale-stage mutation and partial task/root/fact
installation; LINDDUN covers retained descriptors and cross-context correlation.
Use bounded phase/budget classes, never content, paths, private IDs, tokens or
per-attempt metric labels. Actual collectors, clocks and noninterference remain gates.

Full decoded clipboard admission/dispatch retry, copy and provider-effect gateways,
live outcome/event aggregation, native acknowledgment/retention truth, all companions,
actual concurrent/crash/physical/decoder/production and independent assurance remain
open. This adds no public verb, network path, engine component or numeric deployment
default and does not choose annotation point persistence or close a whole family/D-row.
