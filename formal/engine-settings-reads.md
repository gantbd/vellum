# Owned native engine settings inspection

Section 22.3.1.5 supplies a separate retained conditional mutation basis and scoped
ordinary settings invocation; see scoped-settings.md. It does not broaden these
read projections, release private layer identities/generations through F07 or turn
an origin/read selector into mutation authority.

Specification §22.2.1.1 connects F07 values, permitted origins and accepted
setting declarations to actual native configuration state. The reader uses the
engine's closed schema/resolution validator and actual shared owner; it does not
promote the trusted internal full snapshot API to a recipient endpoint.

## Ownership and disclosure

[engine-settings-reads.mjs](engine-settings-reads.mjs) is composed through private
owner wrappers in invocation-publication.mjs. Pool opening reserves its declared
logical cost from the actual parent. Complete normalized host facts bind an actual
target, every registered key, independent value/origin/declaration permissions and
permitted effective origin IDs. Current policy validity/completeness is a host
premise, not a property established by the permission flags themselves.

A one-use cut is bound to the actual settings object and eight-field disclosure
scope. Acquisition mints context/target/origin references and captures a bounded
projection. Query matches actual handles and a fresh current cut. It retains the
original ceiling, refuses narrowing or changed visible projection, and does not
refresh stale cuts. Unrelated target activation can leave a captured read valid.
Closed-pool markers and lifetime issuance prevent release/reopen from recycling
authority. Faults stop disclosure while protected cleanup remains available.
Observed authorization/scope/continuity/liveness/retention loss is absorbing for
the bound context. So is a current cut demonstrating narrowed permission or a
changed captured projection. Regrant and observed value ABA cannot revive it;
new acquisition is required. Transient resource/transfer/reply refusal or query
cancellation alone does not invalidate. Malformed/foreign requests cannot poison
another context. Invalidated contexts retain their charged slot until explicit
retention/delivery discharge, then may retire without an extra stop transition.

Values and capability declarations are copied/frozen normalized data. Origin
containers are newly owned, with immutable context-local references rather than
private layer/workspace identities. Returned origin coverage is permitted-only;
an empty projection cannot establish absence of hidden contributions. Capability
output is the permitted accepted setting declarations, not an exhaustive engine
feature inventory, successful probe or grant. Whole-declaration permission covers
literal type members; defaults are not returned. Sensitivity metadata grants no
permission, including when declared false. Declaration output follows accepted
schema order, independent of visibility-fact enumeration, and explicitly reports
permitted-only coverage even for an empty list.

## Primary precedent and conditional laws

[VS Code's configuration inspection implementation](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/api/common/extHostConfiguration.ts#L245)
returns cloned values for contributing configuration scopes and separates
inspection from updating. This supports scoped inspectable configuration, not
Vellum's authority model, exact precedence or noninterference claims. No VS Code
runtime, transport or extension API is adopted.

Existing scoped-release.smt2 REL-CURRENT-GATE/REL-CAPTURE-MEET and outcome-laws.smt2
OUT-PROJECTION-NONINTERFERENCE provide abstract conditional gate/ceiling/projection
laws. Four added REL-SETTING conditions cover absorbing observed invalidation and
the unobserved frame, with two satisfiable weakened-rule witnesses for regrant
and foreign-claim invalidation. Solver totals are 274 conditions across fourteen
manifests, 60 baseline. These step laws are not a refinement proof of this
JavaScript reader or real policy truth.

## Executable evidence

Five absorbing-gap cases and five retryable transient cases distinguish authority
loss from resource refusal. Actual settings publication away from and back to the
original visible value checks observed value ABA: the old context stays invalid,
while fresh acquisition remains available. Trusted usage counts distinguish
retained invalidated contexts without exposing identities to ordinary recipients.

Run `node formal/engine-settings-read-checks.mjs`. Six typed/dynamic products use
actual native state without mutation jobs. Fifteen gate cases, eight complete-scope
cases, twelve budget cases and twenty-two controls cover foreign/copied handles,
current basis, one-use cuts, widening/narrowing, sensitivity, opaque origins,
visible staleness, hidden-world pairs, disjoint-target progress, owned reply data,
actual parent reservation, lifetime issuance and protected fault cleanup.

Twenty-two semantic mutations must fail assertions after a coherent unchanged
reader/coordinator baseline. Syntax/import failures are not kills. The engine
static import graph now covers 67 modules without frontend helper imports. The
full frozen-input suite must verify the completed batch.

Native bounds assume normalized plain data, explicit finite profiles and trusted
host facts. Reflective descriptor allocation, hostile Proxies/native calls, wire
decoding, physical memory/service cost, concurrent installation, crash behavior,
mutable definition/policy/association integration, complete F07/F02/F19/event
products and independent assurance remain gates. Logical charge is not measured
RSS, and current projection checks are not a proof of host authorization.

## Observation and threat coverage

INS-01/03/08/09/12/13 attribute preparation, acquisition, query, stop, retirement
and declared parent occupancy. MELT/golden/RED separate unavailable/stale/denied/
capacity paths internally without exposing private reasons to recipients. USE
observes pool occupancy, spent issuance and refusal under logical units, not a
physical ceiling. STRIDE covers forged handles/cuts, stale or cross-scope release,
false capability promotion and exhaustion; LINDDUN covers private value/origin
linkage, hidden-existence/count disclosure and cross-context correlation. Keep raw
keys, values, identities and references out of metric labels and ordinary logs.
No new network, interface, job kind, diagnostic exporter or UI ownership is added.
## Native definition integration

Section 22.3.1.3 adds selected actual-owner definition/association producers.
After binding a recognized context/target/scope and passing current read gates,
validated actual target absence invalidates the captured frontier without a
visibility packet. Restoration does not revive it; foreign/transient queries and
other targets are isolated. Existing capture ceilings still exclude newly added
definitions. See engine-settings-definitions.md for native composition and its
remaining consumer, policy, public product and implementation gates.
