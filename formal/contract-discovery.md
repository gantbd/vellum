# Scoped contract discovery

Current integration: §22.1.5 and [owned native discovery](native-discovery.md)
supply a separately checked native context/selector/lifetime boundary over an
attested accepted-catalog input port. The older checks and limitations below remain
scoped to their normalized helper; neither slice proves actual registry/schema/
handler or advisory-target evaluation truth.

Specification §22.1.3 refines F01's list, inspect and advisory-enablement products.
Discovery describes the permitted registered contract, not a separate execution
path. Its metadata cannot register executable aliases, reclassify an operation,
grant authority or establish that a later command's dependencies remain current.

## Precedent and selected products

[Neovim API metadata](https://neovim.io/doc/user/api/#api-metadata) describes API
versions, signatures, parameter/return types, events and compatibility information.
This supports structured agent introspection without importing MessagePack, RPC,
Neovim's version policy or its whole executable vocabulary. Vellum retains the
existing closed execution categories and explicitly staged registry activation.

The native query catalog is contract-discovery.json. Common fields bind the
contract, variant, owner-resolved discovery context and projection/resource profile.
List adds a bounded row count and optional opaque continuation; inspect selects a
scoped entry; advisory enablement additionally selects a scoped variant and an
explicit advisory target context. Context acquisition/issuance remains an owner
integration gate, not an implicit source/annotation snapshot scope or a new verb.

List returns permitted entry references, versions and execution categories in
stable visible-domain order. It does not enumerate hidden registration slots or
return global registry sequence numbers. Inspect returns permitted variants and
their exact versioned input descriptions, outcome alternatives, declared capability
requirements, limit/cancellation profile references and optional presentation data.
Named input fields use declared semantic domains, not guessed Rust/wire types.
Withheld schema/presentation data is omitted, not replaced by an empty schema or
an inference of unsupported execution. A complete visible page is not a claim of
whole-registry visibility or required implementation conformance.

Title, description, category, aliases and bindings are bounded descriptive data.
They do not contain executable handlers, evaluators or implicit provider fetches.
Text is untrusted presentation content, not a tool instruction. An alias becomes
callable only through explicit versioned executable registration, never merely by
appearing in a descriptor. Duplicate entry/variant references refuse the affected
capture rather than selecting by order. F-identifiers and fixture reference strings
remain design references, not a selected stable public command-name encoding.

Enablement is a separate product bound to the exact advisory target. Established
false is distinct from unavailable advice; withheld and stale advice may share
the same recipient-safe unavailable result. A target change can
invalidate advice while leaving registry metadata usable. Inspect does not embed
old enablement flags as if they described current target state. Positive advice
is neither proposal validation, command admission, write authority nor a reservation.
Execution repeats actual schema, authority, dependency and capacity validation.

Capture binds a coherent accepted registry interpretation and permitted metadata
projection. Current release checks recipient, purpose, destination, context,
profile, policy/continuity and registry basis, plus grant/retention/liveness/transfer.
Broadening cannot expand old captured facts, and narrowing cannot release an old
richer product. Continuation binds the exact context and query/page size and uses
only visible rows. Failed or lost capture is unavailable, not an empty registry;
reacquisition must be explicit rather than silently switching registry mid-page.

## Executable evidence and limits

contract-discovery.mjs uses the actual family catalog and selected annotation/F14
native catalogs. Input field domains are derived from those artifacts; schema
references must bind the registered contract and exact variant. F14's declared
fieldTypes inventory is checked against its exact request fields. Two represented
families are not evidence that every required runtime handler/schema exists.

The reference checks 192 release cases, 216 hidden-world comparisons, 18 complete
visible traversals and 57 controls. Hidden variants inside a visible contract are
projected independently of their private references/advice/requirements. The checks
compose the actual operation router to show that positive discovery advice cannot
bypass denied authority or stale dependencies.
Six in-memory mutants must load then fail assertions: expose a hidden entry,
ignore current projection, ignore registry freshness, ignore page-query binding,
expose withheld schema and embed stale enablement in descriptor metadata.

Paired comparisons use shared admitted bounds; they do not prove timing or resource-
pressure noninterference. The registry, visibility, named schema truth, target advice
and current policy basis are trusted normalized inputs. This is not actual handler registration,
schema/type resolution for all domains, native decoding, context/cursor issuance,
concurrent activation/release or a physical resource implementation. Logical byte
charges and per-capture bounds do not prove pre-allocation budgets, real hold
discharge or maximum native transfer size. Opaque continuation issuance/reuse and
closure must refine the existing owner registry, not introduce an unbounded table.
Full identifiers, nested/outcome schemas, compatibility/alias policy, all-family
handler correspondence and reference integration remain gates. Same-author checks
are not independent Cleanroom certification or new solver theorems.

## Instrumentation

INS-01 distinguishes discovery from invocation/admission, INS-03 observes capture
and current page/descriptor/advice release, INS-09 accepted registry interpretation
and activation, INS-08 real retained context/cursor pressure, and INS-12 diagnostic
loss. MELT/golden/RED separate list/inspect/advice attempts, complete visible pages,
unavailable/stale products and capture/release latency. USE applies to concrete
registry/retention/transfer resources. STRIDE/LINDDUN challenge forged selectors,
hidden registration leakage, alias injection and policy expansion. STPA/FMEA
challenge stale positive advice, metadata mislabeled as execution authority and
partial pages advertised as complete. No entry, target, profile version, cursor
or private registry cardinality becomes an ordinary metric label.

Point representation is approved in §29.4.1; native persistence integration remains open. The all-sections
goal remains active; discovery metadata does not close the remaining runtime,
measurement, governance or independent-assurance gates.
