## Declaration and validation boundary

Settings normalizers use the same private field/discriminator declarations that
supply engineSettingsInputForms. Registration wrappers export copies of the private
catalogs used by their exact guards. contextEngineDescriptor groups these forms
without introducing a command, job or mutable registry. Terminal pairs come from
the common invocation machine; recipient disclosure remains independently gated.

The emitted schemas use the published JSON Schema Draft 2020-12 dialect.
[Core oneOf](https://json-schema.org/draft/2020-12/json-schema-core#section-10.2.1.3)
requires exactly one matching branch; distinct contract constants separate these
forms. [Validation required](https://json-schema.org/draft/2020-12/json-schema-validation#section-6.5.3)
requires named properties. These Informational Internet-Drafts provide vocabulary
semantics, not permission, handler correctness or an RFC certification.

Coverage is explicitly outer-structure-only: exact outer fields and types,
operation/contract constants and fixed registration profile constants. Nested
values, out-of-band opaque bases, authority/dependencies and current semantic
acceptance remain runtime contracts. Finite metadata recognition admits no refs,
custom keywords or remote loading and runs only after the existing metadata
bounds. It is not a JSON Schema evaluator in the engine.

## Executable evidence

Run schema-discovery-checks.mjs with VELLUM_JSONSCHEMA_PYTHON naming the pinned
verification Python environment. No missing-validator fallback is accepted.
An actual Draft202012Validator checks both schemas and 94 instances: ten accepted
handler fixtures, 66 missing-field cases, ten extra UI-field cases and eight
structurally valid requests rejected by current handler context validation.
Every preparation uses a fresh invocation ticket and preserves the native root.
Independent field expectations prevent a descriptor and test from agreeing merely
because both read the same manifest.

Its expectedSerialization uses the standard integer/minimum/maximum keywords
for the positive safe-integer range. The finite recognizer admits precisely that
selected range; nested serialization meaning still belongs to the handler.
The eighth form is scoped configuration definition activation (§22.3.1.7).
Its separately supplied retained basis is not an outer JSON field, discovery
selector, native epoch or public wire encoding; runtime ownership remains decisive.
The ninth form is scoped layer lifecycle (§22.3.1.8), with separately supplied
conditional authority and privately materialized creation indices. Its outer schema
does not define nested identities, created-reference results or public wire codecs.

Eleven controls check frozen source declarations, legacy preservation, partial
catalog correspondence, profile and every-context-field binding, origin and
recipient gates, schema withholding, native state framing, advisory unknown,
cross-profile nonrefunding issuance and independent metadata/capacity bounds.
Malformed schema metadata refuses before issuing a packet. Existing /1 discovery
and built-in-source controls remain separate, unchanged acceptance obligations.

Seven source mutations remove profile fencing, admit arbitrary schemas, omit F16,
remove a required field, substitute a variant or inflate coverage. An unchanged
coherent module graph passes first. Only assertion failures count as kills;
import/syntax errors do not. These mutations challenge the selected declarations
and reader, not every nested handler predicate or possible schema.

## Remaining refinement and observation

No new SMT condition is added: existing conditional ownership, release, bounded
capacity and publication laws retain their separate scopes. This evidence does
not establish complete value/result/event codecs, installed all-family routing,
full scoped definition/lifecycle products, hostile decoding, actual policy/host
truth, production packaging or physical/concurrent/crash/independent refinement.

INS-01/03/08/09/12/13 distinguish source preparation, profile/shape refusal,
capacity, current release and held-context retirement. Metadata inspection is not
command execution, and schema validation is not enablement. Keep these populations
separate in MELT/RED/USE/golden signals; use bounded reason/profile labels, not raw
schemas, identities, handles or payloads. STRIDE/LINDDUN retain source substitution,
metadata disclosure and exhaustion coverage at IF-01/07 and PATH-02.
