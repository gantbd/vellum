# Native source search ownership evidence

The selected synchronous F05 reference evaluates the source captured by the
actual F02 invocation owner. Its retained results and occurrence references remain
dependent on that context. Preparing an F11 replacement or F12 match selection
does not create an independent read lease. This slice does not define an async
worker protocol or add a public verb, transport, UI mode or numeric default.

## Authority and immutable source

The private pool binds one actual invocation owner and domain. Section 15.4.3
extends original context resolution to source-only and combined issuers; the
opening context pool is bootstrap metadata, not ongoing read authority.
Only the original native context identity supplies a snapshot. Scope claims bind
document incarnation, recipient, purpose, destination, policy, continuity and
profile; matching strings do not establish grants. Source release facts and the
six current-query facts are independently required and exact true. Host identity,
policy interpretation and complete loss notification remain accepted premises.

Bounded-copy the complete request and current packet without replacing the opaque
context identity. Validate numeric scope ranges and the request's document binding
before observing loss. Wrong handles, changed current requests and foreign scope
claims cannot invalidate another result. Intersect root, input and reply ceilings
with the captured source profile. Later publication does not refresh the snapshot.

## Reservation and result lifetime

The finite profile bounds retained results, lifetime issuance, request/capture/
selector bytes, copy nodes/depth and the existing literal-search limits. Before
opening, compare the declared reservation with both the local ceiling and actual
parent headroom. With `R = maxResults`, the selected logical reservation is:

```text
profileBytes + 2*maxRequestBytes + 2*maxCaptureBytes
  + 3*R*(maxCaptureBytes + maxRequestBytes + limits.maxReplyBytes
         + limits.maxMatches*maxSelectorBytes)
```

The actual parent separately owns its declared root and invocation frames.
This is a logical reservation, not measured allocation or complete host accounting.
Input workspace remains reserved when result capacity is zero.

Reserve an actual source hold before evaluation. A known unpublished refusal
discards that hold but does not refund spent source issuance. A published result
keeps its source hold until protected retirement. Exact-false bound query loss is
absorbing for that result; unknown facts and transient capacity refusal withhold
delivery without establishing loss. Query loss alone does not close an independent
source reader. Actual source stop, fault or disposal prevents dependent release.

Retirement requires exact-true owner control, released retention and drained
delivery. Neither stop nor settlement is evidence of those facts. A result row's
removal does not refund the pool reservation or lifetime issuance. Empty-pool
retirement releases the reservation once; reopening cannot reset the issuer.

## Dependent editing consumers

The native result index identifies its original pool; original occurrence handles
identify their original result. The decoded F11/F12 gateways validate that native
owner and current result before first preparation and again at invocation service.
Opaque copies or a caller's positive facts cannot revive a stopped context or
retired result. Existing unmanaged reference producers retain their own narrower
contracts and gain no native-context guarantee from this integration.

The invocation owns its prepared argument/intent frames and, for replacement, a
separately charged returned-result frame. These reservations do not make the
original query independent. Lost currentness refuses new preparation or settles
pending work as `notApplied`, preserving the current root. It does not cancel the
invocation, erase its outcome, refund its charges or establish physical reclamation.
Protected invocation retirement remains separate. An independently leased prepared
consumer would require a distinct supported ownership contract; none is introduced.

## Remaining integration obligations

Protected retirement removes the selected literal-search capture and occurrence
registry lookup paths. Remaining prepared invocations retain their bounded intent/
argument and reply obligations until their own protected discharge. Removal of
logical lookup paths is not a claim of physical erasure or complete allocator
accounting.

Required historical/version-set native issuers, async result
dispatch, complete public codecs/results/events and all remaining operation variants
stay open. Actual policy/identity/currentness notification, physical/global resource
accounting, production concurrency/crash behavior and independent assurance are
separate gates. This evidence closes no whole residual family. Adoption requires
specification/model/instrumentation reconciliation and a fresh full frozen run.
