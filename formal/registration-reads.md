## Actual root and visibility preparation

One read registry belongs to one actual native publication domain. Creation checks
the actual authority/engine, healthy owner, strict owner-control/preparation/resource
facts and a complete finite limit profile. A copied domain cannot create it.
Retiring that registry leaves a fixed domain-lifetime spent-issuer marker: it
cannot reopen/reset issuance within that native incarnation. New native domains
still require the existing unique-domain and resource-grant premises.

Read-only native schema validation reuses §22.3.3's actual catalog validator; it
does not require registration mutation rights. The trusted host supplies exactly
one visibility row per actual read/write slot, with table/provider/resource tuple,
Boolean visibility/descriptor facts and a contiguous approved visible order.
Hidden rows have no descriptor grant or order. Exact tuple coverage, unique slots,
closed shapes and bounds are checked before issuing a private preparation.
Policy truth and whether an approved order is appropriate remain host premises.

The preparation is bound to its registry, exact current root object and complete
authority/engine/recipient/purpose/destination/policy/continuity/profile scope.
Root changes require fresh preparation, even when output would be equal. A
scoped current acquisition/query attempt consumes it once; copied, foreign, stale
or spent handles do not authorize another root. Denied preconditions can leave an
unconsumed preparation for explicit owner release. Bounded live preparations
account conservatively for their root references and copied facts; actual allocator,
shared-retention and aggregate host-accounting truth remain separate obligations.

## Captured permitted metadata

Capture only visible slots in approved visible order. Keep private tuple keys and
the captured descriptor ceiling internally; retain copied projected metadata,
not the whole root, in the read context. A table-only entry reveals read/write
classification. A descriptor-enabled read entry contains only profile/atomicRead
and the source insertion-line-break declaration where applicable. A writer entry
contains only procedure and its existing identity/continuity/synchronization/
conditional-write/causal/nonreuse/exclusive-create declarations.

These are accepted declarations, not live probes, grants or proof of provider
identity. A host-approved literal procedure label is permitted metadata; field
whitelisting is not a universal content-classification or secret-scanning theorem.
Do not automatically include native provider/resource identities, locators,
identity keys/domains, registration stamps, publication or owner-wide floor.

The context is a captured permitted snapshot. Later visibility broadening or new
visible entries cannot expand it, and current ordering cannot reinterpret its
captured order. Every query needs fresh current-root visibility preparation and
current scope/release facts. Compare current values only within the captured
visible slot/facet ceiling. Lost visibility, narrowed descriptor permission,
missing slots or changed permitted values refuse the old envelope. Hidden entries,
private fields and undisclosed descriptor changes do not alone stale that envelope.

Every result says coverage captured-permitted. An explicit empty page means the
captured permitted set was empty, not that no other or newly visible registration
exists. Reacquisition is a separate current snapshot. These contexts neither
establish current physical file/provider state nor retain a native epoch promise.
In particular, removal/reinstallation of the same logical slot with equal permitted
metadata may again satisfy a read comparison. The selector still identifies its
immutable captured slot/value, not the new native registration. It cannot be used
as a native continuity, freshness or compare-and-swap token. Public mutation
preconditions and cross-product adapters remain explicit technical gates.

## Query selectors and whole response publication

The exact outer query binds contract, F07 capabilities operation, context, profile
and one nested list or inspect product. List takes positive bounded limit and null
or issued continuation; inspect takes an issued entry selector. Reject unknown
fields/products, raw offsets, copied handles and cross-context selectors. These
opaque local objects have no public ordinal or native-key encoding.

Allocate entry selectors only for visible rows in a completed page. Continuations
bind exact context, limit and next captured position. Stable page retries reuse
the same selectors. Stage entry/cursor maps, lifetime issuance and the complete
reply together; capacity or reply failure cannot spend partial bindings. Public
pages expose reference/table only; inspect returns the captured permitted fields
under the same whole-envelope release checks. Return owned values and frozen
opaque handles, not mutable aliases into retained projections.

Stop requires the complete original scope and exact-true owner-control but no
ordinary disclosure, transfer or capacity grant. It prevents delivery, clears
projected rows and selectors, and does not refund lifetime issuance. Retirement
requires stopped state plus independent retention/delivery discharge. Registry
retirement requires no contexts or preparations. No provider task, effect,
binding, baseline, native root, registration floor or producer reservation is
cancelled, refunded or retired by these read-lifetime operations.

## Resource and termination contract

Limits independently bound live contexts/preparations, rows, selectors, lifetime
issuance, page size, roots, packets, scopes, captures, rows, selector records and
replies. The declared reservation is maxContextBytes plus
maxPreparations × maxPacketBytes plus maxContexts × (maxContextBytes +
2 × maxCaptureBytes + 2 × maxReplyBytes) plus
2 × maxSelectors × maxSelectorBytes. Reject unsafe arithmetic or a reservation
above maxHeldBytes. These are conservative reference envelopes, not exact physical
allocation measurements or numeric product defaults.

Preparation ends as consumed or explicitly released; contexts move active →
stopped → retired. Every call scans/copies only finite validated structures and
either returns a complete bounded result or refuses. Pagination advances within
the finite captured visible sequence; repeats do not allocate another selector.
This is per-call termination and bounded retained-state evidence, not external
provider termination, scheduler fairness or whole-engine categorical/lattice closure.

## Conditional arguments and executable evidence

Assume the existing private module boundary, immutable serialized native roots,
unique domains, truthful current policy/continuity/visibility/order/retention and
resource premises, supported native profiles and non-reentrant execution.

1. **Coherence and frame.** The packet owns the actual root and complete tuple
   coverage. Acquisition retains one scoped projected snapshot, and current-root
   checks prevent old visibility from authorizing a new publication. Query and
   read-lifetime transitions never write native state, floors or producer ledgers.
2. **Disclosure.** Filter hidden slots before ordering/allocation; apply captured
   and current descriptor ceilings; compare only permitted current values. Under
