# Lifecycle activation envelope integration

Specification §11.2.13.7 now adds the actual-parent temporary reservation described
in [lifecycle workspace](lifecycle-workspace.md). It supersedes the temporary-parent
exclusion below for these nine forms, not the physical or broader public gates.

Nine existing lifecycle forms connect typed and dynamic argument capture to
their native owner preparation ports. The adapter returns the existing lifecycle
or relation job plus its route; it introduces no command, executor, transport,
registry or cleanup receipt.

| Forms | Existing native control ports | Native work retained |
| --- | --- | --- |
| Source load | Original completed-load authority | Create, join or repeat through native read and current-owner checks |
| Annotation restore and baseline adoption | Original completed-read authority; existing inspection role, including the native restore null value | Separate restore and adopt-baseline phases, not a joint transaction |
| Source SaveAs | Original completed-write activation authority | Activate the already established destination evidence, not issue another write |
| Pure source rebind | Original writer inspection | Current binding transition; no filesystem rename or write |
| View and workspace container create and retire | Empty native-port record; existing profile and current host facts | Existing relation lifecycle jobs and current identity/generation checks |

The fixed native-port record accepts only its declared own ordinary data
properties. It copies the outer record without traversing or cloning opaque
handles. Profile and host facts remain native control ports, not serialized
request arguments. Owned argument/context capture precedes native authority
validation and preserves the invocation's issued value.

Preparation reuses the existing slot's busy guard. Recursive preparation,
sibling native preparation, submission and retirement cannot interleave through
that slot. Ordinary refusals preserve root, slot eligibility and existing ledgers.
Successful preparation is not publication: submission, native execution,
current validation, publication and result release remain separate transitions.

Unexpected preparation faults fence the domain and clear the busy guard.
The caller retains its original ticket, which can retire an installed intent
after the existing retention and delivery obligations permit it. A late failure
does not undo completed provider work, erase other slots, refund issuance or
start counters, or reopen the faulted domain. No new cleanup acquisition is needed.

Eight controls exercise eighteen fresh-ticket typed/dynamic publications,
320 ordinary refusals, 175 observed reentry refusals, nine native host faults and
nine opaque bookkeeping cases. Twelve targeted mutations run against copied
complete graphs; construction and process failures are not semantic detections.
Capture and release fault checkpoints cover all nine forms through both routes:
36 cases. Verifier-only booleans establish zero early installations, eighteen late
installations and native prepared-map discharge through the original ticket.
No opaque plan is exposed as a public recovery handle.

The selected engine graph reaches 95 modules without frontend imports; its
clean-entrypoint regression covers the enlarged graph. Architectural components,
interfaces, the 76/11 engine/presentation partition and existing native job kinds
are unchanged. IF-01/03/04/05/07/08 and INS-01/02/03/04/05/07/08/09/12/13 retain
capture, native authority, publication, fault and discharge distinctions.
Raw arguments, invocation values, probes and locators are not ordinary labels.

Local byte/node/depth ceilings do not establish actual-parent temporary
reservation, physical bounds or host resource truth. Complete F17 results,
outcomes/events/discovery, additional profiles, operational measurements and
independent assurance remain open. Full frozen qualification and endpoint
reconciliation are required before adoption.
