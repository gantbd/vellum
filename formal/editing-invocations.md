## Precedent and selected boundary

[CodeMirror transactions](https://github.com/codemirror/state/blob/main/src/transaction.ts)
retain starting state, changes and an explicit selection; their resulting selection
can instead be mapped when no explicit selection is supplied. This supports keeping
selection intent distinct from source changes. Vellum uses its existing exact-source,
owned-preparation and replay rules, not CodeMirror extension callbacks, positions,
timestamp policy or an imported implementation. Its transaction annotations are
not Vellum's authored comments.

The shared reference's closed internal job sum extends from compound/reversal to
six local editing kinds, adding `selection`, `line`, `boundary` and `replacement`;
§6.5.3 separately adds the seventh, acknowledged clipboard continuation, and §13.6.1
adds the eighth, native annotation fields. These four adapters cover the
existing named F11/F12 products, not new northbound verbs, routes or a plugin ABI.
Private producer facets and fixed dispatch cases have no callback registration or
expression evaluator. Neither a visible handle nor a retained descriptor is a grant.

## Owned identity and complete private intent

The existing producers intentionally expose small owned handles while keeping
requests, dependencies and derived work in private registries. Equal-looking handles
can mean different edits. Only the matching producer registry can describe a handle;
copied, foreign-kind and unknown handles refuse. For these four kinds, a matching
retry requires both the same retained prepared identity and equal captured semantic
data. Rebuilding even an equal-looking preparation is not a retry of that retained
candidate. Production request adapters must resolve an existing invocation before
preparing new work; this reference does not prove that upstream canonical gateway.

Bound the complete normalized descriptor, not just the visible proxy. Selection
descriptors include the original request, interpretation limits, current required
views, annotation-set dependency, exact edits and post-selections. Line descriptors
retain the original action/settings/request, charges and underlying selection plan.
Unicode descriptors retain unit/direction/count/extension, exact source/view context,
limits/work and the underlying derived selection plan. Replacement retains the
original replacement/index/operation request, captured query/generation/scope/source,
limits, edits and view companions. In particular, zero matches do not erase a
different replacement string, and equal derived indentation does not erase tab width.

Opaque occurrence and Unicode-evidence bindings stay attached to the original
producer preparation; they are not flattened into equal-looking serialized handles.
Those bindings retain their own producer/host lifetime, quota and current-eligibility
obligations. Descriptors are bounded trusted engine data, never a new northbound
inspection product exposing peer views, source, query text or private dependencies.

Admission first checks existing domain/entry scope and reserved capacity. A producer
returns a bounded owned copy, then the ledger also bounds the complete normalized
kind/descriptor envelope. A tiny visible proxy cannot bypass either bound. Logical
byte checks and producer-bound preparation are not physical allocation/copy-peak or
complete cross-owner accounting evidence.

## Execution and current dependencies

At the one eligible run, retrieve the original producer preparation and compare its
private semantic snapshot again. Missing or changed already-retained preparation is
an unexpected internal fault: keep the prior root, retain conservative Unknown/faulted
facts and fence the domain. Normal changes to current rights, targets, settings,
query/evidence eligibility or supported profile are handled by actual producer
validation and can yield known NotApplied without replacing the prepared meaning.
The private mutation test exercises integrity containment, not hostile decoding.

Invoke the actual existing publishers, not a generic byte edit reconstructed from
their visible handles. Ordinary edits preserve explicit caret-after versus mapped
selection meaning and all current supported view/annotation companions. View-only
commands do not need source-write authority, create no authored source history,
and preserve compatible later comment edits. Line publication checks captured
settings and work bounds. Unicode publication consumes already-owned exact-source
evidence and current retention/profile; the pinned native reference batch is acquired
outside execution, not launched inside the editing decision. Replacement and
search-occurrence selection check their original current query/generation/retention;
they neither rerun the search nor guess a newer match.

All candidates still pass the shared root bound and root/terminal-fact installation.
Unchanged is a spent terminal invocation, not future eligibility. Later caret/source
changes cannot make an old no-op act again. Current outcome release, protected stop,
result forgetting and drained retirement retain §6.5.1's independent responsibilities.
No producer task flag or external effect is committed by these pure local adapters.

## Conditional arguments and evidence

Assume finite normalized owned data, truthful current host/producer scope and
retention, actual reservations and serialized non-reentrant local decisions. An
owned candidate resolves in only its producer registry. Identical handle binding
plus immutable descriptor equality prevents a different candidate from redirecting
an invocation; the execution-time comparison detects private meaning drift before
publication. Actual producer validation then establishes its scoped current source/
view/query/settings/evidence conditions. Existing ledger induction supplies at most
one start and paired root/fact installation; result eviction cannot restore eligibility.

The four adapters covered here have fixed dispatch cases; §13.6.1 separately adds
native annotation fields. Descriptor recursion for these four is limited to the
existing line/boundary→selection composition, with bounded source/view/edit/request
values and no executable extension. Each selected producer already supplies finite
work bounds. This supports conditional per-run halting, not scheduler fairness,
physical latency, whole-engine categorical completeness or bounded-lattice closure.

Checks execute 1,024 admission, 512 publication and 512 release combinations and all
720 six-action permutations for each of four kinds: 2,880 traces/17,280 edges. Sixteen
controls and fifteen assertion-rejected semantic mutants cover actual resulting
roots/carets, owned versus copied/rebuilt candidates, private and envelope byte bounds,
invocation binding, view-only rights/later comment preservation, old no-ops, settings,
Unicode evidence, query generations/occurrences, zero-match intent, private drift,
root pressure and current operation permissions. The reference compares actual
producer roots with shared-ledger results. These finite traces and conditional
arguments are not full arbitrary-length implementation refinement or independent
Cleanroom certification. Existing ledger/producer suites remain revalidated evidence.
