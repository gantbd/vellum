# Native annotation storage artifact capture

The later owned-retention composition in §16.2.2 and
[annotation-retention.md](annotation-retention.md) calls this actual producer.
It does not claim provider writes, streaming generation or native restoration.
The raw-capture evidence below retains its original scope and counts.

Specification §16.2.1 connects the actual managed annotation root to the approved
version 1 storage shape. The selected capture preserves every live record's body,
versions, authored target and current placement, including both point profiles.
It produces an owned immutable artifact without modifying the engine or writing
a provider. Missing required identity/source evidence refuses the entire capture.

## Precedent and boundary

[Web Annotation states](https://www.w3.org/TR/annotation-model/#states) distinguish
the intended resource representation from selection within it. This supports the
existing original-source/current-placement separation, not a requirement for
JSON-LD, HTTP, temporal retrieval or fuzzy repair. The approved Vellum schema
retains its byte-coordinate and point-profile semantics.
[RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html#section-10) constrains JSON
generation; the existing strict decoder validates the generated reference bytes.
Neither source establishes live identity, authorization, historical continuity or
durable storage. Those remain Vellum host/provider obligations.

annotation-artifact.mjs is a trusted serialized native composition, not a public
save verb, alias protocol, wire token or provider service. It reads the actual
invocation authority root; a copied domain cannot select it. Complete normalized
context and document identity must bind the owner, engine and capture table.
Exact current source and annotation-set dependencies are checked, never refreshed
silently. No source/annotation mutation, invocation execution or observer operation
is called by capture.

## Complete inventory and explicit aliases

The existing native membership validator establishes a coherent bounded activated
inventory for this selected root. Unknown/legacy inventory is not inferred empty.
Only current live records enter the snapshot; retained-absent records, tombstones,
history journals and private source bytes are not a second export inventory.
The format is a live annotation snapshot, not a history archive.

The host supplies a bounded explicit association, one storage alias per live native
record and source evidence/bytes for exactly the needed source revisions. Native
identity/incarnation and storage namespace/value mappings must be unique and
complete within the capture. Native positive integer incarnations/versions become
exact decimal strings; this selects no new engine-wide integer representation.
Aliases are not constructed from paths, workspace labels, renderer objects or
recipient stream references. Their real issuance/continuity/current-policy truth
is supplied by the host, not proved by table equality or Boolean fixtures.

The selected capture requires injective source evidence keys within its table so
distinct native revision bindings are not merged. These are source-context aliases,
not a rule that external ETags, hashes or write validators are unique/ordered.
Current source bytes must exactly equal the actual committed source. Historical
source bytes/evidence require an independent current historical-evidence premise;
no current text, equal bytes, placement or history lookup silently fills a gap.
This reference does not implement that historical evidence supplier.

Validate every target against its selected source's UTF-8 scalar boundaries.
Authored targets retain their original source evidence. Located placements bind
the current source; detached placement does not acquire a current target. Preserve
document, range and both explicit point profiles and affinities. Body strings,
line endings, empty bodies, exact versions, current placement state and live record
order survive the projection. Unknown native record/target shapes or any missing
alias fail rather than dropping a field or truncating the record set.

## Disclosure, bounds and ownership

Capture requires exact-true current authorization/scope/continuity/liveness,
nonstopped preparation, annotation read and complete disclosure, current aliases,
source evidence, resources, retention, transfer and preparation reservation.
This is a complete storage export, not an F03 filtered collection query. If the
complete disclosure predicate is unavailable, refuse; do not save a filtered
subset as if it were the complete document. Write authority alone grants no read
or export authority. Actual policy/retention/reservation truth remains a premise.

Native limits bound root/document/record/table/source/serialized artifact and full
reply sizes. Existing membership and strict snapshot profiles independently apply.
All are explicit finite fixture profiles, not production defaults. Stringification,
candidate construction and decoder allocations need actually reserved preparation
work; this reference does not prove transient physical accounting, ingress cost or
cross-owner charging. Shared logical admission and reservation truth are also
supplied, not established by post-materialization size checks. JSON generation is
neither canonical signing nor a selected
streaming implementation. Resource failure returns no partial artifact.

The immutable returned bytes and private copied basis name the captured document,
source revision, annotation-set generation and context. They retain no parent root
or new long-lived registry owner. Later input/native changes cannot rewrite them.
Raw delivery is an explicit disclosure, not a revocable lease; later provider
dispatch must recheck its own actual disclosure/destination/retention constraints.
The private basis and structural immutability confer no future write capability,
baseline freshness, restore authority or safe-retirement fact.

## Conditional preservation and halting argument

Assume an authentic serialized native owner, complete host alias/disclosure/source
evidence and actually reserved bounded preparation. Membership validation checks
the actual current inventory. Complete injective alias tables give exactly one
representation per live native record and required source revision. Field-wise
projection preserves each supported native component; positive safe integers have
exact decimal representations, and the approved closed target fields include
point profile. Strict decode validation precedes delivery. Recovering native
fields through the inverse alias correspondence therefore yields the captured
supported values, not a freshly queried or repaired version.

The function contains bounded scans over the admitted root, alias tables and live
records, followed by bounded generation/validation and a full reply bound. Each
scan consumes a finite input-index rank; there is no waiting, retry, provider
callback or traversal to an undisclosed source. Failure discards private values
without root publication. This is per-call reference termination, not a physical
latency bound, whole-engine completion theorem or global categorical closure.

## Executed evidence and remaining gates

annotation-artifact-checks.mjs drives actual native create/body/reattach/delete,
compound source changes and F14 undo/redo before capture. It checks 150 native
captures, 8,192 gate combinations, seven context changes and three actual
source-history stages. An inverse projection oracle compares every live record
and field against the real native root. Ten controls cover ownership, stale bases,
current/historical source evidence, complete/injective aliases, unknown inventory,
retained deletion, immutable old captures, bounds and strict grants.

Eleven assertion-killed mutations have a passing dynamically loaded baseline.
They challenge complete disclosure/reservation, original context/source/set bases,
actual current source equality, historical evidence, point coercion, record
truncation and artifact/reply bounds. Import or syntax failures are not detections.
Existing snapshot checks and 223 SMT conditions/thirteen manifests retain their
own scopes; this slice adds no new solver condition or production certification.

Actual host alias/policy/historical source truth, shared physical reservation,
streaming production encoding, native restoration/migration, provider write/
receipt/baseline coordination, complete annotation persistence, concurrency and
independent assurance remain gates. No whole D20/F21 or all-sections goal closes.

## Instrumentation

Reuse PATH-03/PATH-05, IF-01/IF-13 and INS-01/03/06/07/08/12. MELT/RED/golden signals
separate offered/admitted/refused captures, complete artifacts, bytes, preparation
latency and unavailable evidence. USE tracks root/alias/artifact/preparation
pressure, not imaginary physical release. Actual capture overhead remains measured
integration work. STRIDE challenges forged aliases, stale bases, profile tampering,
partial inventory and abusive expansion. LINDDUN covers source/history/identity
disclosure and linkability; keep raw bodies, aliases, offsets and context IDs out
of ordinary labels. Diagnostic failure cannot change capture or publication facts.
