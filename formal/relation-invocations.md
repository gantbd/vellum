# Owned view and workspace lifecycle invocations

Current document-lifecycle integration: §11.2.13 adds owned invocation for the
eight existing native scratch/relation/disposal/release products with live
restricted writer inspection and current result release; see
[lifecycle-invocations.md](lifecycle-invocations.md). Current shared cancellation
now covers ten native kinds/fifteen forms. Earlier counts/exclusions retain their
original slice scope; effect/activation/events/registry and host/physical/independent
gates remain.

Specification §11.2.12 connects the native logical container controls of §11.2.11
to the existing issued/pending/running/done invocation owner. Typed and dynamic
admission share an owned interpretation, current native publication and terminal
outcome; no keystroke, UI focus, file effect or separate workflow is involved.

## Closed semantic product and retained interpretation

relation-invocation/1 carries contract, operation, invocation, profile and action.
Operation is view-container or workspace-container; action is create or retire.
Retire additionally requires target and expected, exactly as §11.2.11 specifies.
Profile is native-relation-lifecycle/1. Unknown fields/operations/contracts/profiles,
caller-assigned creation targets, stale retirement and wrong invocation refuse.
The existing F17 catalog gains these two named subproducts: 28 families and four
categories remain; 87 semantic variant labels replace 85. These artifact labels
are not frozen wire identifiers or a complete public registry.

Preparation requires an actual issued ticket and full current invocation context,
strict shared admission facts and a currently valid native request/profile. It
captures immutable request and the trusted compiler-supplied lifecycle/membership/
binding profile, not an arbitrary callback or caller-selected resource envelope.
The serialized interpretation must fit actual maxIntentBytes. Each issued slot
has at most one owned preparation: identical preparation returns it; another
interpretation refuses. Plans bind the actual owner, domain, ticket and invocation
reference; copied or foreign plans cannot be submitted. Existing deduplication
compares the same normalized intent and owned plan across typed/dynamic routes.

The new closed native job kind relation is not a new semantic family, arbitrary
execution verb, transport or extension runtime. Only this exact product can
prepare it. It is not in ownedEditingKinds, which retains its editing-only meaning.
Preparation is interpretation, not a retained replacement root. Final service
constructs a fresh candidate against the actual current root, so an unrelated
source publication is preserved rather than overwritten or unnecessarily staling
the request. A retirement still needs its exact current target generations.

## Service, publication and result lifetime

Pending cancellation follows the existing protected F18 control. It settles
notApplied/stopped without creating/retiring anything. It neither preempts a
running synchronous publication nor disposes documents or retained provider work.
Service revalidates relationInterpretationCurrent exactly true and exact equality
of the host's current relationLifecycleProfile to the retained profile. Unknown
compatibility refuses; a changed profile never reinterprets an old payload.
The existing native facts and private candidate certificate govern actual mutation.

Staging constructs an applied candidate and an invocation-attributed created/retired
receipt. The full {status: result, result: receipt} envelope must fit the actual
result cap. Actual root caps and current baseline promises are checked before
publication. Known refusal clears candidate receipt and settles notApplied/rejected.
Final commit rechecks the exact owned stage, before-root, candidate/receipt and
current interpretation/native facts. Source journals carry. Frozen root, prepared
common outcome and receipt install together with terminal bookkeeping. A trusted
protocol contradiction or exception faults the owner conservatively with unknown
publication and no new root or identity result. There is no provider callback,
I/O or await inside publication. The tests' getters model trusted-host faults;
they do not authorize extension callbacks inside this boundary.

Successful result data is exactly invocation, created/retired status, kind and
target. It contains no root, source, membership list, provider configuration or
certificate. Disclosure requires the original admission ceiling
relationResultIdentifiersAllowed === true, complete current invocation context,
existing release facts/policy, an available applied common outcome and strict
relationResultReadable/relationResultContextCurrent/historicalTargetReadable facts.
These are scoped current host assertions, not grants inferred from target existence.
Later authority cannot widen an absent admission ceiling. A successful mutation
can therefore have a withheld identity result without changing its outcome.

The identity is historical local-engine data, not a mutation capability or proof
that the container still exists. A retired view's receipt can remain readable
under current historical-target authority. Current release bounds still apply;
temporary withholding does not rewrite the outcome. Forgetting drops the retained
receipt and common result without reopening execution; authorized retirement
removes the slot and owned preparation. Old/copied tickets cannot revive it.
An engine-local identity may encode allocation order: this product does not
authorize unprivileged remote disclosure of that encoding. Scoped opaque public
references, non-linkability and registry/discovery encodings remain separate gates.

Preparation/intent copies and the mutually exclusive relation receipt remain under
the existing invocation slot/intent/result/root charge envelopes; no extra profile
default or logical budget is introduced. The lower native stage is transient and
commits or is discarded in the same service turn. Logical envelope preservation
is not allocator/RSS/stack/time/global physical accounting or crash durability.

## Conditional arguments and executable support

Assume truthful current compiler/profile/policy/coverage/retention facts, supported
normalized semantic inputs, unique native domains and the existing serialized
nonreentrant owner. No hostile byte decoder, provider truth or independent review
is inferred from the reference.

1. A plan belongs to one actual owner/domain/ticket and immutable interpretation.
   Submission checks this ownership and its original invocation. Retained intent
   equality plus the native pending-only service transition prevents replay as
   a different request or a second local publication. Forgetting affects evidence,
   not execution eligibility. Retirement cannot restore an issued coordinate.
2. Every noncancelled service either derives a current native candidate under the
   retained profile or refuses. Exact native reconstruction and current caps/promises
   preserve the original document/producer frames. Receipt/outcome construction
   precedes the callback-free final commit. Candidate, common outcome and private
   receipt are never exposed as an intermediate root to other readers.
3. Current release is the intersection of the admission ceiling, original complete
   context, current summary authority, historical-target authority and transfer
   limits. No result is returned for stopped/refused/faulted/forgotten work. Current
   disclosure denial cannot reverse an already committed container mutation.
4. The vocabulary is two operations/two actions and the existing finite invocation
   phases. Preparation, service and release perform bounded validation/copies and
   native scans. A pending request services once or remains pending under existing
   scheduling assumptions; no claim of provider termination or open-load fairness
   follows. This is per-call halting and conditional preservation, not categorical
   completeness or a global bounded-lattice theorem.

These are authored conditional construction/trace arguments, not machine-checked
induction or independent certification. relation-invocation-checks.mjs covers
42 annotation/history stages, 336 typed/dynamic native publications, 256 admission
cases, 174 strict service refusals, 32 result masks, fifteen controls and 23 semantic
mutants. Each mutant must fail assertions against a passing coherently rewired
multimodule baseline; import/syntax/TypeErrors do not count as kills.
The existing cancellation suite now includes a relation job: fourteen forms/nine
native job kinds, 224 gate/112 context/28 race cases, 3,626 traces/10,164 edges,
ten controls and twelve mutants. This is representative shared-control coverage;
the new lifecycle suite exercises all four kind/action forms.
Existing 234 SMT conditions/fourteen manifests are unchanged; the semantic family
routing reference now checks all 87 labels/44,544 Boolean routing contexts.
