# Qualified native annotation baseline installation

Specification §16.5.7 installs the actual qualified annotation baseline and transfers
the pending capacity obligation into retained native producer ownership. It composes
the accepted newest-eligible baseline election, actual ticket/claim linkage, native
reservation floor and serialized root/companion publication precedents. It does
not make an external write atomic with local publication or complete ordinary-save
admission, all host routes or public execution/event products.

## Synchronous producer and consumer boundary

installAnnotationWriteBaseline resolves the actual private writer/ticket and its
original native domain. Sixteen exact-true current publication/preparation/transfer/
retention facts precede work. Current pair, full annotation binding/registration,
historical artifact, actual known application and captured requested strength remain
required. The actual private baseline builder supplies exact retained bytes and
attribution; the accepted publisher supplies newest-eligible election.

The checked writer seals a package-private installation certificate and immediately
calls the actual native installer in the same synchronous serialized operation.
No certificate, prepared root, callback or await is returned to the caller. The
certificate binds exact before-root object identity, candidate, claim, domain/pool,
producing task and actual knowledge-object identities. The consumer independently
checks live actual ticket/producer records, original artifact descriptor, body,
requested/qualified strength, serial, version, current registration and domain.
Publishing or refreshing still requires the unique newest eligible producer for
that document/binding/registration, not receipt arrival or revision order.

Only the source writer calls the seal factory, and only the native invocation
authority calls the final pool commit in the checked non-test source tree. The
reference assumes those facets remain package-private; static callsites and
JavaScript module exports do not prove production package visibility. Direct
certificate-construction tests deliberately challenge consumer defenses against
an incorrect producer; they are not a public certificate-minting interface.

## Installation and transfer cases

| Case | Native root | Pending capacity | Evidence retained |
|---|---|---|---|
| Selected producer publication | Baseline plus one safe publication advance | Remove only its own hold | Actual producing claim, ticket and artifact |
| Already-current producer | Unchanged | Remove its pending hold | Existing producing claim |
| Already-installed newer producer | Unchanged; older attempt is superseded, not relabeled current | Remove the older hold | Newer qualified actual producer, same original context/registration |
| Current-producer metadata refresh | Validated metadata plus one publication advance | No recreated hold or issuance | Same producing claim; ordinary remaining floors still apply |

For a changed root, restore its old annotationBaseline field (or remove a newly
inserted field) and old publication in a private comparison frame. That complete
frame must equal the before-root. Thus source, annotation authoring, peers,
bindings, histories, views, source baselines and all other fields are preserved.
Publication advances exactly once with safe arithmetic. Existing/current transfer
requires actual root identity and baseline equality without a counter advance.

The actual pool computes floors using every remaining hold after excluding only
the consumed reservation. This permits the last promised publication unit to be
used without double-counting it, while preserving others. Refresh consumes no
reservation and can refuse when another hold owns the remaining counter or space.
An already-current retry is unchanged even when no unused generation is offered.

The candidate is frozen and optional existing parser-source journal evidence is
carried through an exact baseline/publication frame before final commit. The
original receipt handles remain identical; no new source transform is issued.
Invalid or absent optional evidence is not fabricated. The final pool/claim/root
assignments are bounded trusted operations with no intervening user/host code
under the existing serialized installation premise. Actual memory/concurrent
atomicity is not established by a JavaScript statement sequence.

## Producer ownership and retirement

Dropping the pending hold cannot leave only an origin string in JSON. Native pool
ownership retains the actual producing claim. Each installed producer originates
in an issued hold, so retained producer references are bounded by maxIssued.
Precharge live and staged reference-set envelopes in pool bookkeeping. Refresh
reuses the existing reference; current/superseded transfer requires an already
retained producer. The actual writer's separately charged claim/ticket/artifact
remains alive through that reference and its existing lifecycle obligations.

The source writer's claimed-written retirement path checks both supplied-root
evidence and the actual current native root/declared annotation binding history.
A supplied root omitting the real producing baseline therefore cannot authorize
retirement. Once a newer qualifying baseline supersedes an unneeded producer,
retirement may remove its actual ticket/artifact/private claim under existing
quiescence, destination, retention and drain gates. The native set may keep the
now-empty nominal handle as a prepaid, nonreusable lifetime tombstone; it does not
retain the retired private payload. Complete snapshot/pin/discharge truth remains
a host and integration obligation.

Baseline installation does not release writer execution capacity, declare safe
external disposition or remove the export-destination reservation. Known written
application can have a historical qualified baseline before effect quiescence;
the actual writer retains those independent obligations. Stopping the write or
new pool admission does not erase separately acknowledged history. Historical
artifact authority does not grant current source/annotation disclosure, and this
internal operation returns no bodies or external freshness assertion.

## Conditional preservation arguments

For finite normalized inputs, immutable artifacts, confined producer factories,
truthful host/provider facts and serialized native transitions:

1. The sealed baseline is traceable to an actual qualified producing task and its
   private immutable capture. Descriptor, serial, acknowledgment and version checks
   prevent copied metadata from inventing a different write or stronger guarantee.
2. Exact before-root identity, current pair/registration, evidence identity and
   newest-eligible checks prevent stale or superseded new publication. Root-frame
   equality permits only the declared baseline/publication change. Refusal leaves
   the actual root, hold ledger, writer charges and claim link unchanged.
3. If N holds were reserved at p and publication consumes one, the remaining N−1
   are checked at p+1; promised units are neither spent twice nor stolen from
   another hold. Byte floors similarly use the complete candidate and remaining
   per-document maxima. An unchanged transfer consumes no publication unit.
4. A consumed hold is replaced by actual retained producer ownership. Its lifetime
   reference count cannot exceed issued holds, and its writer payload remains
   charged. Actual-native-root retirement checks prevent a supplied-root omission
   from removing the producer while its baseline still depends on it.
5. Existing source journal receipts carry only through the exact metadata frame
   with their source/revision evidence intact. Baseline bookkeeping cannot create
   a source edit, parser transform or new source receipt identity.

These are authored conditional accounting/frame/ownership arguments and finite
actual-code checks, not proof-assistant induction, new SMT conditions, independent
Cleanroom certification or whole-engine categorical closure.

## Remaining integrations and observations

Atomic ordinary-save admission still needs one checked transaction before dispatch.
Unclaimed/legacy historical exports, cross-context adoption, failed/abandoned hold
resolution and complete supplied-root/destination metadata routing remain open.
This path neither silently adopts those cases nor weakens them into successful
installation. Actual provider/policy truth, production package privacy, public
invocation/events, complete global/origin/temporary/physical accounting, hostile
decoding, production/concurrency and independent assurance remain gates.

The private certificate is temporary within one serialized call; its additional
preparation/copy costs rely on the supplied bounded parent preparation premise.
The hold/reference accounting here is not a complete temporary-peak or allocator
proof. No new public operation, transport, component or native job kind is selected.
