# Decoded synchronous search evidence

Section 15.4.4 connects the existing typed and dynamic F05 routes to the same
synchronous native service. All three literal operations preserve one canonical
meaning, original opaque context identity and existing result ownership. There is
no new transport, asynchronous mode, UI policy or substrate mechanism.

## Data and authority

Exact outer tuples and request fields derive from the existing facade and literal
declaration. Literal spelling, scope order, unsupported profiles and well-shaped
stale navigation are preserved for native evaluation. Bounded inert copies reject
malformed scalar text, unknown fields, accessors, cycles and unsupported prototypes.
Opaque identities are bound without traversal. These checks do not contain hostile
Proxy/native behavior or implement a wire decoder.

The authority frame has seven exact fields; existing authority/engine domain
binding does not grant source access or require every actor field to equal the
domain's initial caller. The original source owner separately validates its
recipient scope and read profile. The current request, its opaque context, six
query facts, source scope and current host facts are independently captured. No
command data repairs a mismatch or promotes current grants. Recognized source loss
is checked by the native service before query capacity and host-resource refusal;
foreign/malformed requests cannot poison the original context.

## Ownership and logical units

Before bounded copying, the owner reserves one finite classification frame: the
serialized exact three-field limit record at the largest safe integer values.
It then reserves eight frames at min(maxRequestBytes, owner.maxIntentBytes).
Envelope, authority, canonical record, limits, normalized descriptor, current/facts
packet, producer request and restored current request each fit that ceiling. Node
and depth ceilings apply independently. The explicit conservative envelope bounds
declared logical units, not physical allocation, arbitrary descriptors or global
memory; its coefficient is not a production measurement or numeric default.

The workspace stays charged and busy throughout the synchronous query. Protected
finally cleanup refunds exactly its own charge; nested entry refuses. A fixed
pre-query surprise fences the owner with no native issuance, hold or authored-root
change. Returned products remain owned by the existing native service and retain
their issuer-specific hold and spent issuance. Cleanup neither retires results nor
refunds their separate reservations. Post-query crash cleanup is not established
by the pre-query fault probes.

## Execution and observation boundaries

### Cooperative cancellation quantum

Specification §15.4.4 binds requirements §§5.6/7.6 to the existing synchronous
profile. A whole bounded query is one cancellation quantum, not each storage
chunk. Original context/current notStopped checks precede evaluation. The call
admits no interleaved owner transition; a stop accepted afterward governs later
queries, retained-result release and dependent editing, not already disclosed
bytes. Host control service between calls and measured response time remain
separate obligations. This adds no queue, ticket or async mode.

[Emacs quitting semantics](https://raw.githubusercontent.com/emacs-mirror/emacs/master/doc/lispref/commands.texi)
provide safe-point precedent: C-level quitting occurs at explicit checks, rather
than arbitrary instructions. Vellum selects the boundary above for its finite
profile; it does not inherit Emacs's check frequency, keyboard behavior or latency.

The conditional argument is over the existing serialized reference. The entry
check refuses an already stopped request/context before search issuance. During
the call, finite loops and nonrenewable comparison units bound evaluation and no
control transition can interleave. After return, original-context and result
checks reject accepted stop at every subsequent release/use; protected retirement
separately owns the retained hold. Thus no accepted stop is bypassed at a later
boundary, although work inside a previously admitted quantum may finish. This is
not native preemption, open-load fairness or a wall-clock theorem.

Existing qualified controls cover these claims: the gateway's
`current-request-context-and-facts-are-not-repaired-from-decoded-command` refuses
notStopped=false without search issuance; native search's
`source-stop-retains-child-until-protected-result-retirement` and
`query-loss-is-absorbing-without-closing-independent-source-read` cover later stop,
no revival and separate discharge. Native consumer lifecycle checks cover stop
after F11/F12 preparation but before service. Literal comparison-budget/coverage
checks supply the finite-work case. These existing assertions are reused; no
mid-scan interruption or new proof model is claimed.

Use finite dispositions, logical saturation and retained counts; never use source,

Complete public nested/result/event/selector discovery, separately supported
