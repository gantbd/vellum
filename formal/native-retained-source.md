# Retained source context acquisition evidence

The native source pool accepts retained selection of an original available context
in the same actual owner, domain and pool. Its exact stored source/revision and
immutable source profile supply a new owned copy. This extends existing F02
snapshot-handoff; it adds no verb, transport, public pin API or numeric default.

## Identity and authority

Original object identity resolves the retained context. Copied, missing, foreign,
stopped or retired references refuse without current-state fallback. A source
revision or matching visible tag cannot stand in for retained ownership. Only the
already retained source projection is available: this path cannot add annotations,
change scope or reconstruct fields from current content.

The caller scope must match the captured document incarnation, recipient, purpose,
destination, policy, continuity and profile. Binding is not a grant. All original
context release and new preparation facts remain exact-true requirements. Accepted
false authority, scope, continuity, liveness, retained availability or source-read
loss closes delivery before considering new capacity. Unknown facts and transient
resource/refusal conditions do not establish loss. Actual owner faults/disposal
fence reacquisition despite stale positive supplied facts. Host policy/identity
truth and complete notification remain premises.

## Owned copies and resource bounds

The existing pool reserves complete context/source/scope/reply and input workspace
frames. Retained acquisition copies the exact available projection under those
limits, issues one new opaque context and spends one nonrefunding issuance unit.
Context capacity, lifetime issuance and the normalized request envelope remain
independent admission limits. Opening still compares local limits with actual
parent headroom; no additional numeric defaults or physical accounting are inferred.

The copied context does not borrow a parent lease or acquire a hold on the original.
The original may stop and retire without erasing the new owned copy. Both contexts
independently require current release, actual document liveness and protected
retirement. A later source publication refreshes neither. Internal holds retain
stopped bytes until separate owner/retention/drain discharge; pool retirement
refunds only its own reservation, never spent issuance or another owner's frames.

All three F05 variants can search the old cut after newer publication and original
context retirement. F11 replacement and F12 occurrence selection retain their
separate preparation/service currentness checks; retained bytes grant no write
authority and cannot repair stale revision or companion evidence.

## Observation and remaining gates

IF-02/05 and PATH-02/07 distinguish retained reacquisition, source/search handoff
and dependent editing. INS-01/03/05/06/08/13 distinguish admission, evaluation,
release, current use, retention and protected discharge. MELT/golden/RED/USE may
record finite operation/disposition, latency, logical saturation and spent issuance;
source, selectors and identities are not metric labels. Observation grants neither
read access nor cleanup authority. Actual clocks/telemetry and measured ceilings
remain separate obligations.

The substrate probe excludes import/setup and arbitrary host APIs; its unchanged
preinstallation frame is not general fault containment. Section 12.8.7 supplies
retained annotation/combined projections and class narrowing. Broader historical
publication lookup and coherent version-set
ownership, asynchronous protocols and complete public codecs/results/events remain
required. Actual policy/identity/notification, physical/global accounting,
production concurrency/crash behavior and independent assurance remain gates.
No categorical or whole-engine completeness follows from these scoped checks.
