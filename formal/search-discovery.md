# Search product and discovery evidence

Section 22.1.9 exposes the existing three synchronous F05 search operations through
explicit discovery profile owned-contract-discovery/4. Older /1–/3 catalogs retain
their exact rows and order. The first-party source uses the existing F01 owner,
current cuts, original opaque selectors and captured/current metadata ceilings.
Discovery is descriptive data, not a new execution or registration mechanism.

## Shared declarations and product meaning

Request fields and operation names come from the literal handler's declaration.
JSON Schema 2020-12 describes exact outer fields and operation-specific navigation:
null for literal-matches and object for next/previous. The normalizer and schema
share exact source-ref, scope-row and navigation field declarations. Nonempty
identity text, safe nonnegative numbers, null/numeric current index and boolean
wrap are described without allowing extra nested fields. Empty query text and
unsupported nonempty profile names stay structurally valid. The conservative
outer-structure-only coverage marker does not claim a complete value codec.
Authority equality, lo/hi ordering, scalar-text validity, current source/ref meaning
and opaque authenticity remain runtime checks. Only these exact
fixed schemas are recognized; there is no arbitrary evaluator or remote loading.

The actual producer shares a closed refusal/data/navigation shape declaration.
Superseded, unavailable, exhausted and unsupported carry status only. Complete and
partial replies carry the original context, source ref, generation, coverage,
matches and total; navigation appears only when requested. Complete totals are
exact within scope; partial totals are null, and partial navigation is unavailable.
Each match contains lo/hi plus an original owned occurrence reference. Complete
navigation admits match/index/wrapped, none or stale. Producer assertions reject
undeclared shapes; they do not establish source authority or nested codec validity.

Discovery references identify F01 metadata, not F02 contexts or F05 occurrences.
Neither schema validity nor positive advice authenticates a selector or grants
execution. F11/F12 still depend on the original native result's current-use checks.
The selected synchronous profile has no asynchronous events or interleaved stop;
separately required asynchronous lifetimes and cancellation remain open.

## Resource and observation boundaries

The larger permitted catalog must fit every existing discovery envelope. Failure
does not widen limits, install partial descriptor selectors, spend issuance or
disable an older profile that still fits. Reply-bound refusal preserves staged
selector registries. Discovery leaves authored roots and invocation accounting
unchanged; this is not whole-engine/parent/physical/global accounting evidence.
No production numeric defaults are added.

IF-01/02/05/07 and INS-01/03/05/09/12/13 separate metadata release/advice from
search evaluation/current use. MELT/golden/RED/USE and STRIDE/LINDDUN/STPA/FMEA
cover origin/schema substitution, downgrade, copied selectors, partial-result
overstatement, stale permission and exhaustion. Use finite dispositions and
logical units, not schemas, source, selectors or private identities as labels.
Diagnostic evidence cannot confer grants or discharge protected ownership.

Post-import probes exclude fixture/catalog-example reads and do not establish
static package isolation, all-host API coverage or fault containment. Complete
nested/reference/companion codecs, all-family dispatch, actual host/policy truth,
measured/physical/global/concurrent/crash refinement and independent assurance
remain explicit gates. No new SMT law, component or network path is introduced.
