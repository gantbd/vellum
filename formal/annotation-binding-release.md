## Association and ownership

[Emacs buffer file association](https://www.gnu.org/software/emacs/manual/html_node/elisp/Buffer-File-Name.html)
can be removed while preserving the buffer. This is precedent for separating
in-memory content from a visited resource, not evidence for Vellum's effect,
annotation, retention or concurrency guarantees. The direct executable precedent
is the existing disposed source-binding release and shared destination writer.

The internal disposed-annotation-binding-release/1 request contains exactly
contract, document, expectedLifecycle, expectedPair and expectedAnnotationBinding.
It is a disposal substep, not a new public verb or live unbind/rebind policy.
Require a bounded valid lifecycle root, activated ordinary-binding inventory and
annotation membership inventory. The selected actual writer belongs to the same
authority. Actual complete writer routing and host retention remain premises:
an unrelated empty same-authority registry is not proof that other writers have
no outstanding effects.

Only live=false with phase disposed-retained is eligible. Check the current
document identity and all three expected generations. Sixteen independent facts
must be exactly true: the existing ten lifecycle admission facts and binding
release, binding coverage, writer coverage, disposition readability, annotation
history retention and annotation history coverage. Boolean completeness fields do
not establish that real inventories are complete.

An absent history is known-empty only under explicit absence attestation; present
history must be a bounded array of exact binding/baseline pairs, with unique older
binding generations and recognized baseline descriptor shapes. Missing baseline
also needs explicit absence attestation. No legacy migration, baseline decoding,
freshness or acknowledgment promotion occurs. Loaded bytes and acknowledged-write
bytes retain their existing separate meanings.

Require the exact unique annotation owner row and current binding generation,
with no retained export origins. The actual selected shared writer must report
every same-key task safely disposed: queued work must be stopped; dispatched work
needs known application, uncontested evidence and no-future-effect disposition.
Quiescence or cancellation alone does not establish effect resolution. Conversely,
safe disposition can release the key while execution charges remain held; this
does not refund tasks or release their evidence.

## Publication and preservation

Append the exact old binding and baseline to retained annotationBindingHistory.
Set the current annotation baseline to null, remove the current annotation
binding and exactly its owner row, and advance pair, lifecycle and publication
generations without overflow. Validate the resulting bounded root and activated
pair inventory before accepting the copied candidate. Failure returns the
original root unchanged; no peer owner or provider ledger changes.

Preserve source, serialization, annotation bodies/targets/placement/membership,
source and linked history, views, workspaces, peer documents, identity allocation,
source binding/baseline and historical writer/read/codec state. Source and
annotation key release can occur in either order. The existing provenance-release
substep still requires both current bindings absent and independent history,
snapshot, read, write and provider discharge. Archived data remains present and
accounted until that separate disposition; this is not physical reclamation.

After successful release, a current repeated request is unchanged, not another
archive append or generation increment. Stale requests refuse. No current
annotation binding means no non-null current annotation baseline is permitted. This
substep neither grants permission to reattach nor proves baseline producer-pin
retirement; the actual native authority still retains its original pins.

proof-assistant induction, whole-engine categorical closure or independent assurance.
