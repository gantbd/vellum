# Fixed selection behavior declaration

The F12 declaration describes existing selection/navigation semantics without
choosing key bindings or visual presentation policy. It derives four argument
forms from the native selection and Unicode-boundary declarations: explicit
selection, logical line/document movement, search-match selection, and logical
Unicode movement. Three semantic verbs remain the public behavior facade.

The outer schemas preserve exact contract/operation/profile constants, required
fields, basic types and safe integer bounds. They do not validate every nested
selection, permitted unit, Unicode coordinate or original opaque handle. Nine
counterexamples show structurally valid data refused by native revision, value
or identity checks. Source-read and view-write rights remain mandatory;
source-write rights are unnecessary for these view-only operations.

`selection-descriptor-checks.mjs` exercises eight actual owned publications across
typed/dynamic routes without changing documents or source history. Its four
controls include 249 standard JSON Schema cases, 232 syntax refusals and 42
recognition refusals. `selection-descriptor-mutations.mjs` detects nineteen
targeted changes to declarations, schema bounds, recognizers and effect claims.
Construction, import and external-validator failures are not semantic detections.

The companion discovery /11 integration registers the existing semantic forms
while preserving profiles /1–/10; see selection-discovery.md for its separate
evidence. Complete outcomes/events, public result mapping, implementation
refinement and host/measurement/independent evidence remain open. Existing runtime
gateway and substrate checks keep their own scope; these declaration checks do
not expand their interception claims. No new instrumentation path, deployment
dependency, production callback or schema loader is added. Full frozen
qualification and endpoint reconciliation are still adoption gates.
