# Owned native annotation creation and deletion

Specification §13.6.2 connects native F13 create/delete to the same owned annotation
producer, compound membership/history evaluator and shared invocation ledger used
by the field bridge. It closes normalized native admission/publication and selected
native F14 composition, not identity issuance, lifecycle activation, a wire decoder
or complete result/event projection. Section 13.6.3 separately checks actual native
collection events and independent current writer outcomes in
[annotation-observation.md](annotation-observation.md); that does not complete F13
record-result products or every event profile within that event checker. Section
13.6.4 separately checks normalized native identity/version receipts and current
release in [annotation-results.md](annotation-results.md); wire/alias/query and
actual host/issuer/grant refinement remain separate.

## Allocation and retained identity

[VS Code's notebook model](https://raw.githubusercontent.com/microsoft/vscode/main/src/vs/workbench/contrib/notebook/common/model/notebookTextModel.ts)
separates fresh cell-handle allocation from reinsertion of retained cell models
through undo. That supports the existing fresh-versus-restored distinction; it
does not prove Vellum's authorization, incarnation or resource contracts. Native
create/delete retain the membership rules in
[annotation-membership.md](annotation-membership.md), rather than treating create
as restoration or deletion as final retirement.

Public create still carries no caller-selected live identity. The trusted host
supplies an already-issued private allocation with exactly invocation, document,
id and incarnation, under a strict current-allocation premise. Preparation binds
that allocation to the original invocation/document and copies it into the owned
descriptor. Publication requires the same allocation and captured lifecycle limits;
it cannot ask for a newer identity or retarget a prepared create. The host must
establish actual issuance, reservation lifetime and non-reuse even after refusal.
This reference neither implements that issuer nor discharges its obligations.

The complete owned native request constructs the private compound plan and its
matching ordered allocation manifest. Public callers cannot supply those manifests
through F13, forge the WeakMap-owned descriptor or replace its stored body/target.
The compound evaluator independently checks live and retained inventory against
the proposed identity. Present, retained-absent and retired incarnations cannot
be reused by ordinary create; a live local ID cannot name two incarnations.

## Current publication and reversal

Preparation and publication validate the existing exact native common/variant
products, current owner/recipient/profile, required-plus-extra dependency union,
live document, explicit bounded inventory and logical limits. Create supports
document, nonempty range and explicit-profile/affinity point targets at actual
UTF-8 scalar boundaries. Its target must name the current source revision; later
source work refuses the prepared create instead of moving or rebuilding it.

Delete binds the exact annotation incarnation and both current authored field
versions. It does not need source-write authority, a new target, fresh-allocation
evidence or an unrelated target-current flag. Source mapping can advance current
placement without changing authored versions: deletion then retains the actual
current mapped payload, not a preparation-time copy. A changed authored body or
target makes the old delete ineligible.

Both operations pass through the existing `annotation` invocation kind. Successful
publication advances the annotation collection/publication once with one real
membership journal. Stop, current-check failure, resource/counter pressure and
outer root refusal install no membership/history candidate. A settled retry cannot
run again. Current release gates still govern outcome observation; neither native
admission nor local success grants disclosure of a newly allocated record. Complete
F13 result-reference allocation and collection/event integration remain separate.

Actual native F14 undo/redo uses the existing frontier and current-rights checks
and the retained membership evaluator. Restoration preserves logical identity but
advances both field counters above retained floors. A history reversal does not
make the original create/delete invocation executable again. General target
restoration and full retirement planning remain outside this profile.

## Conditional argument

Assume a trusted serialized owner boundary, authentic current host facts, a valid
explicit lifecycle root and the supplied finite logical budgets. The pure producer
copies and freezes private intent, not caller objects. Native admission can then
only retain the original operation, allocation, limits and dependency set.

At publication, revalidation either refuses without changing the input root or
constructs exactly one compound participant from that retained native request.
For create, equality with the captured allocation establishes that the lowering
cannot substitute another currently valid identity. Exact whole-plan manifest
construction supplies the compound binding premise, not issuer truth. For delete,
the current incarnation/two-version test selects the current record; it cannot
remove a later authored state or restore a stale prepared placement.

The existing compound candidate and outer invocation root/fact protocol establish
one local installation or no installation under their stated premises. The retained
membership version-floor laws in baseline-contracts.smt2 apply unchanged; this
batch adds no new SMT axioms or inferred cross-language refinement. Induction over
the owned invocation phases preserves single execution after success, refusal,
stop and later history reversal. This is an authored conditional argument plus
bounded executable evidence, not a machine-checked proof of an arbitrary engine.

Each finite reference call terminates under the explicit bounds and existing
compound/view operators. It performs no provider callback, grammar work, network
operation, arbitrary user code or search for an alternative target. This does not
prove the runtime's physical allocation, native scheduling or hostile decoding
termination. The execution vocabulary remains closed; a known refusal is distinct
from the shared kernel's Unknown/faulted fence for a surprise.

## Executable evidence

`annotation-membership-editing-checks.mjs` exercises the actual shared producer,
editing adapter, kernel and native reversal path:

- 512 admission and 8,192 publication gate combinations across create/delete;
- 256 current-release combinations;
- 1,440 six-action permutations, 8,640 edges, checking at most one execution and
  unchanged source (finite permutations, not arbitrary trace closure);
- 118 target cases against an independent scalar-boundary oracle, including
  document/range and both point profiles with both affinities;
- fourteen semantic controls and fourteen rejected producer mutations.

Controls distinguish admission from downstream refusal, require both delete
versions, test current mapped retention, reject allocation/limit substitution,
reject missing inventories and tracked incarnation reuse, and cover original
request/allocation ownership, capacity/stop/retry and actual F14 fresh-version
round trips. The unmutated dynamically loaded composition must pass before any
mutation is counted. A mutant must cause an assertion failure; import/load errors
do not count. Existing field tests now apply each semantic mutation to all matching
sites, so a newly added membership branch cannot hide an older field mutation.

## Instrumentation and remaining obligations

PATH-01/03/04/10/12 and IF-01/03/08/12 retain the existing local admission,
publication, history and release boundaries. INS-01/02 record preparation/current
validation, disposition and atomic root/fact outcomes; INS-06 separates membership
frontier/restoration failures; INS-07/08 track retained payload and discharge;
INS-03/12/13 keep current disclosure, diagnostic loss and useful completion distinct.
MELT/RED/golden signals distinguish offered/admitted/applied/refused/faulted work and
phase latency; USE tracks descriptor, inventory/history and held-byte pressure.
No raw annotation ID, body, coordinate, descriptor or private blocker becomes a
metric label. STRIDE covers substituted allocation, replay and stale deletion;
LINDDUN covers retained-body/linkage and newly allocated identity disclosure.

Section 11.2.4 separately checks new source/scratch inventory construction and
relations/disposal/release framing in [annotation-lifecycle.md](annotation-lifecycle.md).
This native checker's lifecycleActivationProved:false still describes its own scope,
not absence of that separate evidence.

Remaining obligations are actual identity issuer/reservation and host policy truth,
legacy inventory/annotation-snapshot activation, complete native result/event
projection, general retained target mapping/full retirement planning, point-profile
persistence, hostile public codecs and actual concurrent/crash/physical/native/
production/independent refinement. No family, decision row or all-sections goal is
closed by this native bridge alone.
