# Native history query results and fault retention

Existing F04 queries return frontier, availability, blocking-detail or unavailable
products. Closed structure, original-context binding, permitted alias membership
and copy integrity are distinct checks. None establishes complete history truth,
current authority or reversal rights by itself.

## Structure and captured binding

`history-query-results.mjs` supplies immutable result-field and availability
declarations consumed by actual guards. Frontier carries status/context/group,
with an explicit null group for established emptiness. Availability carries
status/context/value with empty, eligible or blocked. Blocking detail carries
status/context/blockers. Unavailable has status only. Successful products must
match the original operation and expected context identity.

Each blocker has exactly scope/group labels. Require nonempty valid Unicode
labels, a dense ordinary array within the existing detail bound and strictly
increasing scope order. Two scopes may name the same group; repeated scope rows
are not allowed. Reject extra fields, symbols, nondata properties and unsupported
record/array prototypes without executing getters or coercing a status object.
This applies to trusted native product construction, not arbitrary JavaScript
proxies or hostile decoder containment.

Before rebinding, compare the lower product with the independently retained private
context and captured projection. Frontier aliases and every detail alias must be
permitted by that projection; detail also needs its captured disclosure ceiling.
The lower reply is not its own alias authority. Replace only the private context
with the original issued native handle. Check that rebound product, preflight its
existing reply-byte limit, then copy disclosed values while preserving the handle.
The copied product must retain shape, context, permitted aliases and exact values.

Shape-valid aliases can still be unpermitted. Even an allowed availability label
does not prove the actual group eligible. The existing actual history basis,
complete-participant calculation, evidence, current release and projection premises
continue to own those meanings. No token codec, issuer or public operation is added.

## Fault state and ownership

A malformed internal product, invalid original binding, unpermitted alias, copy
frame violation or unexpected lower/copy exception sets the inspection owner's
fault bit and returns only unavailable. That bit fences new acquisitions, later
queries and trusted reversal-alias resolution. It does not mutate authored roots,
cancel an independently owned reversal, delete contexts, refund issuance or release
their retained obligations.

Owner stop and fault bits are separate and never cleared on that owner. Individual
entry liveness is another facet. A retained entry can keep its live flag while a
faulted owner makes it nondeliverable; that flag alone is not a grant or a count
of admissible deliveries. Closing and retirement remain available after a fault,
with their original recipient, delivery-drain and retention conditions. Retirement
removes discharged entries from the registry; it does not reduce the owner's
declared base-capacity reservation or refund lifetime issuance.

Ordinary unavailable products, unsupported/malformed requests, unknown aliases,
withheld authority and reply-capacity refusals do not become invariant faults.
Recognized current loss still invalidates its context through the existing path;
later equality or regrant cannot revive it. No generalized recovery or restart
protocol is established here.

## Conditional reasoning and resource scope

For an admitted finite native product, the fixed status partition selects one
closed branch. Detail traversal decreases the remaining bounded row count; alias
membership scans finite captured scope/group arrays. Copy comparison follows the
already preflighted finite value tree. Private owner storage has no exposed fault
reset, and fault handling retains rather than discharges registry obligations.
These structural arguments rely on existing serialized execution, captured bounds,
trusted host facts and runtime semantics; the finite checks below are not unbounded
induction or categorical completeness.

The existing history owner retains its capture/basis and two-reply logical envelope.
Preflight the rebound value before making its disclosed-value copy. This adds no
retained alias set, numeric default or complete auxiliary-allocation accounting.
Descriptor reflection, malformed native-code outputs, physical/global/concurrent/crash limits
and measured latency remain external refinements. Actual-parent argument gateway
workspace admission/discharge is still a separate obligation.

## Observation and security coverage

IF-01/02 and PATH-02 retain the existing read boundary. INS-01/03/06/07/08/12/13
must distinguish ordinary refusal, lower-product validation, rebinding, copy/reply
admission, owner fault and protected discharge. Observe bounded stage/outcome
buckets, latency and error rates, retained context/issuance pressure and discharge
progress using the existing MELT, golden, RED and USE lenses. Count a fault once
as an owner transition rather than reclassifying every later unavailable delivery
as a new fault.

STRIDE challenges spoofed contexts, alias substitution, value tampering and loss
of protected cleanup. LINDDUN and the existing privacy/hazard review challenge
hidden blocker leakage, linkage and raw fault-payload retention. Do not log a
malformed product or use source/history contents, aliases or handles as ordinary
metric labels. Existing recipient-scoped observation/current-release rules govern
disclosure; instrumentation does not grant query or reversal authority. Reference
checks do not establish actual runtime signal delivery or measured thresholds.

## Evidence and remaining gates

`history-query-result-mutations.mjs` checks a coherent copied-graph baseline and
31 semantic mutants. Every mutant runs both complete shape and fixed-fault corpora;
an assertion must detect the change, and nonassertion process/syntax failures reject
qualification. The shape corpus has seven controls, twelve native products,
114 malformed products, three exact detail boundaries and three explicit cases
where shape does not establish alias authority or history eligibility.

Thirteen fixed probes cover 29 native branches, including lower/copy exceptions,
extra fields, context substitution, product getters/coercion, foreign aliases and
changed copied meaning. They check unchanged roots, retained obligations, fenced
admission/alias resolution, protected retirement and nonrefunding issuance.
The selected substrate checker intercepts 143 filesystem/process callables after
imports. Its complete seven-control corpus, including fixture operations, makes no
baseline calls; three injected call types are detected. This is not import
isolation, all-host containment or production dependency separation.
