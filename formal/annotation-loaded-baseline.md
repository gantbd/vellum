## Owned read and shared writer evidence

The native read coordinator registers its actual private reader-task and consumed
restoration stores with a format-neutral provenance participant. Only that confined
factory obtains the stores; no recipient API exposes them. The participant checks
the actual submitted read, uncontested/unrefused status, sole successful EOF,
complete retained chunk bytes, original captured request/basis/registration and
start version/coherence. Stop does not erase previously consumed read evidence.
The participant imports no snapshot parser, schema, provider or host callback.

The shared writer explicitly attaches that read owner to its actual native domain.
Attachment requires independent owner/preparation/resource/coverage facts, bounds
the declared owner relation and reserves maxCaptureBytes per relation in existing
writer held capacity. It spends no invocation, writer ticket, artifact or origin.
Repeated exact attachment is current without a second charge; foreign/cloned owners
refuse. Attachment/engine-global ownership and physical memory are not proved by
this logical record bound. No detach or provenance-discharge facet is selected here.

Initial adoption requires the exact current annotation binding, whole captured
read registration and current complete ordinary-pair/known-distinction checks.
The original read must have actually restored or validated unchanged annotations.
Source/body edits after restoration may proceed: the baseline continues to name
the original consumed snapshot and does not claim those edits were loaded.

A confined actual-writer guard covers the entire destination key, not only the
target document's annotation tickets. Queued active work, unresolved work, known
writes and quarantine refuse initial adoption. Stopped unlaunched or confirmed
nonapplied work may be harmless only under the existing destination-release,
disposition/quiescence and uncontested facts. The guard checks the actual attached
read owner and live writer ledger again at certificate consumption; a caller label
or a previously true coverage check is insufficient. It does not infer ordering
between independent read and write resource tokens.

## Loaded baseline values and publication

The loaded-annotation-capture record contains annotation binding generation,
original source revision, the annotation set established by restoration, selected
format profile and restoration context, read origin/provider/resource, independent
read-registration generation, captured version/coherence and original raw bytes.
It contains no write dispatch serial, acknowledgment or durability strength.
The loaded annotation-set value includes the restoration increment, or remains
unchanged for empty validation; it never relabels later authored edits as loaded.

Adopt only into a known null/absent baseline; absence needs its independent current
attestation. An exactly matching, actually adopted loaded baseline can return
current without another generation. Other baseline replacement, including an
acknowledged write or unsupported/unknown baseline, refuses. This prevents a late
read from regressing stronger own-write knowledge. No latest-read ordering or
arbitrary replacement policy is invented.

The complete original provenance plus prospective baseline must fit the existing
per-task companion reservation, and the baseline must fit the actual writer's
baseline bound before publication. A private ephemeral certificate binds actual
owner/task/domain, original read/application records, writer guard, complete
before/next roots and exact baseline. Native consumption revalidates it, actual
before-root identity, current fifteen-fact gates, liveness/binding, safe generation,
complete baseline-only frame, native root size and every attached reservation
floor. Only annotationBaseline and one publication counter may change. Current
success keeps root identity. Existing parser-source receipt identities carry
through this metadata-only publication without minting transforms.

Final baseline publication and adoption bookkeeping form a serialized reference
transition. Expected refusal changes no root, issuance, persistent charge or
adoption state. Temporary preparation peaks, allocator failure, production
concurrency/crash atomicity and package confinement remain refinement premises.

## Comparison and subsequent writes

The shared writer authenticates loaded baselines through the explicitly attached
actual read owner, document/full binding and exact reconstructed baseline, with
the native domain checked where available. An attribution string, baseline copy,
same length or equal token is not independent evidence. The existing authorized
native artifact capture then compares complete intended output bytes directly
against the original loaded bytes under the combined comparison budget.
Comparison does not issue persistent work, adopt a baseline, report current
external freshness or acknowledge a write.

Original noncanonical JSON whitespace/member/escape spelling remains in the read
and baseline. Canonical intended output can honestly compare different immediately
after semantic restoration. This is exact output equality, not semantic-clean
status or a claim of a formatting-preserving JSON encoder. The adopted annotation
format's semantic-value fidelity and the source file's independent byte-round-trip
law must not be conflated. Persisted version/source evidence can also differ after
undo even when body text again matches; versions are not silently discarded.

An ordinary save from a loaded baseline requires actual uncontested baseline
evidence and the exact pinned loaded token. Launch rechecks loaded evidence, so
a queued ordinary save cannot overwrite after its producing read becomes contested.
The ordinary capture retains its original loaded baseline within maxCaptureBytes;
launch revalidates that historical dependency even after an intervening qualified
write has replaced the root baseline. A reused external token cannot substitute
the newer root's acknowledgment for the queued capture's now-contested read.
Explicit conversion/force/recovery or other export profiles are separate contracts,
not an automatic fallback when ordinary save is refused.

The existing ordinary writer/codec/reservation/native installation path can replace
a valid loaded baseline with its qualified acknowledged write. Requested/achieved
strength and original dispatch attribution remain the writer's own facts. A later
contradiction of the old read does not invalidate the independent new write's
baseline or roll back authored state. The old read producer remains conservatively
pinned until complete transfer/discharge is specified; replacement alone is not
permission to drop history or other consumers.

## Conditional arguments and finite evidence

For confined factories, actual immutable roots, truthful current host facts,
finite profiles and serialized transitions:

1. Baseline reconstruction uses the original consumed private read and associated
   restoration, so no file field, copied handle or fabricated acknowledgment can
   create loaded provenance or stronger persistence knowledge.
2. Actual writer coverage plus destination-wide nonapplication checks and final
   revalidation prevent known conflicting own effects from being replaced by a
   read-derived first baseline. Existing non-null baselines are not regressed.
3. The complete certificate frame and reservation floors preserve authored state,
   peers, history, bindings, source baseline and other promised capacity. Exact
   current metadata needs no spare publication generation.
4. Direct byte comparison establishes only intended-output equality to that
   attributed baseline. Later read contradictions disable read-derived evidence
   and ordinary overwrite without rewriting published state. Independent qualified
   write evidence remains independent of the old read.
5. All calls traverse bounded root/task/attachment/transcript arrays/maps and closed
   variants; no provider callback or unbounded interpreter enters installation.
   This proves neither arbitrary provider termination nor wall-clock service time.

These are authored conditional composition/frame arguments, not proof-assistant
induction, whole-engine categorical closure or independent Cleanroom certification.
No new SMT condition is claimed; totals remain 234 across fourteen manifests.

annotation-loaded-baseline-checks.mjs covers 42 native variant/capture/undo/redo
