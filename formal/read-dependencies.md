## Product and precedent

`read-dependencies.json` defines the exact private `owned-annotation-plan/2`
fields and four predicate variants. `/1` remains exact and unchanged; adding
`reads` to `/1` rejects. Reads name source revision, annotation-set revision,
annotation body version or authored-target generation. Placement is not authored
target. Object and record incarnations fence replacement identities.

The architecture follows the read/write-set distinction documented in
[FoundationDB conflict ranges](https://apple.github.io/foundationdb/developer-guide.html#conflict-ranges):
dependencies can invalidate a writer without themselves becoming writes. This is
a local predicate-validation adaptation, not adoption of FoundationDB, its range
algorithm, distributed serializability or automatic retry. Vellum's current owner
already serializes local publication; a failed assumption does not refresh intent.

## Execution and authority

Admission validates the exact finite product, rejects duplicate subjects and
canonicalizes only the unordered read conjunction. UTF-8 byte comparison of a
fixed JSON identity tuple is a private reference ordering, not a public selector
encoding. The whole intent remains subject to the existing byte bound and owned
copy. Final validation uses separately supplied finite count/identifier bounds.

The invocation owner passes its stored seven-field context to the compound
publisher. Every nonempty read needs exactly one current permission fact with the
same complete dependency and actual context and strict true read, presence and
equality grants. The facts may be reordered, but omitted/extra/duplicate or
mismatched facts fail. A host-supplied substitute context cannot replace the
owner's context. Actual policy and evidence truth remain host premises.

Validation runs on the starting root before candidate mutations and semantic
no-op classification. Failure returns that same current root. Successful reads
do not allocate versions or enter `changes`, history scopes, frontiers or views.
Only authored effects enter the existing journal and linked history group.
An empty conjunction introduces no otherwise unused permission requirement.

## Scoped proof arguments

Given a finite validated read list of length n, validation loops over at most n
grant facts and n predicates, with finite root/record searches. It cannot invoke
agent code, recurse into dependency graphs or fetch another workspace. The closed
kind product admits no callback, property-path expression or evaluator. Termination
is conditional on the existing finite inert native products and host execution,
not a proof about hostile JavaScript getters or physical scheduling.

For every accepted nonempty conjunction, each list element has one equal grant
fact, the actual context matches, and its live exact subject/version matches the
starting root. The early return precedes candidate creation: any failed predicate
leaves publication/history/version state unchanged. Subsequent candidate writes
cannot invalidate an already-tested same-object premise retroactively. Induction
over the finite conjunction proves these declared matches, not completeness of the
agent's assumptions or semantic correctness of a rename.

The unchanged compound publisher constructs history from authored `changes` only.
The read validator neither changes the root nor appends a change, so an object
referenced exclusively by reads contributes no authored scope. This frame argument
does not grant semantic undo across future changes; reversal-specific assumptions
remain governed by the existing frontier/reversal contract.

## Executable evidence

`read-dependency-checks.mjs` runs eight current/stale predicate cases, all eight
strict permission combinations and all 24 read permutations. Fourteen controls
exercise both native routes, actual three-object compound publication, exact
product/identity/limit rejection, no-op refusal, same-object validation, legacy
and empty-read compatibility, copied intent, current context and complete grants.
An intervening actual native edit of the read-only object rejects both authored
objects without undoing that intervening publication. An intervening source edit
does not stale a body-only dependency when that body version remains unchanged.

A coherent three-module graph baseline precedes twelve negative mutations:
omitted source/set/body/target checks, ignored context, truthy permissions,
duplicate subjects, ignored count bound, mismatched permission predicate,
omitted publication validation, omitted canonicalization and omitted actual owner
context. Each must fail a semantic assertion; syntax/import/runtime errors are
not accepted as mutation kills. These finite checks and arguments add no SMT
conditions; the prior 252 conditions/fourteen manifests remain separately scoped.

## Instrumentation and remaining gates

Use the existing preparation/final-publication interfaces and pathway observations
for read validation work, bounded refusal, stale assumptions and queue/service
latency. MELT plus RED/USE and golden signals distinguish admission, validation,
candidate publication and observation; no new network path or diagnostic owner is
introduced. STRIDE/LINDDUN apply to private object/predicate/version/context
linkage. Do not emit raw dependency identifiers, versions, grant facts, source or
annotation bodies into ordinary metrics/errors; private refusal detail retains
its existing release ceiling and current authorization.

This slice does not close F10's standalone advisory validation query, dependency
domains outside the four predicates, provider discovery of semantic assumptions,
all managed lifecycle/reversal combinations, full physical accounting, actual
host identity/policy truth, public wire/ABI selection, production concurrent/crash
refinement or independent assurance. No whole operation family or decision row
closes. Focused checks pass; full frozen verification is required for this batch.
