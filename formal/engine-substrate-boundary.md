## Contract and mechanism

The engine captures source/annotation state and serialization settings, validates
dependencies and authority, coordinates its mediated writers and adopts qualified
baseline evidence. A substrate performs the advertised procedure and reports what
it observed. Receipt validation checks attribution and consistency; it does not
prove a provider's report truthful. Lossless preservation remains an observable
obligation even when byte conversion is implemented at the edge.

This matches the distinction in Rust's primary contracts: [rename](https://doc.rust-lang.org/std/fs/fn.rename.html)
has platform-dependent behavior and does not work across mount points, while
[File synchronization](https://doc.rust-lang.org/std/fs/struct.File.html#method.sync_all)
is a separate fallible operation. Those contracts support keeping procedure and
acknowledgment strength explicit; they do not establish Vellum host conformance,
directory durability, conditional writes or protection from arbitrary writers.

## Selected execution checks

Run `node formal/engine-substrate-checks.mjs`. The full verifier runs this checker
in its own process. All fixture and reference modules load before interception.
The checker replaces callable filesystem, filesystem-promise and child-process
exports, synchronizes built-in ESM bindings, and restores the original property
descriptors in a finalizer. It refuses to report success if any callable export
could not be intercepted. The current pinned verification runtime exposes 143
such functions; that inventory is a tool observation, not a product limit.

Six negative controls invoke a read, rename, promise read and process launch,
including named ESM read/launch imports. Each must fail with the checker's exact
interception code. After clearing those expected observations, the checker runs
the existing fifteen workspace-read controls, 24 semantic-settings controls and
twenty annotation-read controls without changing their predicates. It also
executes actual reference source-load staging/activation and source-save admission,
dispatch and receipt processing. No intercepted calls occur on these selected
paths. The save test processes supplied evidence; it does not write a file.

Three complete source-save module variants inject a hidden read, rename or process
launch at dispatch. A coherently loaded baseline first passes the same fixture
path. A mutant counts as detected only when execution raises the exact interception
code and records one attempted call; import, syntax and unrelated assertion errors
do not count. Production behavior is not changed by these verification variants.

## Evidence limits and remaining acceptance

The metadata participant additionally runs through typed and dynamic ordinary
routes with zero intercepted calls. A separate coherent state/editing/kernel
baseline passes both routes before three metadata publication mutations inject
read, rename or process launch. All six mutant-route cases must record the exact
attempted function and result in common faulted/unknown outcomes, unchanged root,
admission fencing and protected retirement without issuance refund. Because the
common publisher catches the interception error, a thrown error alone is not the
acceptance predicate for these paths. No new production behavior is introduced.

The design-reference graph is not statically host-free. A read-only traversal of
the six facade/owner/settings/read/codec/destination roots reaches 71 local modules,
including catalog/document readers and verification helpers. In particular,
`unicode-boundaries.mjs` combines a pinned Java provider bridge with boundary-ticket
validation; semantic commands import the ticket validator. `annotation-snapshot.mjs`
also contains a Python schema-artifact verification helper. Those roles are not
production runtime dependencies selected by their presence in the reference graph.

The interception check establishes selected post-import call behavior, not import
independence, arbitrary dynamic code containment, coverage of every host API or
all engine paths. Captured function copies, native extensions, direct runtime
bindings, networking and concurrent execution are outside this check. Production
package dependency separation, all public/native route integration, concrete host
identity/procedures, physical ownership, crash behavior and independent assurance
remain explicit gates. No additional solver law or categorical closure is claimed.

INS-08 retains resolver/binding observations, INS-07 serialization/preparation and
INS-04 effect execution/evidence. Engine queue/service, provider procedure and
observation delay are separate populations. Report failures and unknown outcomes
without logging payloads, raw paths, handles or resource tokens in ordinary labels.
STRIDE/LINDDUN cover identity substitution, forged/late receipts, silent guarantee
promotion, disclosure and exhaustion at these same interfaces.
