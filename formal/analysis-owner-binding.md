# Actual engine analysis owner binding

Specification §18.8.3 supplies a fixed first-party native assembly over the
existing normalized analysis owner. It binds that owner to an actual engine
domain and current root without selecting a parser runtime, public codec or new
execution mode.

The factory requires strict owner/resource/preparation facts and a supported
explicit analysis inventory. Missing or malformed inventory refuses. Explicit
empty inventory permits ownership but admits no unknown context. One registry per
actual domain retains spent origin lifetime; multiple supported analysis contexts
and providers still use the existing bounded owner. No replacement factory can
reset issuance in that domain.

Admission, submission, acceptance and query obtain the actual current root.
Lower-level calls on the same bound owner reject copied, foreign and stale roots.
Existing native source/context/provider/view applicability and accepted-snapshot
ownership remain necessary. Actual annotation publication can preserve analysis;
actual source publication stales it. These ports do not publish source or run a
provider. The existing native session remains verification-only.

Strict ordinary grants and native health precede work. Producer evidence,
quiescence, cancellation and retirement use their independent strict facts after
a domain fault. Existing parser leases, retained bases, consumed origins and
query-workspace/fault contracts remain unchanged. The legacy unbound normalized
owner is retained, not reclassified as a secure public native gateway.

The actual-module corpus passes ten controls, 117 ordinary and 36 protected grant
cases. It follows genuine native annotation/source publications and a genuine
native owner fault, not simulated replacement roots. Twelve coherent source
mutants are rejected by assertions after a passing unchanged module baseline.
Import/construction errors do not count as semantic detection.

Legacy analysis's 88 controls/21 mutants, live native host's fifteen controls/
fourteen mutants/eleven protocol cases, query-result/workspace five controls/eight
mutants, closed query-value checks and 124 cold native entrypoints pass adjacent
regressions. The legacy data-URL mutation loader initially omitted the new engine
import and stopped at construction; rebasing that import restores the original
mutation suite without counting the failure as a kill.

The original normalized input, trusted current facts and serialized execution are
premises. Section 18.8.4 separately composes the selected existing-owner F08 query
facade; this owner-binding slice alone does not establish arbitrary audience/context
acquisition, F16 activation, matching invocation retry, all F24/F28/events, a
hostile decoder, package visibility or host/parser truth. Section 17.4.2 supplies
selected declared parent/child attachments; neither that nor per-owner logical
charges proves global or physical reservation. No whole-engine categorical closure, arbitrary
receipt lattice, wall-clock halting, concurrent/crash refinement or independent
certification follows. Full frozen qualification and exact adoption remain gates.

Reuse IF-01/02/05/07, PATH-07/08 and INS-01/02/03/05/08/12/13 for binding/profile
refusal, stale applicability, fault, retained obligations and protected discharge.
No new telemetry path or content-bearing ordinary label is introduced.
