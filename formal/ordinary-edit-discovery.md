# Ordinary edit declarations and versioned discovery

Specification §22.1.8 adds selected handler-bound discovery evidence. Full frozen
verification is required for the adopted batch.

## Existing behavior and explicit profile evolution

The fixed owned-contract-discovery/3 profile adds metadata for four existing F11
ordinary-edit request forms: literal selection-edit/1, explicit line-edit/1,
boundary-command/1 and configured-line-edit/1. It adds no edit verb, invocation
kind, UI binding, source mutation algorithm or external service. The default /1
and existing /2 profiles retain their meanings and descriptor rows. The /3 catalog
preserves /2's three-row prefix and appends one ordinary-edit descriptor; it does
not claim every F11 variant is implemented by that source.

Catalog-owned selection, line and boundary declarations expose frozen copies of
the private fields and profile constants used by their guards. The configured
line guard consumes its shared frozen declaration directly. Its constants and
field list are unchanged. Metadata does not become a new preparation authority.

The descriptor uses the existing JSON Schema Draft 2020-12 outer-structure
vocabulary. Distinct contract constants separate four oneOf branches. Every
outer field is required, extra fields refuse, and the existing profile constants
are explicit. Text may be empty; source/selection versions use the safe natural
representation and boundary counts use positive safe integers. These mathematical
representation bounds do not select production workload or memory limits.

Nested value validity, boundary-handle authenticity, exact source/selection state,
configuration applicability, authority and complete companion validation remain
runtime obligations. In particular, a copied boundary handle or stale source
revision can pass the outer schema and still refuse preparation. The older finite
schema recognizer is unchanged. The /3 reader admits this additional schema only
when it exactly matches the fixed ordinary-edit declaration; there is no remote
schema fetch, arbitrary evaluator or handler registration through metadata.

## Current release and lifecycle

The existing F01 owner, cuts, context-local entry/variant selectors and captured
disclosure ceilings govern /3. Fixed first-party descriptor origin is derived by
the internal producer; generic lookalike metadata cannot replace that origin.
Current-root and complete-scope validation remain required at release. Cross-profile
refusal cannot stop another valid context; observed permission/metadata loss stops
the old context, while unknown authority withholds without inventing a revocation.
Publication-guard exclusion prevents release or selector issuance in that guard.

Queries preserve the authority root and invocation accounting. Stop/retirement
retain their protected retention-release/delivery-drain checks and do not refund
lifetime issuance. New metadata still fits the existing independent row, metadata,
packet, context, capture, reply and registry bounds or refuses as unavailable.
A smaller supported profile need not fail because /3 exceeds its own catalog bound.

Advisory enablement remains target-bound and separately authorized. Unknown,
established false and established true are distinct. A positive advisory response
is neither an invocation grant nor a reservation; lost current-target evidence
withholds advice without making unchanged metadata unavailable. Discovery selectors
are not invocation tickets or executable callbacks. The public selector-to-invocation
bridge and complete argument/result/event codecs remain separate work.

## Executable evidence

editing-declaration-checks.mjs compares four independent expected field lists
against actual preparation. All 43 field omissions and four extra-field cases
refuse without root/invocation changes. Sixty independent standard-validator cases
cover four valid products, those omissions/extras, five structurally valid but
semantically invalid source/handle cases and four unknown profile constants.

editing-discovery-mutations.mjs runs fourteen disclosure/lifecycle/advisory controls
and seventeen targeted mutations after a coherent descriptor/discovery baseline.
Source target uniqueness and graph construction/import precede semantic assertion
detection. Mutations cover profile evolution, missing forms/fields, extra fields,
schema recognition, captured ceilings, context binding, loss versus unknown,
publication-guard exclusion, protected retirement, fixed origin and current advice.
The existing generic 32-mutation, eight invalidation, nine builtin-origin, seven
older-schema and eleven configured-line mutation checks retain their identities.
The two older schema-target snippets follow the new profile condition; their
semantic assertions and seven mutation identities remain unchanged.

editing-discovery-substrate-checks.mjs preloads modules and 21 fixture owners per
variant before intercepting 143 filesystem/promise/process callables. The generic
fixture reads catalog examples during construction; that setup is outside the
measured path. All fourteen post-fixture controls execute without intercepted
calls, and injected query read/rename/process variants must record the exact call
and raise the interception code. Originals are restored and checked afterward.
This proves neither import independence nor containment of arbitrary runtime APIs.
The existing semantic-root traversal remains 71 modules without frontend helpers;
it is not a whole-package host-free production claim.

## Conditional arguments and observation boundaries

Shared private field sources and the immutable configured declaration preserve
the existing exact guard meanings. Distinct contract/profile constants and strict
required/extra-field validation describe these outer products without making a
structural acceptance claim about their nested values or current eligibility.
Profile-scoped source selection preserves old metadata rather than reinterpreting
an old captured context. The existing bounded owner machinery governs selectors,
current release and protected discharge; no new execution FSM or solver law is added.

IF-01/02/07 and INS-01/03/09/12/13 retain request discovery, metadata disclosure,
accepted source/profile, bounded capture and lifecycle observations. IF-03 semantic
publication remains unchanged. MELT/golden/RED/USE distinguish metadata/advice
queries, withheld/refused release and registry occupancy/issuance. STRIDE/LINDDUN
cover schema/origin substitution, profile downgrade, copied selectors, hidden
metadata correlation and exhaustion. STPA/FMEA include treating positive advice
as authority, stale state as current and missing cleanup as released resources.
Use bounded profile/reason codes, not handles, native identities, schema payloads,
source, current version vectors or private registry totals in ordinary labels.

Current host/policy/target truth, complete F11/public products, production package
and Rust integration, physical accounting, concurrent/crash behavior, measurements
and independent Cleanroom assurance remain gates. The existing 295 SMT conditions
and fourteen manifests retain their scopes. Full current-input verification is
required before an adopted batch can be called verified.
