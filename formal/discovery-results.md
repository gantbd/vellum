# Discovery native result products

The existing F01 reader returns four closed shapes: page, descriptor, advice or
unavailable. These products describe the current native values without adding a
query, result field, self-discovery profile, transport or executable metadata.
The native query now invokes the existing checker on its actual reply before
selector/issuance publication. Invalid produced results or validator exceptions
fence the discovery owner, not the editing domain; protected cleanup remains.

| Product | Existing meaning and binding |
| --- | --- |
| Page | Original context, captured-permitted coverage, bounded entry references with version/kind, explicit nullable continuation |
| Descriptor | Original context and requested entry; version/kind, variant references, all-or-none schema facets and optional permitted presentation data |
| Advice | Original context and requested entry/variant/target; a Boolean advisory value, not permission or a reservation |
| Unavailable | Status only; no hidden reason, count or partial value |

## Closure and native authority

Exact data fields, safe positive versions, known kinds, dense bounded arrays,
unique reference roles and operation/request correlations reject surprise values.
Descriptor variants contain either their reference alone or all five existing
schema facets: input, outcomes, requirements, limits and cancellation.
Presentation admits only the existing descriptive keys. These literal values do
not configure UI behavior or cause schema loading.

Opaque contexts, entries, variants, cursors and targets remain outside metadata
traversal. Matching copied shapes may still pass structural checks if paired with
matching copied requests; only native ownership and current lookup authenticate
them. Empty permitted rows, empty permitted variant sets, hidden facets and false
advice remain distinct valid meanings.

The native reader still owns selector staging/installation, current cuts,
captured ceilings, fixed origin, loss/stop behavior, retention and whole-reply
limits. A checker refusal after a native query cannot be treated as rollback of
already-installed selectors or spent issuance. The new precommit guard leaves
original maps/issuance unchanged on validation failure; an already consumed cut
is not restored. Actual-parent facade ownership remains a separate obligation.

## Bounded metadata argument

Metadata validation uses an explicit work stack and node/depth/UTF-8 JSON-byte
ceilings. Each iteration consumes node fuel or refuses. Object keys and array
positions contribute their exact JSON punctuation and escaped scalar costs.
Only scalar values are serialized for cost; nested objects are not recursively
serialized or cloned. Sparse arrays, getters, symbols, hidden fields, non-plain
data, cycles, nonfinite numbers and malformed Unicode refuse.

The operation sum and structural field vocabulary are closed. Metadata instances
are not a finite universe before an admitted profile bounds them. This supplies
neither a general bounded lattice nor whole-engine categorical completeness.
Logical cost/termination reasoning does not establish physical memory, arbitrary
proxy isolation or actual host execution limits.

## Instrumentation and evidence

IF-01/02 and PATH-02 distinguish native query publication, structural validation
and recipient delivery. Existing INS-01/03/05/08/12/13 carry MELT/golden/RED
dispositions and latency populations, with USE retention/saturation/discharge.
STRIDE/LINDDUN/privacy/hazard cases include role substitution, partial facet
disclosure, false complete-catalog claims, stale advice, hidden metadata and
reference linkage. Raw references, identities, descriptor bodies and authored
content are not ordinary labels or failure payloads.

Ten controls cover 240 selected native results across all ten profiles, 97
malformed refusals, fifteen exact resource boundaries, seven original-reference
correlations, two structural-nonauthority witnesses and 52 metadata probes.
Thirty-two copied-graph semantic mutations challenge those controls. Selected
post-import result-validation calls run with 143 filesystem/process functions
intercepted: 550 guarded calls make no baseline attempt, and three injected calls
are detected. This does not cover native-query/import I/O or general isolation.

The selected static engine/reference graph reaches 114 modules with frontend
exclusion and clean/ordered initialization obligations. No component/interface
or engine/presentation partition changes.

## Verification partition and adoption

A broader 0.189 verification run reported the existing outer 60-second timeout
in lifecycle discovery bank 0. That failure is not a semantic detection or a pass.
The candidate partitions the same 24 lifecycle mutations into six banks of four
and the same 28 discovery-argument mutations into two banks of fourteen. Result
mutations use four banks of eight. Each bank retains a complete unchanged
baseline and the original oracles; explicit partition checks preserve every rule
exactly once. Neither the verifier timeout nor any engine budget is increased.

Full fresh frozen verification and endpoint reconciliation remain adoption gates.
The timed-out evidence remains unqualified. Native selector/facade fault
integration, result access for other families, events, installed instrumentation,
host/physical/measurement truth and independent assurance remain open.
