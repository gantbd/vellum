## Captures, authorization and destination coordination

source-save.json closes normalized requests, write registrations, receipt variants
and finite profile parameters. Admission captures document incarnation, actual
source/settings revisions, serialization profile/BOM, current binding and full
write registration, original loaded baseline, origin/effect/attempt, pinned
epoch/token, protection and requested acknowledgment. The private actual source-
codec produces the immutable output artifact before admitting any external work.
Invalid UTF-8 or the adopted ambiguous absent-BOM/literal-leading-BOM output refuses
without source mutation or a queued task. A caller-supplied payload is not trusted.

An authority-bound read owner verifies exact historical loaded bytes, provider,
binding, versions and strength against its retained successful transcript.
resourceReadBaselineEvidence validates that retained fact without installing an
old baseline over the current root; loadedBaselineUncontested still checks the
actual current root. Neither predicate establishes current external contents or
write permission. A later contradiction in the read owner prevents dispatch.
Section 16.5.1's acknowledged-write anchors use actual private write evidence, not
this loaded predicate. Transferred/rebound provenance remains integration work.

Admission and dispatch independently require current launch grants, source access,
authority/scope/continuity/liveness/stop, complete binding coverage, complete writer
coverage, provider availability and usable resources. The root's resolved key must
have exactly one source owner with the matching binding generation. The supplied
coverage predicates must cover *all* relevant artifact roles and engine writers;
the source-only reference does not prove actual annotation-writer integration.
Provider identity and these policy/coverage facts are trusted host premises.

FIFO is by admitted task order per [identity domain, identity key], not document
revision, workspace, provider, locator alias, procedure or serialization profile.
No latest-only coalescing occurs. Canceled queued entries leave scheduling order;
their retained payload/origin obligations remain until explicit retirement.
Independent destinations may progress. Whole registration and binding bodies are
rechecked before dispatch, not just a caller's unchanged generation number.
Newer source/settings alone do not invalidate or alter an older frozen payload.

At launch an attested probe must identify the captured provider/resource/key and
registration, and match the original pinned epoch/token. A changed/missing token
does not refresh the condition. Ordinary best-effort checking is not atomic
isolation against arbitrary external writers; conditional protection requires its
independent declared capability. Ordinary acknowledgment requires synchronization
where the declared procedure supports it; explicit synchronized requests reject
unsupported profiles before admission. Write-only is separately explicit.
Actual [write/synchronization behavior](https://doc.rust-lang.org/std/fs/struct.File.html#method.sync_all)
and platform replacement guarantees remain adapter/refinement obligations.

Only a dispatched task can disclose bounded artifact ranges to a currently
authorized matching provider/resource recipient. Results are copies; modifying
a returned capture or octet array cannot change the private artifact. Stop fences
further mediated disclosure without recalling bytes already handed to the host.
The dispatch handoff excludes original baseline bytes; it carries metadata and
the separately mediated payload, not an incidental disclosure of historical text.

## Evidence knowledge and lifetime

Authenticate and correlate task, origin, provider/resource and the full immutable
receipt capture before accepting a closed result/disposition/quiescence variant.
Validate payload schema, counters, token limits and attestation before conflict
classification. Malformed/unrelated input cannot poison an honest task.

Results retain independent application knowledge (unknown/not-written/written),
observed-byte lower bound, synchronization knowledge and optional post-write
version. Unknown progress can refine to written, and unknown synchronization or
version can acquire a fact. Observed bytes cannot decrease. Written requires the
full captured length; not-written requires zero observed bytes, no write token
and synchronization not requested. A partial-write fact cannot refine to known
nonapplication. A receipt without a post-write token still retains its write fact;
it does not provide a usable future version condition by implication.

Different known application, synchronization or version facts are contradictions,
not last-arrival replacements. Retain canonical accumulated knowledge plus two
bounded conflicting witnesses; a third distinct alternative returns evidence-full.
An exact retained alternative is idempotent. Any contradiction permanently faults
that destination in this owner and disables acknowledgment eligibility/future
dispatch. No reconciliation/clearing operation is invented. This capped store is
not an arbitrary-union bounded lattice or a whole-engine categorical-completeness
proof. Knowledge refinement and a finite closed vocabulary do not by themselves
prove native effect termination.

Written plus failed synchronization retains both facts and fails the ordinary
supported-synchronization guarantee. Result success does not establish safe
disposition or worker quiescence. Separately attested disposition states no future
effect remains; it does not erase possible prior application. Quiescence releases
an execution slot only. Same-key dispatch stays blocked until preceding dispatched
attempts have both known application and safe disposition, with no contradiction.
Even known written/not-written does not release that barrier alone. Disposition
plus unknown application also remains blocking. Stopped attempts continue receiving
attributable late results; receipts never edit/undo authored source or annotations.

Retirement requires a stopped never-dispatched task, or quiescence plus safely
resolved effect knowledge, and independent retention release/delivery drain. The
host must not assert retention release while a baseline/dependent consumer needs
the record. Origins are permanently spent for this owner's lifetime; they are not
recycled on retirement. Receipt intake performs no automatic retry or baseline
election; §16.5.1 supplies explicit current-root baseline publication/retention checks.

## Conditional arguments, tests and instrumentation

Under the declared current-root, host-policy, identity, provider and serialized-
transition premises, induction on reference transitions gives:

1. Every queued/dispatched task owns one actual exact-revision encoded artifact;
   no later source/settings mutation changes its bytes or provenance.
2. Only the first live queued entry of a resolved destination can launch; a prior
   unknown/unsafe/contested attempt remains a barrier. Different keys do not add
   each other's barrier. Safe disposition is a supplied fact, not inferred order.
3. Compatible result knowledge only adds facts or increases an observed-byte
   lower bound. Incompatible known facts remain visible and disable eligibility.
   Cancel, quiescence and receipt arrival never erase knowledge or author source.
4. Task, queued-per-key, outstanding, issued-origin, capture/envelope/witness,
   registry/root/tag and codec capacities remain within the admitted finite profile.
   The shared owner now reserves maximum capture, five evidence envelopes, bounded
   derivation and a codec artifact per task for the separately checked extension.
   Spent origin/fault metadata is separately bounded by issuance and capture limits;
   live held-byte accounting is not allocator/RSS or total process memory.

These are authored conditional arguments, not machine-checked unbounded induction.
source-save-checks.mjs executes 4,096 admission/4,096 dispatch/eight intake/128
recipient-mask cases, 25 controls and eighteen import-success/assertion-failing
semantic mutants. Fixtures create actual read-owned loaded roots and use the
actual source-codec, not fabricated serialized payloads. Tests exercise mixed
source/BOM, capture mutation, edits/settings after admission, destination keys,
FIFO, independent resources, rights, probes/capabilities, layered synchronization,
stop/late results, contradictions, unknown writes and bounded retention.

INS-04/07/08/13 observe capture/encoding, admission/refusal, queue/launch, external
attempt, attributed evidence, safe-disposition/unknown age and retained saturation;
INS-03 governs payload/status recipient release. Keep application, acknowledgment,
disposition and quiescence as separate outcomes. MELT/RED monitor rates/errors/
duration at those boundaries; USE addresses execution/queue/retention saturation.
Golden signals distinguish local queue latency from external attempt latency.
STRIDE challenges binding/condition/receipt substitution, false release and blocked
destination denial; LINDDUN covers activity/destination/token linkage. Use protected
correlation, bounded reason labels and declared units, never source, paths, keys or
tokens as telemetry labels. Actual collectors/timers/exporters and measured budgets
are not implemented by these trusted reference status/usage helpers.
