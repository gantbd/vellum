# Decoded literal replacement gateway

The private gateway connects existing F11 replace-current and replace-all requests
to original issued tickets, native literal-search evidence and common publication.
It preserves the four existing request fields: operation, index, replacement and
invocation. The original owned result remains a separate argument, as in the native
producer; no new public contract, wire encoding, profile, verb or query service is
selected.

## Native result and complete request meaning

Immutable declarations share the native replacement guard's actual field and
variant source. Typed and dynamic tuples capture complete request/context/limits.
Replace-current requires a nonnegative integral index; replace-all requires null.
Native preparation checks that a current index actually exists and that an all-set
is complete. A known partial occurrence may support current replacement but cannot
establish replace-all completeness.

Replacement strings remain literal scalar text, including empty text, controls,
prose, code and mixed-mode content. No normalization or replacement-template
evaluation is introduced. Zero matches do not erase the original literal intent.

Retain the actual result by identity without traversing unknown objects. A private
WeakMap records measured UTF-8 JSON reply bytes only after the actual native search
returns a frozen, bounded result. Copies, frozen lookalikes and unreturned objects
have no footprint. This is native producer-origin/size metadata, not a read grant,
query-context issuer, lifetime lease or physical-size measurement.

## Shared ownership and separate reservations

Reuse the existing canonical slot, preparation-busy marker, owner/domain/ticket
plan binding and common publication decision. One ticket cannot retain ordinary,
selection and replacement candidates simultaneously. Matching retries reuse the
same native plan before submission, while pending and after completion. Changed
request data or a fresh equal-query result cannot replace original meaning.
Legacy submit cannot borrow or rebuild that canonical candidate.

| Retained obligation | Logical bound and release |
|---|---|
| Complete canonical capture | Own measured serialized charge under remaining owner maxHeldBytes |
| Original returned reply frame | Separate actual native reply-byte charge under the same remaining ceiling |
| Native query/snapshot/derived plan | Existing complete native-intent and normalized job-envelope bounds; producer reservations remain required |

Check the sum of the first two charges before producer work; no additional numeric
default is selected. Capture-only headroom is insufficient. Producer refusal and
provisional faults refund both charges. Retained preparation and publication faults
keep both until protected retirement. Replay adds no charge. Retirement erases the
private replacement plan, releases both charges and tombstones eligibility without
refunding lifetime issuance. Caller-owned result retention and actual query-context
obligations are not discharged by retiring this invocation.

These bounds describe logical serialized data. Native allocation/aliasing, transient
copy peaks, complete cross-owner accounting, physical reclamation and actual
supplier reservations remain implementation/evidence gates.

## Authority and publication dependencies

Preparation and service require exact-true common/current source-read/source-write
and all-selected-match write facts. Query grant, scope, continuity, capacity,
retention and stop facts are checked again before native resolution. A result
reference does not authorize its use. Actual policy and uninterrupted-authority
truth remain separately supplied premises.

No frontend focus, keymap or origin-view write grant is required merely to submit
a source replacement. Native all-attached-view mapping, current versions and
companions remain mandatory where changed; there is no competing UI edit engine.

Preserve native source revision, annotation-set and view dependencies. A later
same-document comment-body change increments annotationSet and makes an already
prepared replacement refuse, preserving the current root; it is not silently
merged by refreshing preparation. A comment current before preparation retains
its authored body/version/target generation while placement maps through the
source change. Later source changes and changed query text/generation/scopes/
profile likewise refuse without re-search, retargeting or old-root restoration.

Use the actual companion-aware no-op decision: equal source bytes alone do not
establish identity. A valid zero-match no-op still checks assumptions but needs
no unused source/view version. Pending cancellation retains both charges and
cannot make a ticket fresh.

## Faults and conditional arguments

Provisional faults fence admission, preserve the root and refund unretained data.
Faults after private preparation is retained leave no delivered candidate but
retain protected cleanup. A publication fault pairs the old root with the existing
Unknown/faulted fact. No fault grants a new run or invents an external write,
acknowledgment, quiescence or query-retirement fact.

Conditional replay safety follows complete immutable meaning, actual result/plan
identity and the common single-run phase. The sum reservation preserves the owner
ceiling when existing owner/producer accounting is valid; exclusive slots and
protected once-only retirement prevent duplicate refunds. Native decisions retain
source/annotation/view/history contracts. Fixed two-form normalization and bounded
native matching/edit products add no unbounded retry or query loop. This is not a
whole-engine categorical closure, concurrent/crash proof or independent Cleanroom
certification.

limit boundaries. Twelve semantic mutations and two construction controls keep

24 complete capture/native-parent boundaries and twelve semantic mutations. Six

publication stages. Current-query/source/annotation staleness, current comment
preservation, mutual exclusion, exact owner headroom, zero matches and actual
equal-byte companion decisions are exercised.

F18/context/observer composition retains its ten controls/twelve mutations across
38 forms/twelve kinds: 608 gate cases, 304 context cases, 76 races and 9,842
traces/27,588 edges. Ordinary and selection gateway banks preserve their eleven
and ten mutation identities, and configured-line checks retain eleven. Similar

Post-import substrate checks intercept 143 filesystem/promise/process callables.
The 25-control baseline, including 24 capture boundaries, makes no intercepted
calls. Three hidden read/rename/process variants each record two exact attempts

arbitrary-code isolation and actual provider truth remain unproved.

## Instrumentation and remaining scope

INS-01 separates first preparation/admission, replay, refusal and the two capture
charges. INS-05 observes query evidence/currentness, not an implied new query task.
INS-02 observes the actual local decision and fault pair; INS-06 the linked source
history; INS-07 annotation mapping versus authored changes; INS-10 view companions;
INS-13 held result/capture bytes and protected discharge. INS-04 has no newly
introduced external effect, and INS-11 stays at native frontend input. Optional
capture/drain health continues through INS-12 without exporter work in publication.

Separate preparation, queue, execution and observation populations under MELT,
RED/USE and golden signals. STRIDE/LINDDUN cover result/scope substitution,
replay refresh, forged size/evidence, disclosure and exhaustion. Never use source,
replacement/query text, paths, raw identities, handles or tokens as ordinary metric
labels; counters do not establish policy, lifetime or delivery truth.

Full frozen verification is required. F05 context issuance and async lifetime,
actual host/policy/reservations, complete public/wire/result/event/multidocument
products, physical/global/concurrent/crash refinement and independent assurance
remain open. No whole C/D-row or overall goal is closed by these checks.
