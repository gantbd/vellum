# Explicit source batch facade binding

F11 exact-batch accepts explicit source intent, not private engine compound state.
The source-only profile is exact-source-batch/1 with
bounded-explicit-source-batch/1. Atomic authored source-plus-annotation composition
remains separately required under requirements §3.8/specification §13.9. Neither
sequential calls nor exposing a private execute-anything plan supplies that contract.

## Public request and private preparation

The exact fields are contract, operation, invocation, profile, sources, reads and
scopes. Operation is exact-batch. Each source has exactly document, expectedSource
and edits; each edit has lo, hi, expected and ins. The document is an exact authority/
id/incarnation. Ranges are half-open original-source UTF-8 byte offsets with complete
expected bytes and literal valid UTF-8 insertion bytes. No focus/view/selection is
inferred. Explicit reads and source scopes use the existing closed compound /5
predicate/scope vocabulary and current authority contracts. Unknown executable
versions/profiles, extra fields, arbitrary functions and malformed finite data refuse.

Typed and dynamic F11/version-1 tuples normalize through the same bounded native
guard. exactBatchInputForm supplies the field inventory for generic accepted-registry
description; actual descriptor/handler correspondence remains an installation premise.
No new fixed builtin discovery version, operation variant or wire codec is selected.

The gateway passes an inert shadow plan through existing shared normalization,
using null only as a private companion placeholder. This is not evidence or a
current annotation-set version. Repeated consistent documents, edit order, reads
and scopes normalize before public intent capture/comparison. The canonical public
record contains no annotation-set stamp and no authored annotation operations.

After current admission/source/write/scope grants and actual owner headroom pass,
reserve the complete canonical public capture. Resolve each actual live document,
validate exact source revision, scalar boundaries, expected bytes and insertion
bytes, then capture its engine-owned annotation-set version once. The immutable
private /5 plan has no authored annotation operations and binds its descriptor to
the original invocation. Only this owned plan can enter its reserved ticket.
Preparation is private: the caller receives the normal admission disposition, not
the private plan or companion versions. Source-write authority never grants F13
annotation authoring.

## Replay and common publication

Retain public intent and private capture under the existing canonical-preparation
ownership discipline. Matching retries return pending or observe-existing without
re-reading private companion versions, reallocating capture or retargeting source.
Changed expected bytes, payload, context, limits or semantic profile cannot replace
the original claim. Another facade or structurally equal legacy compound cannot
borrow the ticket. Losing an outcome does not make that ticket fresh.

Service rechecks strict current source/write/context grants and uses the shared
compound evaluator. Exact source/private annotation-set dependencies, declared
read predicates and write scopes remain conjunctive. All required view companions
are derived from the current service root, not restored from admission selections.
An explicit source proposal does not acquire an accidental focus or peer-selection
generation dependency. Aggregate view/history/parser/annotation and candidate-root
bounds still apply; inability to stage the whole candidate refuses publication.

One local decision installs actual source, automatic annotation placement, linked
history and current-view changes with the normal terminal facts. Five existing
local terminal pairs and current-recipient release apply, with effect none.
Publication projections remain the existing source/annotation/view interfaces;
complete cross-family event assembly remains separate work. No operation-specific
created-result reference is added, so this binding does not select U01 retrieval.

Stop prevents unperformed publication but retains captured responsibility. Failed
preparation refunds only provisional canonical charge. The existing per-slot native
intent reservation also bounds the complete private plan/envelope. Protected
terminal/issued retirement releases the retained pure compound data and canonical
charge once, without pretending it is a boundary-provider plan or refunding lifetime
issuance. These are normalized serialized-value units, not physical memory/GC proof.

## Arguments and focused evidence

Assume truthful current grants/reservations, finite inert normalized inputs and one
serialized non-reentrant authoritative coordinator. Closed field/byte/node/depth
checks precede retention. Shared grouping/order normalization preserves all complete
records and exact contexts. The public request is captured before any private stamp;
the retained plan fixes those stamps once. Equality of normalized public retries
therefore reuses one plan, while current final guards reject stale dependencies.
The inherited pending/running/done relation and common root/fact installation yield
at most one start and no partial source/history/companion publication in this scope.
Finite bounded traversals contain no callback, recursive dependency evaluation or
provider I/O. This does not prove whole-engine categorical/lattice completeness,
physical execution, scheduling fairness, crash behavior or independent certification.

Fourteen controls, seven omitted fields and sixteen service-permission cases cover
two-document actual publication, hidden companion-stamp invalidation, current peer
selection mapping, grouped/permuted retries, exact read/scope checks, unknown versions/
executable values, owner headroom, caller mutation, stop, protected retirement,
cross-ingress claim exclusion and spent no-op. Six coherent-graph mutations challenge
private dependency loss, changed-intent reuse, service-right bypass, omitted charge
headroom, wrong compound retirement and missing public canonicalization. Construction
failures do not count as semantic kills. Full frozen qualification/adoption remains.
