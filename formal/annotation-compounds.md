## Precedents and selected boundaries

[CodeMirror transactions](https://github.com/codemirror/state/blob/main/src/transaction.ts)
associate starting state, changes and selection/effects within one transaction.
Vellum retains explicit closed participants, not arbitrary effect callbacks inside
publication; CodeMirror transaction annotations are not authored comments.
[Neovim extmarks](https://neovim.io/doc/user/api/#nvim_buf_set_extmark()) distinguish
gravity, invalidation and undo restoration. These inform explicit mapping profiles,
not authored-body storage or permission. Vellum does not import automatic restoration
of a deleted comment target merely because source undo restores equal bytes.

Source history belongs to a document; authored history belongs to the logical
annotation record, including body and explicit target choices. Independent body/
target versions permit compatible current field edits but do not establish
independent selective-undo histories. Automatic source-driven placement mapping
does not add an authored annotation participant. A compound operation links its
actual source and authored participants in one group and one local publication.

## Owned targets and current publication

A new target may name the exact before-source context or the owned candidate
descriptor. Validate before targets against the starting root, then map their
placements through actual edits. Validate candidate targets against resulting
UTF-8 bytes after source staging; the descriptor binds the complete immutable
candidate, not a caller-guessed future live revision. At publication the authored
target receives actual source context. Candidate handles/descriptors never become
persisted grants or a second mutation interface. Document-wide, explicit-affinity
point and nonempty range targets are distinct; there is no UTF-8 interior clamping.

The user-approved snapshot schema in §29.4.1 requires explicit position/content
profiles in both authored and located points, separately from offset and affinity.
Its decode/stage preservation and subsequent native-capture evidence are separate
from this field-journal reference. Exercising both profiles here does not prove
native restoration or complete persistence; no profile may be silently discarded.

The source mapping preparation captures engine-owned annotation-set dependencies
because comments can appear or be reattached without changing source revision.
Those dependencies need not be disclosed to a source author. Current source and
explicit annotation rights are distinct from required internal mapping eligibility;
automatic mapping never grants the caller annotation-body visibility or authorship.
Missing required private companions refuses the complete operation under its
recipient-safe result, not a public list of hidden records.

Stage all source edits, required current placements, authored field changes and
history journals in an owned candidate. Validate versions, complete dependencies,
rights, bounds, stop state, interpretation and history/identity obligations, then
publish once or preserve current state. Body/target changes to the same annotation
use independent expected versions and one logical history scope. Duplicate changes
to the same authored field refuse in this product; sequential wishes must first
lower to one unambiguous final intent. Equal values alone do not establish complete
identity. A validated complete no-op needs no unused new publication counter.

## Reversal argument

Retain field-level before/after values and exact source forward/inverse transforms,
not whole historical document/annotation snapshots as replacement instructions.
Require the original group at every actual participant frontier, current rights,
matching incarnations and expected current authored content plus complete retained
reversal evidence. Equal bytes after later authored edits are not frontier eligibility.
Reverse all eligible participants atomically and move their frontiers without
creating an ordinary group that would undo itself. Changed versions are fresh.

Source reversal maps the currently live annotations through actual inverse edits.
It must not restore an old whole annotation row: later bodies and explicit target
choices survive unless they are eligible authored participants of that group.
Detached targets remain detached in the conservative source-only profile; equal
restored text is not causal identity or reattachment evidence. Explicit target
reversal additionally requires actual retained target/source mapping evidence.
Missing evidence refuses; it does not relabel historical coordinates as current.

New authored work invalidates complete linked redo groups and their dependent
continuations across all scopes, not just the invoking document's stack. The finite
closure iteration only adds members from retained redo entries, so its remaining-
groups rank decreases until fixed point. Bounded profile validation must bound the
real registry, mapping, journal and closure work before admission. Neither this
argument nor a finite action reference proves host memory accounting, general
inverse correctness, all replay/lifecycle behavior or global service progress.

## Executable evidence and limits

annotation-compounds.mjs composes actual canonical edit validation/emission and
sequential inverse generation from text-oracles.mjs, content/position mapping from
mapping-profiles.mjs and authored field changes from annotation-records.mjs. It
checks 128 gate combinations, eight before/candidate target cases including their
undo/redo paths, two body/target order cases and 29 controls. Controls cover whole-
group blocking even after equal-content edits, current-field preservation, stale
private set/source/body evidence, cross-authority rejection, no-op frames, complete
linked redo retirement, multi-document source/comment publication and unrelated
history preservation. All initial gate scenarios check request/state/check frames.

Eight in-memory mutants must import successfully then fail assertions: missing
annotation-set dependency, conflating body/source history, ignoring content
version, ignoring participant frontiers, rolling versions backward, restoring
old bodies on source undo, ignoring the candidate descriptor and clearing only
one linked redo stack. The equal-content frontier scenario prevents relying only
on incidental byte mismatches. These are same-author sensitivity tests, not
independent Cleanroom certification or new solver theorems.

The reference uses representative normalized records/bytes, safe integer versions,
one live record plus a second source document, and trusted conjunctive policy,
companion, capacity, interpretation and target-restoration facts. Authored target
restoration is restricted to unchanged source or a supported same-group source
reversal with supplied valid evidence; general retained mapping-history restoration
is not proved. This older field/source checker does not implement record create/delete reversal, identity
reservations, retirement/pins, public codecs, all invocation replay, current reply
projection, physical allocation charges or a concurrent engine. History/frontier
registry integrity is a premise. General selections/other required companions
remain mandatory but are supplied by the complete eligibility premise here.

Section 6.4.1 now adds actual equal-byte mapping publication in this evaluator;
see equal-byte-companions.md. Automatic placement changes preserve source revision,
authored field versions and authored undo/redo entries. Actual body/target/text
participants still use their own history scopes; other profiles remain gates.
Target shapes here are logical products,
not the older point-only F13 reference retroactively proving every target decoder.
The source format remains lossless and current release/save boundaries are unchanged.
