# Combined context search ownership evidence

The synchronous engine-owned F05 service accepts current native source-only and
combined source/annotation contexts. Both may coexist under one owner. Original
context identity resolves a fixed first-party issuer case; caller labels and
callbacks cannot select another owner. The opening pool is bootstrap metadata,
not a later authority requirement or service mode.

## Authority and dependency

Combined source bytes retain their original profile and cut. Searching those bytes
requires current authority for both admitted classes and the captured annotation
facet domain. Source permission alone cannot revive a combined context; an
annotation-only context cannot become a source query. The six current-query facts
remain separate exact-true gates. Host identity/policy truth, complete notification
and synchronous non-reentrancy remain explicit premises.

Each managed result stores its original issuer and lease. Release and protected
retirement resolve that original pair. Stop or loss for a combined context does
not affect an unrelated source-only result. A retired bootstrap pool cannot fence
a result owned by another still-current issuer.

F11 replacement and F12 match selection validate managed ownership before first
preparation and again at invocation service. Preparation retains bounded argument
and reply obligations but does not create an independent context lease. Lost
authority rejects new preparation or settles queued work as notApplied without
changing the root. Unmanaged reference producers retain their narrower contracts.

## Resource ownership and cleanup

The combined context profile adds a finite maxHolds. Each hold reserves opaque
lease and record bytes and spends the same nonrefunding issuance budget used by
contexts and annotation selectors. The installed pool's selector/hold term is:

    (2*maxSelectors + maxHolds)*(maxSelectorBytes + maxSelectorRecordBytes)

The two selector frames cover live and staged registry candidates. Hold records
refer to the already retained context rather than copying its source. Opening
compares the complete declared envelope with local and actual parent headroom.
These units do not establish physical or global allocation bounds.

Reserve a hold before evaluation. An unpublished refusal discharges the hold, not
spent issuance. A published result keeps its hold until protected retirement.
Context stop does not discharge a result; a held stopped context cannot retire.
Exact-true owner control, released retention and drained delivery permit once-only
cleanup after actual disposal or owner fault without renewed content grants.
Retiring the preparation pool leaves installed context/search obligations intact.
Pool discharge restores only that pool's declared reservation, preserving other
owner obligations and the authored root.
