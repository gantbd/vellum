# Public mixed source and annotation authoring binding

Specification §6.5.2.5 binds an explicit atomic-source-annotation/1 proposal to the
existing F11 typed/dynamic exact-batch route. It composes all four existing F13
operations with source edits and §13.9.6's retained receipts through one actual
invocation coordinator. The source-only profile remains distinct and closed.

## Public intent and original native components

The normalizer owns only bounded ordinary data. It reuses the existing F11 source/
context/route checks and rejects unknown fields/profiles/operations, callbacks,
accessors and malformed target/dependency/identity/version forms. It is not a proof
against arbitrary proxies/native code. The mixed contract governs its component
data; it does not overload standalone annotation-authoring/1's LiveSourceTarget.

Canonical public capture retains original component order and the full normalized
source/read/scope intent. Private source companion stamps are captured once. Each
annotation lowers to an existing native F13 request on the actual before root or
the proposal's privately staged source candidate. Its owned native capsule retains
owner, recipient/profile, limits, required dependencies and create allocation.
Before/candidate targets preserve explicit position/content point profiles. A
candidate on a document without source writes still retains its original native
source context, rather than becoming an implicit future-current target.

The host supplies separate current component bindings and native authorization/
allocation facts. They cannot enter through caller JSON. At service, exact original
component identity and the native capsule's owner/currentness are rechecked. F11
source permission does not stand in for annotationWritable or membership authority;
annotation-only work does not require source mutation permission. Actual supplier
truth and identity issuance remain explicit premises.

## Staging and resource ownership

The actual invocation parent first debits 3C + 2M + 2R declared serialized bytes,
for public capture C, maxIntentBytes M and maxRootBytes R. Complete bundle metadata
must fit M. The additional §13.9.6 receipt hold is charged to remaining parent
headroom; neither stage creates a new independent capacity pool. Provisional refusal
refunds only provisional units. These bounds cover declared logical frames, not
RSS, allocation overhead, hostile-object evaluation or measured copy peaks.

The source candidate is private preparation data, never an intermediate engine
publication. Final service repeats original component checks against the actual
current root and recomputes complete source/annotation/current-view/history effects.
It checks the final candidate against every component's root/document/record bounds
before the shared publication/terminal-fact/receipt assignment. Duplicate same-field
or membership identity conflicts cannot become a sequential script. Body/target
independence and compatible automatic mapping are retained.

Known rejection preserves the complete current root. Unexpected native/protocol
failure records Unknown/faulted and retains the original responsibility. Matching
retries cannot refresh private stamps, replace a native allocation or widen receipt
ceilings. Retention/drain result forgetting and protected owner-controlled retirement
remain separate from stop, source publication and supplier identity disposition.

## Conditional preservation and halting arguments

Assume truthful current host/policy/allocation facts, normalized finite roots and
correct existing source, F13, history, view and receipt helpers, under serialized
non-reentrant trusted execution. First preparation establishes complete public intent,
private dependencies, native component correspondence and actual parent funding.
Current validation preserves that correspondence; source candidate construction
does not mutate the authoritative root. The final compound and outer/component
limit checks precede the shared trusted installation. Therefore eligible source
and authored annotation components install coherently, with their original receipts,
or none of their effects install. The existing once-only invocation transition and
unchanged original capture prevent retry from creating a second execution.

Native component checks use independent field versions; a body-only component can
remain eligible after compatible source/placement changes. A target-bearing capsule
retains its original source meaning and cannot silently migrate to a newer source.
Final limits apply to the whole candidate, not merely each independently prepared
component. These are reference composition arguments, not solver proofs of all
engine states or assertions of production/crash atomicity.

The closed source/read/target/annotation vocabulary and bounded vector traversals
give conditional per-call halting or fault. They do not establish categorical
completeness, a whole-engine bounded lattice, provider halting or scheduler fairness.
