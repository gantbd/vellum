# Discovery query owner integration

The existing F01 discovery owner dispatches bounded typed/dynamic list, inspect
and advisory-enablement arguments to its existing native query. Original owner,
context, entry, cursor, variant, target and prepared-cut roles are preserved.
This adds no operation, public acquisition, transport, execution mode, UI policy
or substrate procedure.

## Local ownership and fixed capture

Resolve a healthy nonbusy owner before inspecting the limit profile. Reserve
the finite classification frame against its actual current declared headroom.
Then reserve seven complete request-byte frames: envelope, authority context,
canonical capture, limits, descriptor, current facts and native producer request.
Check arithmetic and headroom before incrementing the charge. These are local
logical reservations, not invocation-domain/global admission or physical sizes.
The construction follows the existing F04 owner gateway pattern.

Normalize the existing three forms and bind the copied recipient context to the
original live native context before using current-loss facts. The prepared cut
remains an opaque native port, not canonical JSON. Native current root, profile,
origin, disclosure, cursor, target/advice, selector and reply limits still apply.
Unknown aliases/profiles are not repaired. A foreign context cannot lend loss
to another context; a bound request with an unknown entry still observes actual
native whole-context loss before entry lookup.

Capture only the fifteen actual query facts under independent byte/node/depth
ceilings. Read each named own data descriptor once, without enumerating unrelated
host bookkeeping. Missing/undefined facts remain unknown; false is not erased
and unknown values do not become grants. Recognized accessors refuse without
execution. Unrelated opaque values, including a WeakMap, are not cloned or
traversed. Verifier-owned proxy probes count descriptor reads; they do not prove
arbitrary hostile proxy isolation.

## Closed execution and protected completion

The bounded path has fixed phases: idle, classification borrow, full workspace
borrow, captured arguments/facts, native query, and completion. Every admitted
return or caught exception passes the finalizer, which refunds exactly the
temporary tally and clears the borrow. Reentry into query, descriptor work,
preparation, acquisition or borrowed-object discharge refuses during that path.
No callback, provider procedure or await is part of normal execution.

Unexpected exceptions latch the discovery owner's fault fence, not the editing
domain's fault flag. Original contexts, selectors, base reservation and spent
issuance remain accounted for. After the finalizer, original handles retain
protected stop/retirement and registry discharge. The old domain/owner identity
does not reopen with refunded issuance. Restart/recovery remains a separate
supported-lifetime obligation.

A late native query fault can follow selector installation. That installation
and its spent issuance remain; refusal is not rollback. The native core now invokes
the existing structural result checker before publishing tentative selectors and
issuance. It uses the already reserved native reply/selector staging, not the
decoder's input-sized workspace. Invalid results or validator exceptions fence
only this owner, with original maps/issuance and consumed-cut history retained.
Both native and decoded routes use the same guard. Native selector authority is
still separate from structural validity.

Conditional termination follows the fixed dispatch sum, bounded data copier,
finite named fact reads and bounded native query under the serialized inert-port
premises. This does not prove whole-engine categorical completeness, a general
bounded lattice, abrupt-exit recovery or physical/global resource accounting.

## Instrumentation and evidence

IF-01/02 and PATH-02 retain facade/native query boundaries. Existing
INS-01/03/05/08/12/13 distinguish classification, reservation, argument/fact
capture, native query, refusal, local fault and protected refund. MELT/golden/RED
cover stage populations, latency and dispositions; USE covers the actual owner's
temporary occupancy, saturation, busy state and retained native pressure.
Compare reserved/refunded/remaining amounts without treating unavailable as
proof of discharge.

STRIDE/LINDDUN/privacy/hazard cases include owner/role substitution, recipient
confusion, truthiness grants, reentry, capacity inference, fault linkage and
premature cleanup. Do not record raw handles, identities, facts, descriptor bodies
or authored content as ordinary labels. No telemetry backend, threshold or
measured service objective is selected.

Eleven controls cover sixty native route/profile results, eighty refusals,
fifteen exact classification/workspace/fact boundaries, eight absorbing losses
and two opaque-bookkeeping probes. Thirty pre-query faults and six late faults
check the original root/parent, local fault latch and exact temporary refund.
Four late cases install fresh selectors; sixty reentry attempts refuse.
Thirty-two semantic mutations run complete product/fault corpora against unchanged
copied-graph baselines. Construction, timeout and tool failures are not detections.

Selected post-import execution preconstructs 140 baseline and eighteen fault
fixtures. With 143 filesystem/process callables intercepted, the complete baseline
corpus attempts none. Three injected call types across six route/operation cases
each retain local fault fencing, temporary refund and original-handle cleanup.
Fixture/import I/O, all-host isolation and general fault containment are not proved.

The selected static engine/reference graph is 115 modules. Frontend exclusion and
clean/ordered initialization remain obligations; components/interfaces and the
76/11 partition do not change. Existing native/discovery/argument/result regression
banks remain separate full-suite obligations.

Full fresh frozen qualification and endpoint reconciliation remain adoption gates.
Restart, actual global/physical/
host/measurement truth, other public products/events and independent assurance
remain open.

The precommit guard has 27 scoped cases across three native forms and native/
typed/dynamic routes, including 18 fresh-selector stages. Invalid status,
wrong context and validator exceptions preserve original maps/issuance and
editing-domain health while fencing this owner and retaining protected discharge.
Three semantic mutations bypass validation, suppress its fault fence or publish
selectors too early; each fails an assertion after the unchanged baseline passes.
