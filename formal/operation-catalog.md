effective contexts, enabled analysis/geometry and advisory validation. Local
commands cover source/selection/annotation/history/view/context/lifecycle/control/
observation state. Effect requests cover resource reads/writes, clipboard, enabled
analysis/geometry work and explicitly advertised host facilities. Observations
separate historical provider evidence from contextual derived results.

All eleven current requirements §3.3 engine facade bullets and the separately
owned optional-presentation paragraph have inventory links, together with owning
contract sections and existing INS placements. A bullet can need several families,
and a family can contribute to several bullets. This is selected category alignment
and manually reviewed scope, not a proof that every v1 requirement, variant or
outcome has been enumerated. Concrete descriptor fields/units/limits, global
coverage and complete malformed/late/concurrent relations remain specification gates.
Sink labels name logical responsibilities under the one local authority, not new
engines, services or independent publication implementations. Actual authored
participants still use the common atomic coordinator contract, including a
history reversal whose only participant is authored annotation content.

Source edits still require the full participant/dependency/publication contract;
family calls do not create transactions by sequence. Queries can compute bounded
pure results/caches, but do not secretly call providers. Needed host work is explicit;
pending results do not imply a new asynchronous editing mode. Effects may execute
synchronously or on a supplied executor. Notifications cannot directly mutate.
Optional analysis/geometry and conditional host facilities add no deferred feature
or runtime/network dependency. Required reference integrations remain release gates.

## Conditional routing arguments

A validated descriptor has exactly one category and an allowed owner/sink for it.
Dispatch uses that descriptor, not a caller's proposed category. Unknown names,
variants, versions or invalid envelopes have no route. Query routing has only the
read/no-route alternatives in the reference. Real handler purity still requires
ownership/API review, tests and implementation refinement; a metadata field cannot
prevent arbitrary native code from mutating state.

If typed and dynamic decoding yield the same canonical semantic request and
accepted context, one deterministic routing relation gives the same disposition.
The local congruence law is conditional on that equality. Actual Rust adapters,
full payload decoding/equality and interruption/concurrency behavior are unproved.
Advisory discovery/validation supplies no continuing grant; actual admission checks
current authority, dependencies and capacity again.

Historical effect evidence has a different gate from new-work commands. Supplied
schema-valid, authentic attributable facts use protected evidence ownership even
when ordinary capacity, current enablement, source context or observer grant has
changed. Disclosure remains a separate current-release decision. Protected intake
exhaustion requires retained responsibility, not silent discard. The reference's
retention-required route is an obligation on a real host/owner, not an implemented
fallback store or proof that no message can be lost. Captured contract lookup and
old-version retention are also unproved; only one private version is exercised.

Protected control uses an explicit descriptor/variant whitelist: cancellation,
shutdown, observation stop/revocation, downstream task cancellation and bounded
reserved minimal status. After current target/retained-contract, authority, schema
and capability validation, these routes use protected rather than ordinary capacity;
new-work enablement does not invalidate an admitted obligation's control contract.
New streams/grants and detailed/unbounded status cannot acquire this lane by name.
Protected exhaustion retains responsible-host control obligations or reports
unavailable minimal status; no actual reservation/retention implementation is proved.

Pure derived results require valid provenance plus current context/rights and
declared capacity. Rejecting a stale result does not establish worker quiescence,
physical reclamation or safe discharge. Neither evidence nor a derived result
directly enters source authoring or creates authority from its payload.

## Executable and symbolic evidence

`operation-catalog.mjs` validates all 28 rows, distinct names, category/sink pairs,
required/conditional markers, nonempty bounded-design lists and exact owning
section/observation/selected-facade references. This is structural validation,
not runtime resource-bound enforcement or semantic adequacy.

For all 87 declared variants it compares two private decoders: typed ordinal versus
dynamic semantic label. Each canonical pair is routed across 512 contexts varying
nine Boolean facts: enablement, current authority, schema validity, current context,
ordinary/protected capacity, trusted provenance, attribution and release permission.
All 44,544 cases compare exact internal route/disposition, check adapter agreement
and frame inputs. An independently spelled decision table uses stable artifact
identity rather than category dispatch, including accepted cases and refusal cases.
These selected Boolean facts stand in for suppliers, not actual policy evaluation,
cryptography, payload validation, retained snapshots, provider state or handlers.

Twenty-eight controls cover missing/duplicate/malformed descriptors, query mutation
and wrong observation lanes, unknown verb/variant/version, caller reclassification,
discovery versus current grants, historical evidence versus observer revocation,
forged facts, protected-capacity retention and stale derived results. They also
check each protected variant under ordinary saturation/disabled new work, current
target validation, downstream cancellation and refusal to promote new streams.
Controls are selected probes, not full mutation adequacy or independent Cleanroom
expectations.

`operation-catalog.smt2` has seven positive local laws (SAT premises followed by UNSAT
negated conclusion) and three SAT controls: query read-only routing, unknown refusal,
canonical congruence, observer/evidence separation, protected retention, derived
freshness and protected-control independence from ordinary capacity. Controls
exhibit wrong query routing, discovery without current grant
and valid historical facts without live-source/observer grants. The encoding uses
trusted Z3; no independent proof-certificate replay or automatic code refinement.
Routing choices do not prove actual publication, effect launch/completion, no-op
classification, historical lookup or every event/state combination's totality.

## Instrumentation and remaining closure

Specification §22.1.2 and [source-edit-contracts.md](source-edit-contracts.md)
now refine F02 bounded-range and F11 exact-batch at their source/context boundary.
This adds mandatory semantic field/result obligations and private byte-level
cases, not public IDs, full variant schemas or handler refinement.

IF-01/INS-01 retain request resolution/discovery/admission, IF-03/INS-02 actual
coherent publication, IF-02/08 with INS-03 current release and IF-04/05/13 with
INS-04/05 actual work/evidence boundaries. INS-06–13 retain history, persistence,
lifecycle, activation, geometry/native, diagnostics and shutdown distinctions.
Count routed requests separately from actual commits, provider dispatches,
acknowledgments, accepted derived results and recipient handoffs. A routed plan is
not success. Queues, service/pending age, useful outcomes, retention and loss retain
their declared units and bounded classes; raw names/arguments/paths/identities
must not become unbounded or private metric labels.

STRIDE covers descriptor/variant spoofing, schema tampering, privilege confusion,
stale discovery, forged evidence, cross-category dispatch and bounded-work floods.
LINDDUN covers registry existence, private enabledness/reasons, arguments, targets
and correlations. Discovery and outcome projection follow D05/D09–D12/D42; this
fixture does not prove complete metadata privacy or side-channel noninterference.
No new service, scripting runtime, callback execution or policy engine is selected.

Remaining D33 work is the actual public identifiers, per-variant bounded schemas,
admissible outcomes/events, full operation coverage, handler totality/rank/resource
arguments and typed/dynamic implementation refinement. D34/D43/D44 also own concrete
setting/type/package/version choices. Existing models and this routing evidence
remain separately scoped; a family inventory is not a proof of whole-engine closure.

[Neovim's typed API metadata](https://neovim.io/doc/user/api/#api-metadata)
provides mechanism precedent for shared typed/discoverable contracts. Vellum's
four-category boundary and stricter explicit-target/evidence rules are its own
choices; no transport or equivalent implementation guarantee is imported.
