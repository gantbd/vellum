# Native compound advisory validation

Current integration: §5.2 adds explicitly scoped compound `/3`, retaining the
exact earlier profiles and shared read/advisory/publication rules. Scope is an
original-coordinate caller restriction, not a grant or another owner. See
[source-scopes.md](source-scopes.md); earlier counts/exclusions retain their own
slice scope. Current solver totals are 262 conditions/fourteen manifests.

Specification §5.1 adds a bounded F10 query over the native owner's current root.
It shares candidate rules with source/annotation publication without publishing
the candidate, issuing an invocation or creating committed journal receipts.
The result describes current checks, not a later command's permission or success.

## Scope and precedent

`proposal-validation.json` defines the private request, reply and host-basis
products. The current profile accepts compound `/1` and explicit-read `/2`, not
every native job or arbitrary user validator. Both routes use the actual catalog
F10 entry and existing local owner; there is no second engine, queue or transport.

[Roslyn's workspace model](https://learn.microsoft.com/en-us/dotnet/csharp/roslyn-sdk/work-with-workspace)
separates analysis of immutable solutions from explicitly applying changes to a
workspace. Vellum adopts that separation at its domain-neutral candidate boundary,
not Roslyn's compiler model or equivalent security/atomicity guarantees. The
[read conflict-set precedent](https://apple.github.io/foundationdb/developer-guide.html#conflict-ranges)
supports final dependency revalidation; it does not make prior advice a commit.

## Execution and data ownership

`queryProposalValidation` validates the route envelope and actual F10 variant.
`validateInvocationProposal` obtains the actual root/context/limits and checks
strict current query gates. The host's exact basis binds root identity, complete
context and request. `proposalReadable` and `validationObservable` cover every
influencing predicate, including private companion/capacity facts; their truth is
not inferred from request possession or caller-provided labels.

The compound publisher and query use `decideAnnotationPlan`; both use the same
view preparation, validation and completion decision rules. Publication alone adds
source-journal preparation/commit and view journal carry. Advisory evaluation
selects `decideForwardViews`, which performs no carry. Candidate version/history
values are isolated computed data, not live allocation or a published branch.
The query returns only a fresh advice object with profile and Boolean predicate,
never the candidate root or a reusable execution selector.

Current input/root/result and view/membership/read-dependency limits apply. There
is no invocation-slot charge, command reservation, start, event, terminal result
or external launch to refund or retire. Repeated calls repeat bounded derived
work; they do not accumulate query handles or reset invocation issuance.
Temporary cloning and owned view-preparation metadata still require production
resource accounting; the reference does not establish allocator or latency bounds.

## Conditional arguments

The synchronous query calls no host callback and uses finite inert native products.
Plan loops, source edits, record searches and view batches are finite. Linked-redo
invalidation grows a set over finite retained group references: every continuing
iteration adds a previously absent reference, so the fixed-point loop terminates.
This is a closed-profile termination argument, not a proof about hostile JavaScript
accessors, arbitrary extensions or real scheduling.

The query never assigns the owner's root or touches a ticket. Its candidate
decision clones authored state; its selected view completion does not prepare,
commit or carry a source journal. By composition, successful or rejected advice
frames current source, annotations, versions, history, views, invocation usage and
committed receipts. Derived view-preparation ownership is temporary, not authority.
Unexpected private failure is separate from ordinary advice/refusal: it sets the
existing owner's fault fence without publishing authored state or starting work.
Protected supervision retains responsibility for already admitted tickets.

Both command and query evaluate the same candidate predicate. Successful advice
requires applied-or-unchanged candidate status, the owner's root byte ceiling and
any actual baseline promise floor; reply capacity is separately required. This
does not include execution-ticket binding, scheduling, terminal bookkeeping or
future reservation acquisition. A later edit with changed dependencies or denied
authority still rejects under normal publication rules. Unexpected private failure
fences the native owner and returns no verdict rather than proving the proposal
invalid or permitting repeated execution on a known faulty owner.

No Boolean result is released unless complete current query gates and the exact
basis match. This checks binding and strictness, not actual host policy truth,
all-world resource/timing privacy or whether every influence was made observable.

## Executable evidence

The checker enumerates 2,048 query-gate cases and 128 actual routing cases across
both routes. Fourteen authoring variants, at capture/undo/redo, yield 42 native
states and 84 read-only queries. Twelve controls cover current read predicates,
exact host basis/context, request products, typed/dynamic family isolation, stale
or denied later publication, no-op/refusal/expected-byte cases, capacity, unexpected
failure and repeat-query accounting. Body, target, create and delete advice is
also compared with actual subsequent compound publication on managed native roots.

A coherent four-module baseline precedes thirteen negative mutations. Spies around
the actual parser-journal module detect preparation/commit/carry through a query;
the positive command path must still issue its real receipt. Other mutations
remove gates/context/basis/capacity, install the candidate root, force success,
fabricate a negative verdict after failure, omit the fault fence, or accept another
command family.
Only semantic assertion failures count as kills, not syntax/import/runtime errors.
Mutation runs use a selected short matrix and native subset; the full positive
checker retains all reported gate/routing/native cases. Existing compound, native
invocation and parser-source mutation suites remain separate regression evidence.

These checks and authored arguments add no new SMT condition. The existing 252
conditions/fourteen manifests retain their original scope. Full frozen-input
verification is required for this batch.

## Instrumentation and residuals

INS-01 observes route/admission and bounded proposal work; INS-03 observes current
query release/refusal. INS-02 distinguishes candidate validation work from actual
publication: advice must not increment commit/edit/terminal-outcome counts.
MELT/RED/golden measures separate query rate, duration, refusal and faults from
command success; USE covers temporary candidate/view/membership work and retained
capacity pressure. Existing interfaces and pathways carry these observations;
no new network path, exporter or privileged diagnostic lane is introduced.

STRIDE/LINDDUN address forged basis/context, private predicate or capacity leakage,
replay as permission, false-negative laundering and query floods. Do not label
ordinary telemetry with raw plans, object/version identities, bodies, grant facts
or hidden refusal causes. Current release controls still govern richer diagnostics.

Remaining gates include other native job validation profiles, provider/schema
evidence, complete dependency discovery, required proof/companion activation,
public wire/Rust products and explanations, actual host policy/visibility,
temporary/global/physical accounting, production concurrency/crash refinement and
independent assurance. No whole F10, decision row or all-sections goal closes.
