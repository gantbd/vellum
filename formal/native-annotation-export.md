# Native explicit annotation export routing

Specification §16.3.5 connects annotation-export/1 to actual native destination
admission and release. The semantic sources are annotation-write.md and its
closed request/receipt catalog, annotation-artifact.md, annotation-capture-preparation.md,
ordinary-bindings.md and the existing native destination certificates. This adds
no public operation, execution job, filesystem procedure, transport, component,
resource default or solver condition.

## Admission and capability separation

The trusted native coordinator accepts the existing annotation-export request,
capture context, host association/source-evidence binding and capture profile in
an exact private wrapper. Its outer lifecycle/membership/bindings profile remains
the existing native profile. No caller-supplied candidate root, bytes or callback
is accepted. The current healthy native root, existing closed request, actual
owner, full target registration, current source/annotation/binding generations,
destination grant and shared writer limits determine the candidate reservation.

Twenty-seven strict current facts are the nineteen existing annotation launch
facts plus eight additional capture/owner/current-pair facts. Historical source
attestation is an additional conditional fact only when the actual capture needs
older source evidence. The complete current pair/identity basis is checked at
commit and dispatch. Pair identity is separate from source-write registration:
export does not activate an ordinary binding or require a source-write capability.
The read-only-source witness has no matching source write registration and denies
sourceReadable while actual native annotation export still succeeds.

This does not permit arbitrary disclosure. Annotation readability, complete
disclosure, exact capture context, current alias/source evidence, destination
context and write authority retain their existing obligations. The source bytes
used internally to validate annotation targets are not delivered as a source
payload. A source-payload request for an annotation task refuses. Ordinary source
and annotation binding activation still requires their stronger owning contracts.

## Shared preparation and local commit

The source codec prepares the actual native annotation snapshot using the existing
capture implementation and its owned preparation store. The private adapter seals
the actual codec/owner/store/slot/record/domain/root references and an immutable
copy of the prepared payload. It introduces neither a second serializer nor a
parallel artifact budget. Pending source and annotation preparations continue to
reserve the shared codec's artifact and lifetime-issuance capacity.

The destination certificate binds the actual domain/before-root pointer, writer,
profile, request/capture/receipt/basis and preparation. The final validator checks
current facts, association/identity basis, conditional historical evidence, exact
reservation-only delta, actual writer capacity and origin uniqueness, actual
codec ownership/preparation/bytes/basis, profile limits, native root limits and
existing annotation baseline promises. A foreign codec preparation from the same
domain cannot substitute for the writer's own preparation.

One serialized synchronous commit installs the typed annotation artifact, writer
ticket, spent origin and native destination reservation. It converts the existing
preparation charge to the retained payload charge, consumes the preparation and
advances publication once. No await or provider callback intervenes. Refusal
discards the preparation and refunds its hold without issuing work or spending
an origin. preparationReserved remains a truthful host resource premise; this
logical accounting does not prove allocator/RSS/stack or peak physical costs.

The root delta changes only the affected resource-owner reservation and publication.
All authored source/annotation state, ordinary bindings, baselines, histories,
relationships and identities survive. Existing source-publication journal receipts
are carried without issuing replacements. The journal witnesses require a nonempty
journal at the tested persistence boundary; they do not treat it as an archive of
every prior transform.

## Dispatch, release and retirement

The ticket joins the actual existing source/annotation writer FIFO, destination
effect barrier, codec quotas, receipt store and lifetime origin set. Dispatch uses
the actual healthy root, exact current target registration/source binding and
reservation, current pair identity, strict destination/probe facts and the original
pinned condition. An absent target needs attested exclusive creation; stronger
requests cannot silently downgrade. Later local source/body/target changes do not
recapture or relabel the immutable artifact.

Provider handoff and retained byte reads use the original annotation basis. Each
read separately checks current annotation disclosure, provider/resource, context
and bounds. Native source-root copies cannot redirect dispatch or retirement;
the normalized supplied-root release helper cannot mutate a native ticket's flag.
Valid late facts remain attributable after stop or owner fault, but faulted native
owners refuse new work, dispatch and reservation publication.

The existing private release control removes only this task's reservation under
the actual before-root and a rechecked actual ticket. Queued cancellation or known
uncontested application plus safe effect disposition permits release; quiescence
alone is insufficient. Releasing the last export origin preserves an active
ordinary source or annotation owner. The marker changes only with successful
native publication; an already released task is unchanged without allocating a
counter. Capacity/counter refusal retains both reservation and marker, not a false
release. This is no promise that every future release has reserved counter space.

Retirement separately requires quiescence/effect resolution, reservation release,
actual-root consumer checks, retention release and delivery drain. An export to
an ordinary annotation association can remain pinned by baseline/history consumers;
release is not evidence that every producer obligation ended. Eligible retirement
removes the actual codec artifact/task without recycling origin issuance.

Export does not become SaveAs, activate an ordinary annotation binding or install
a baseline. Separate authorized baseline/claim contracts retain their existing
conditions. The external write and later local reservation release are not one
crash-atomic transaction; no implicit retry, force overwrite or recovery is added.

## Conditional preservation and termination arguments

Assume the existing native capture, codec, request/receipt, writer, pair and
root-owner contracts; bounded normalized plain objects; serialized trusted
composition without reentrant host callbacks; and truthful current host grants,
aliases, identity, coverage, source evidence, preparation and discharge facts.

1. Refusal preserves the native root, writer tasks/spent origins and issued codec
   artifacts. The sole preparation hold is either discarded or converted to one
   actual payload charge at the single commit. Final current-origin/capacity checks
   prevent duplicate issuance or admission using capacity stolen since preparation.
2. Exact domain/before-root, codec-owner/preparation and basis checks bind the
   artifact to this actual native capture. Closed delta reconstruction permits
   only reservation/publication changes. Therefore commit cannot reinterpret
   another artifact kind or alter authored content, ordinary ownership or baselines.
3. Native dispatch imports the existing shared FIFO/effect and exact receipt
   rules. Unknown/conflicting evidence remains a barrier; stop, disposition,
   quiescence and acknowledgment do not substitute for one another. Release and
   retirement preserve the corresponding independent obligations and lifetime IDs.
4. These private facets add only closed preparation/admission/release cases to
   the existing bounded vocabulary. Each call completes via bounded schema checks,
   copies and scans over existing profiles. Discard/commit consumes its certificate.
   This is not a theorem that an external provider, repeated workflow or whole
   editor halts. Capped contradiction witnesses do not establish arbitrary-union
   bounded-lattice or categorical completeness.

These are authored conditional construction/trace arguments, not proof-assistant
induction, complete temporal-module refinement or independent Cleanroom assurance.
