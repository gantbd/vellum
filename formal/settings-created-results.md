# Created layer result references

Specification §22.3.1.10 composes the existing common publication and historical
result-release contracts with §22.3.1.5's fresh conditional write basis. It makes
native layer creation usable without releasing allocator epochs or treating a
returned reference as authority. The fixed optional first-party port adds no job
kind, editing mode, filesystem procedure or selected public wire encoding.

## Publication and resource ownership

One genuine issued ticket/plan/context can prepare one nonreopening result hold.
Its complete private context/profile/invocation/creation capture and worst qualified
result frame each fit actual maxResultBytes. Their reference JSON bytes plus the
existing native maxStateBytes staging envelope charge the parent's remaining held
capacity. Durable result data holds no source/root snapshot; stages share the
common before/candidate roots for one synchronous service turn. These are declared
logical charges, not physical allocation or measured performance claims.

Actual admission captures the reference-disclosure ceiling. Service stages the
actual native creation result; final commit validates its owner, ticket, context,
candidate and current native decision before ordinary terminal bookkeeping.
Reentrant result readers see unavailable while the owner is publishing. Exception
paths discard staged/private reference registration and retain unknown/faulted
outcomes and protected cleanup. Forget/retire deletes mappings and releases the
hold once without refunding invocation or basis issuance.

## Historical references and fresh authority

The result contains invocation, applied/unchanged status and creation index/reference
records. It contains no native layer identity/generation, configuration value or
source. Whole-result captured/current permission and common outcome policy gate
every release. Host facts remain premises, not authenticated authorization proof.

References bind the full original layer incarnation. Their consumer acquires a
fresh native write basis only under current per-layer rights, actual state and the
existing shared pool's limits. Copies, foreign references and other handle roles
cannot substitute. Removal may leave a historical result readable while refusing
a new basis; a surviving same-label layer does not become its target. Forgetting
the creation result does not revoke a separately authorized basis already issued.
Neither source nor configuration-value disclosure is needed for these metadata
operations. Ordinary no-result callers remain independent of the optional hold.
