Section 14.6.1 separately adds native historical F14 receipts/current result release;

its own all-result exclusion; public wire and actual host truth remain separate.

Specification §14.5.1 adds bounded owned contexts around the existing F04 history

## Precedent and ownership

[Neovim undotree](https://neovim.io/doc/user/vimfn/#undotree()) exposes current undo
position and block information. It supports inspectable history, not Vellum's
multi-object authorization, opaque context issuance or immutable projection rules.
The mechanism here follows Vellum's already adopted bounded read-selector and
invocation patterns, with the §14.5 history advice contract unchanged.

The trusted host opens an internal inspection owner against the actual invocation
domain. Match the domain's authority and engine, then copy its independently scoped
history recipient, purpose, destination, profile, policy and continuity. The existing
engine/history component owns these contexts; there is no per-file engine, new
service or transport. Host admission/retention reservations remain premises.

Acquisition accepts only exact bounded projection products: a Boolean detail ceiling,
scope internal/reference pairs with separate undo/redo completeness, and group
internal/reference pairs with evidence readiness. Check unique identities and aliases,
Boolean types and actual group existence. These are trusted host projection facts,
not caller-supplied authority. Alias safety, complete coverage, evidence truth and
current permission are not proved by validating shape or registry membership.

Successful acquisition installs one fresh opaque native handle and increments a
monotone lifetime issuance count. Object identity in this serialized reference makes
cloned, foreign-owner and forged lookalike handles unavailable. The old F04 helper's
private context label is never returned. Native handle identity survives copied
responses; all other disclosed values are copies. Public Rust/ABI/transport encoding,
authentication and cross-process selector issuance remain separate refinement gates.

## Relevant current history basis

Capture actual retained group metadata and frontiers through the existing helper.
Also retain a bounded private comparison basis: selected groups' identity/validity/
complete participant scopes and both frontier stacks for those actual participants
and every selected scope. Normalize set-like group/scope ordering, preserving stack
order. Do not reduce this footprint to visible participants. Missing/changed selected
groups, changed validity or changed participant frontiers invalidate current advice.

The global root object, publication counter and unrelated scopes are not the basis.
Within resource bounds, unrelated native work can leave scoped advice valid. The
underlying capture still charges all metadata it copies; global budget pressure can
refuse, as permitted operational interference, rather than promise timing/resource
noninterference. No raw global progress is added to a public result.

At each query or trusted reversal-alias resolution, recheck owned live handle,
complete captured scope, current grant/retention/liveness/continuity/transfer/history
and reply gates, and equality of the actual current comparison basis. A detected
basis mismatch or explicit bound grant/retention/liveness/continuity/history loss
marks that context invalidated; restoring equal frontiers or regrant later cannot
revive it. Acquire a new context instead. Bind recognized query shape and exact
scope first; unknown facts, transient transfer/reply and foreign/malformed requests
do not establish loss. Trusted reversal alias resolution records the same bound
loss under its actual handle/scope. Stop/discharge require exact true facts.
See §12.8.3 and read-invalidation.md for five loss cases and eight new mutants;
retained capture, issuance and native producer state are not refunded or mutated.

This is endpoint metadata equality plus absorbing observed invalidation, not a
continuous history audit or detection of an unobserved ABA excursion. Source/body
values and versions, inverse validity, actual retention and companion readiness are
not inferred from this basis. The independent current history/evidence premise
remains required, and F14 checks actual current values and complete journals again.
No historical-current freshness claim is made from a global counter or byte equality.

Established empty history requires the declared complete direction and coverage.
Withheld heads, incomplete coverage, missing evidence or invalid groups are unavailable,
not empty. Availability includes every actual participant frontier. Blocking detail
returns only permitted aliases and remains bounded; hidden blockers can make a
complete group blocked without revealing their identities or count in detail.

## Reversal and lifetime separation

The internal resolver supplies only captured/current private alias bindings to the
existing native preparation boundary. It is not an F04 public product and does not
grant write access. Group and scope-frontier requests still bind the originally
selected group and need independent F14 current authority, identity, dependencies,
content, views, bounds, retained evidence and companions. A blocked group may refuse
during preparation; intervening work can also make an admitted plan refuse unchanged
at publication. An eligible query reserves no frontier.

An admitted reversal owns its captured intent independently. Closing an inspection
context does not cancel that command or retarget it. Likewise, query denial cannot
undo an applied reversal. Actual F14 native publications stay on the shared ledger;
undo/redo moves the original group's frontiers and does not author a replacement
history group or reverse external effects. Full detailed F14 result products remain
open beyond the existing coarse F06 observation.

| State or transition | Meaning and retained ownership |
|---|---|
| validation before issuance | Failure publishes no handle and spends no issuance |
| active | Queries require exact current scope, gates and relevant basis |
| invalidated | Observed basis mismatch, context closure or owner stop prevents release; metadata still occupies capacity |
| retired | Explicit owner control, delivery drain and retention discharge remove the entry; lifetime issuance does not decrease |

Owner/context stop needs owner control and recipient binding, not a current content
grant or spare ordinary capacity. Retirement is separate and requires actual delivery
and retention discharge; marking stop is not evidence of either. A retired handle
never names a new entry. These internal controls do not define a new public F19
variant or silently reuse the ordinary read-context contract.

## Bounds and conditional proof

The profile limits live/invalidated contexts, lifetime issuance, groups, scopes,
participants, detail rows, capture/basis/reply bytes and declared held units. At owner
opening reserve (maxContexts + 1) times the capture-plus-basis maxima, two reply
maxima and copied context bytes. The extra candidate is preparation space. Check safe
integer arithmetic and the owner bound before admission. Captures/bases and replies
are checked against their own maxima. Logical serialized charges are not physical
allocations, concurrent reservations, heap/RSS or crash durability evidence.

Under truthful trusted initial roots, scope/alias/coverage/evidence and current
policy/retention facts, acquisition copies a bounded actual basis and installs one
fresh owned context. Current release cannot substitute another owner/handle/scope or
ignore an actual participant; successful F04 outputs therefore satisfy the captured
frontier/evidence predicate under the current matched metadata basis. Existing F14
preparation independently uses the actual whole group and does not obtain rights
from that predicate.

An induction over acquisition/query/native publication/closure/retirement shows:
successful issuance increases count once; observed invalidation cannot become active;
retirement only removes availability and does not restore issuance; failed queries
do not mutate authored roots or grant reversal; copied results cannot mutate retained
metadata. Actual native mutation/history supplies basis changes, not a second mock
publisher. This is an authored conditional argument over the selected serialized
reference, not proof-assistant-checked implementation refinement.

All loops are over admitted finite roots, selected scopes/groups or context slots;
the operation vocabulary remains the existing three F04 variants and two F14 verbs.
No callback, parser, external effect or interpreter is added. Bounded reference
execution does not establish hostile decoder/native scheduler/physical halting.

Six scoped-release solver conditions cover complete participant matching, independence
from unrelated publication, absorbing observed invalidation and lifetime issuance;
SAT controls witness unsafe visible-only matching and resetting issuance on retirement.
At this context batch the scoped manifest had 21 conditions and the whole suite
211 across thirteen manifests. Section 14.6.1 adds six reversal-receipt conditions,
bringing current totals to 27 scoped/217 suite conditions over those manifests.
These check the declared predicates, not automatic JS/TLA+/Rust refinement.

## Executable evidence and instrumentation

history-context-checks.mjs composes actual native F13 creation/body/reattachment/
deletion, all six target forms, actual shared-ledger F14 group/scope-frontier undo/
redo, history capture/query helpers and the new owned context lifecycle. It checks
56 native cases/112 history stages, 8,192 acquisition/1,536 release combinations,
eight hidden-history pairs, fourteen controls/fourteen assertion-rejected mutants
and a passing unmodified dynamic baseline. Controls cover malformed products, handle
identity/scope, empty versus unknown/withheld, stale/unrelated/hidden participant
history, current write denial, stale plans, independent closure, capacity/issuance,
reply/capture/basis bounds, protected stop and copy isolation. Load errors are not
mutation detection. Finite cases are not exhaustive reachable history exploration.

PATH-01/02/03/04/12 and IF-01/03/08/09/12 distinguish context acquisition, current
advice, private alias resolution, independent F14 admission/publication and closure.
INS-01/02 track actual reversal; INS-03 advice/release/refusal; INS-06/08 history/
context retention; INS-07 discharge; INS-12 diagnostic loss; INS-13 useful query/control
completion. Private historyInspectionUsage exposes issued/held/live counts and logical
charge only for trusted supervision, not as an F04 count or hidden progress signal.
MELT/RED/golden signals distinguish advice delivery from reversal completion and stale
advice from empty history; USE covers context, metadata, issuance and reply saturation.
STRIDE challenges forged handles, stale aliases, missing hidden participants and
premature retirement. LINDDUN challenges history linkage, hidden counts and raw IDs.
No raw IDs, aliases, handles, global counters, content or invocations in ordinary
metric labels. Telemetry grants no inspection or reversal authority.

Actual policy/alias/coverage/retention/evidence truth, unobserved history continuity,
public acquisition/encoding, full detailed reversal results, full retirement/general
target mapping/point storage, other families and physical/concurrent/native/decoder/
production/independent assurance remain. No whole F04/F14/D-row or all-sections goal
is closed by this owned context reference alone.
