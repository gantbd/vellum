## Precedent and selected contract

Section 13.9.1 separately composes this native F14 path with actual retained
annotation create/delete history, linked source participants and fresh version
floors. See [annotation-membership.md](annotation-membership.md) for its own bounded
checks and conditional laws. This older admission checker's scope is unchanged;
§13.6.2 separately exercises native create/delete through the shared ledger in
[annotation-membership-editing.md](annotation-membership-editing.md). Actual
issuer/reservation/decoded gateway, full retirement planning and general target
restoration remain gates.

[Neovim undo blocks](https://neovim.io/doc/user/undo/#undo-blocks) group the changes
of a command into one undo step and warn that explicit joining can defeat useful
undo boundaries. This supports Vellum's adopted invocation grouping, not importing
alternate-branch navigation, undo of external effects or arbitrary executable
history. Vellum's linked cross-object participants and current authorization remain
additional constraints specified in §§14.1–14.4.

The closed semantic request fields are in history-reversal.json. They bind undo or
redo, a new invocation, engine authority incarnation, explicit group/scope target,
execution profile and bounded extra read dependencies. An ingress adapter may
resolve a human scope-frontier gesture before queueing, but must freeze its expected
group as part of that invocation. Reusing the invocation cannot mean "whatever is
latest now." A projected reference from history inspection is not itself a grant.
Command reference resolution and write authority remain separate from inspection
rights; private required participants need not be publicly enumerated.

Preparation unions caller dependencies with mandatory engine dependencies; an
omitted caller vector never erases the latter. Capture the original group/journals,
all actual participant frontiers, document incarnations, current source revisions
and required annotation-set generations. A later body edit can stale source-mapping
preparation without becoming an authored participant of source history. Reprepare
from current rows to preserve that body. Unrelated document changes do not stale
the group merely by advancing a global publication counter.

Owned preparation belongs to its engine incarnation, recipient and execution
profile. It cannot be reconstructed from a caller's structurally identical object
or retargeted through input aliases. Final admission checks fresh invocation
eligibility, current rights, stop state, interpretation, companions, resource/version
availability and history retention. Mandatory scope expansion, lost read context,
changed journal/participant state or stale incarnation refuses unchanged. Then the
retained reversal evaluator checks every frontier and actual expected content and
publishes the complete reversal once. Values are restored with fresh versions;
frontiers move without adding an ordinary authored group. No save, clipboard or
other external effect is replayed.

The authoritative terminal dispositions here are applied and not-published. Empty
history is not manufactured into a content publication or a grant to pick another
group. Full result release still follows §§12/23: this internal reference returns
state for assertions, not as the caller's visible result envelope. Later reply loss
cannot rewrite an applied disposition as nonapplication. Duplicate invocation
handling, pending/forgotten/retired results and intent equality remain §6.5, not
permission to execute this first-admission evaluator again.

## Executable evidence and limits

history-reversal.mjs composes actual dependency union from annotation-operations.mjs
and source/body/history reversal from annotation-compounds.mjs. It checks 512 final
gate combinations across undo/redo and 52 controls. Multi-document and source/body
groups reverse atomically, unrelated work does not stale preparation, private
mapping dependencies do, and fresh preparation preserves later bodies. Copies,
other engine incarnations/recipients, stale mandatory/extra dependencies, changed
retained journals, pruned groups and shrunk limits refuse.

Six mutants must load and fail assertions: accept copied ownership, omit annotation-
set capture, ignore required-scope expansion, ignore retained-journal change, ignore
read-only dependencies and omit final invocation freshness. The changed-journal
control alters both retained prior bytes and their consistent inverse. It also
checks changed forward expected-byte metadata independently, so the new view
part's expected-source guard cannot mask the journal-identity mutant.

Specification §14.7 now composes the native path with current-view preparation,
membership/profile/version validation and complete private-candidate installation.
[history-views.md](history-views.md) records 1,024 final gates, 1,010 point-oracle
cases, 14 multi-edit traces, 42 controls/eight mutants. The 512/52/six counts above
remain this admission suite's scope. Raw reverseAnnotationGroup alone is not a
view-aware native implementation; source groups require an explicit current view
inventory and finite source-view/work profiles, including an explicitly empty set.

The owned-plan fixture uses a private WeakMap for actual local object provenance,
not a serialized capability or a memory security boundary. Owner-issued command
references, complete registry/journal integrity, current all-participant rights,
fresh invocation eligibility, interpretation/companion truth and pre-admission
resource accounting are premises. Normalized shapes and logical JSON byte charges
do not implement hostile native decoding, bounded physical allocation or a Rust
ownership protocol. The selected native product is not full invocation/reply
projection composition or concurrent implementation refinement.

Create/delete membership reversal, identity reservations, general retained target
mapping/restoration, other live selection/provider profiles and companions, physical ownership
and resource limits, engine/host concurrency and actual publication/release remain
open. Required equal-byte/nonidentity mapping support remains §6.4; the composed
reference retains its documented restrictions. No new solver theorem, independent
expectation or Cleanroom certification is asserted. Point-profile persistence
remains the separate pending user decision.

## Instrumentation

INS-01 observes request validation, exact target resolution and owned preparation;
INS-06 observes actual participant/journal/frontier eligibility and retention;
INS-02 records one actual publication or unchanged refusal independently of reply
delivery. INS-03 gates visible outcome facts; INS-08 measures retained preparation,
mapping/journal pressure and actual discharge; INS-12 keeps diagnostic loss separate.
MELT/golden/RED separate attempts, preparation, stale/refused admission and committed
reversal latency/counts. USE applies to concrete registry, staging and retention
resources. STRIDE/LINDDUN challenge forged plans, invocation rebinding and hidden
participant disclosure. STPA/FMEA challenge retargeted queued gestures, changed
journals, stale mapping companions and partial linked reversal. Private target,
scope/group, invocation and descriptor identities are not ordinary metric labels.
