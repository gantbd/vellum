# Read declarations and versioned discovery

The explicit `owned-contract-discovery/5` profile adds existing F02 document reads
and F03 annotation queries to the fixed handler catalog. Profiles /1–/4 keep their
rows, order and meaning. There are seven rows in /5, including the unchanged five
from /4. This is selected metadata coverage, not completion of the public catalog.

## Declarations and authority

`read-engine-descriptor.mjs` consumes immutable declarations exported by the actual
source-read, acquisition and annotation-query argument guards. F02 describes
bounded range, logical line and snapshot handoff. Its
`engine-document-read-declaration/1` name identifies the metadata grouping; it is
not another execution contract. Snapshot handoff retains its single-document and
coherent-set request contracts. F03 describes enumerate, inspect and target
location under the existing `annotation-query/1` contract.

The schemas describe exact record fields, document shapes, numeric domains,
selection alternatives and class arrays. Typed and dynamic normalization share
the same meanings. Runtime validation still owns authority equality, participant
slot uniqueness, range ordering, Unicode validity, profile applicability and
original opaque selector authenticity. The coverage remains `outer-structure-only`:
describing some nested shapes does not establish every value or semantic check.
Status vocabularies agree with selected native products, but they are not complete
result codecs or event/selector protocols.

Fixed owner-origin binding, captured disclosure ceilings, current recipient release
and protected lifetime rules remain the existing discovery owner's obligations.
New metadata cannot enter an older profile. A later metadata withdrawal stops its
recognized captured context; unknown authority only withholds. Generic lookalike
packets cannot replace a fixed builtin origin. Target-bound advice does not grant
native read authority, and discovery selectors cannot serve as annotation contexts.

## Logical resources and substrate boundary

Existing entry, variant, row, metadata byte/node/depth, packet and reply envelopes
govern /5. No numeric product default is added. Complete descriptor-reply refusal
preserves selector/issuance state. These are logical local-owner checks, not global
parent reservations or physical allocation bounds.

Post-import probes preconstruct 29 discovery fixtures and two annotation fixtures
before intercepting 143 filesystem/process callables. Selected discovery execution
makes no baseline calls; three injected query call types are detected. This does
not establish fixture/import isolation, production dependency separation, all-host
containment or general fault recovery.

## Verification evidence

`node formal/read-discovery-mutations.mjs` requires the configured standard JSON
Schema validator. It covers ten input shapes, 209 standard-validator cases,
340 normalizations, 22 canonical pairs, 23 shape-valid/runtime-refused cases and
78 selected native success/refusal products. Twelve discovery controls include
twelve schema refusals, five loss cases and both owned descriptors. Nine envelope
dimensions have 27 exact boundary cases. All 32 semantic mutations are detected
after a coherent copied-graph baseline; construction and tool/protocol failures do
not count as semantic detections.

Run `node formal/read-discovery-substrate-checks.mjs` for the selected execution
probes and `node formal/standard-schema-validator.mjs` for seven tool/protocol
controls and three standard-validator smoke cases. The configured validator
receives one explicit byte-counted UTF-8 frame; completion does not depend on EOF
delivery. Nonzero/signal/tool failures and malformed replies are ordinary errors,
not semantic assertion counterexamples. Only a well-formed returned validity value
that disagrees with the expected case is such a counterexample. The shared helper
also serves the existing settings-schema, ordinary-edit, search-product and nested
search-value checks without changing their cases or expected results.

Four search, four ordinary-edit and two settings mutation construction targets are
retargeted to preserve the new profile while retaining their original older-profile
challenge. Their 40, seventeen and seven semantic mutation banks pass; builtin
declaration and engine/UI banks also pass. Static engine reachability remains
89 reference modules, with 76 engine and eleven presentation variants. The suite's
former 87-module expectation is a stale registration, corrected to the independently
observed count; it is not an engine ownership counterexample.

Full frozen verification and endpoint reconciliation remain necessary. Complete
public result/event/selector products, all-family coverage, actual host/policy
truth, measurement, physical/global/concurrent/crash refinement and independent
assurance remain gates. No whole completion row closes.
