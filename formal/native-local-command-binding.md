# Standalone annotation and reversal invocation binding

Specification §14.6.2 connects existing F13/F14 argument products to the shared
typed/dynamic invocation coordinator. It preserves native semantics and original
owned preparation rather than implementing a second annotation/history engine.

## Ownership and execution

Bounded exact public arguments bind invocation, context and native variant. Host
annotation/history roles remain separate from caller data. The first preparation
captures the original native owner, profile, complete finite limits, dependencies
and allocation. Current service rechecks that capsule; retries cannot replace its
request, resolve a newer frontier or allocate a different annotation identity.
Annotation rights remain distinct from source-write rights. Both position/content
point profiles survive. Equal-body no-ops do not require an unused version.

Native publication and receipt staging use the existing one-root coordinator.
Result disclosure is bounded by original ceilings and current grants, not write
permission alone. Stop/fault/forget retain the existing issuance and protected
retirement rules. The public U01 receipt-retrieval decision is not selected.

## Bounded construction

The parent funds 3C + 2M + 2R for public capture C, intent ceiling M and root ceiling
R. After bounded original profile capture, it additionally funds 2 max(0,N-M),
where N is the maximum captured native plan/view/membership construction ceiling.
All arithmetic and remaining capacity are checked before native preparation.
Actual retained intent still fits M. Larger native ceilings can therefore support
small valid edits without bypassing parent capacity or changing native limits.
Failed preparation refunds provisional charges; protected retirement releases the
retained hold once. These are logical serialized frames, not physical JS memory.

## Scoped evidence

The focused baseline has twelve controls, eight variant/target cases, seventy-nine
omissions and eight strict-permission cases. Fourteen coherent graph mutants cover
original intent/limits/allocation, permissions, role separation, parent debit and
capacity, construction funding, preparation replay and retirement classification.
The parent-capacity mutant removes both redundant checks together; failure to
construct a mutant is never counted as semantic detection.

Ten adjacent suites cover native annotation authoring/membership, history reversal,
invocation publication, ordinary editing, exact batches, composition, compound
receipts, mixed authoring and the mutation harness. Bounded second-agent review
found no remaining must-fix after required-limit validation and construction funding
repairs. Full frozen qualification and adoption remain pending. This is not a
complete discovery/event/result facade, hostile-object decoder proof, actual host
or issuer validation, physical/concurrent/crash proof or independent certification.
