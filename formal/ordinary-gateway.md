# Decoded ordinary edit invocation gateway

Section 6.5.2.2 reuses this gateway's slot, busy marker, canonical charge, native
candidate binding and cleanup for F12 selection/navigation. A private family
discriminator selects the view-only permission contract; source-write requirements
remain on ordinary source editing. See selection-gateway.md. The F11 counts and
exclusions below remain scoped to the four ordinary-edit forms.

The private gateway connects four existing F11 ordinary-edit request forms to
issued invocation tickets: selection-edit/1, line-edit/1, boundary-command/1 and
configured-line-edit/1. It uses existing selection, line and boundary job kinds,
producers and the common publication decision. Literal replacement, other variants,
public wire encoding and a Rust ABI are outside this composition.

## Canonical meaning and ownership

Typed and dynamic tuples select the same catalog-owned form. Exact declared outer
fields, fixed contracts/profiles, complete execution context and caller-supplied
finite limits are copied into immutable canonical data. A Unicode boundary object
is retained by identity, not traversed or converted into JSON authority. Native
producers still validate the request's semantic meaning and actual evidence.

A ticket can retain one canonical preparation. Matching retries return the same
job before submission, while pending and after terminal completion; they do not
resample selections, configuration or source. Changed data, limits, configuration
profile or opaque binding refuse. The original domain/ticket pair owns the plan,
even when another domain issues the same textual invocation reference. Legacy
submission cannot borrow that plan or replace it with a newly prepared native plan.
Sixteen existing issued-ticket preparation ports exclude canonical preparation;
the configured native controls exercise valid preparation in both directions.
This is not a claim that every northbound family has a decoded request gateway.

Preparation sets a per-ticket busy marker before inspecting inputs. Nested ordinary
preparation, submission, other preparation and retirement cannot consume that ticket
while it is busy. A controlled reentrant retirement test reproduced an orphaned
plan before the retirement guard was added. This guard does not establish arbitrary
callback containment, synchronization between threads or hostile proxy isolation.

## Logical reservation and cleanup

The existing ledger's four intent maxima are not treated as implicit capacity for
an additional canonical capture. After complete bounded capture and before native
producer work, reserve its measured serialized bytes against the actual owner's
remaining maxHeldBytes. The separate native settings pool keeps its own reservation.
No new numeric profile limit or default is selected.

The charge remains unchanged on replay. A producer refusal releases the provisional
charge before retry. Successful preparation retains it through pending/terminal
phases. A fault after configured interpretation acquisition retains the charge and
original plan until protected cleanup; it fences admission and leaves the old root
intact. Retirement first discharges native obligations, then releases the canonical
charge, removes the entry and marks its plan retired. Issuance is never refunded.
For raw producer plans, protected cleanup removes the private retained plan record;
collection timing and physical reclamation are not asserted.

The reservation argument is conditional on the trusted owner ceiling and native
pool accounting: if charge is within ceiling and capture bytes are at most the
remaining headroom, their sum remains within ceiling. Exclusive preparation and
nonrefunding retirement keep one retained charge per canonical ticket. These are
logical serialized-data charges, not heap peaks, reflection cost, shared-object
size, physical lifetime or complete cross-owner accounting proofs.

## Publication and finite execution

Only the common owned run may publish the retained producer. Current exact-true
ordinary edit permissions are checked again; original native source, selection,
configuration, history, annotation and view dependencies still apply. A valid
no-op checks its assumptions but needs no unused source or selection version.
Cancellation cannot free a pending ticket or refresh its original candidate.

The normalizer walks only bounded data after structural inspection; producers keep
their existing finite work profiles. Gateway control has no retry loop or new
recursive execution vocabulary. A matching retry observes retained eligibility
rather than starting another run. JavaScript reflection, opaque host behavior,
concurrency and crash recovery remain implementation obligations; this is not a
whole-engine halting or categorical-completeness proof.

## Scoped checks and observations

The isolated checker currently runs 35 controls, 162 denied/truthy/missing permission
cases and 48 exact byte/node/depth/parent boundary checks. Owner-headroom tests
separate the canonical charge from an already reserved settings pool and exercise
zero, one-below, exact and one-above capacity. Eleven semantic mutations are killed
after a coherent baseline; two instrumented post-lease faults verify old-root
preservation, admission fencing and protected nonrefunding discharge. Construction
errors are outside mutation-detection predicates.

The substrate probe intercepts 143 filesystem/promise/process callables after
imports. Selected baseline controls make no intercepted calls. Hidden read, rename
and process variants each record the exact attempted call and produce the same
fault/cleanup frame. This does not establish static package separation, every host
API, arbitrary code isolation or real provider truth.
