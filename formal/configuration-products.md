## Precedent and adopted rules

[VS Code configuration inspection](https://code.visualstudio.com/api/references/vscode-api#WorkspaceConfiguration)
exposes effective settings and their contributing scopes, with replacement and
object merging. Vellum uses this inspectable structure while retaining its already
adopted scope order, explicit applicability and host restrictions. This does not
import VS Code's exact language precedence, persistence behavior or extension API.

frontend-configuration-reference.json contains the earlier field inventory. A query binds its
context, explicit target and projection/resource profile; effective-configuration
and permitted-origin name a registered key, while capabilities returns permitted
accepted declarations. Capability metadata is not a successful live probe or a
grant. Unknown, withheld and stale queries are safely unavailable, not a guessed
default, empty permission set or unsupported execution inference.

Origin references are owner-projected identities, not raw private workspace/layer
names. The origin product explicitly covers permitted origins only: an empty list
does not prove that no hidden contribution exists. Current release checks identity,
target, purpose/destination, context/profile, policy/continuity, retention and actual
configuration basis. Narrowing cannot release an old rich capture; broadening
cannot enlarge it. Queries transfer owned bounded values without mutating settings.

Each setting has a declared type, legal scopes, composition, library default and
dependency domain. The normalized resolver covers scalar replacement, replacement
lists and maps merging only at declared top-level keys with replacement at each
key. Nested map/list values use structural equality independent of object-key
insertion order; list order remains meaningful. Library defaults, host, language,
explicit workspace applicability, document and permitted view/input have the
adopted precedence. Membership/open/focus order does not resolve ambiguity.

Incompatible equal-rank values reject even if a higher override would mask them,
as required by requirements §11.2. Disjoint map keys may merge at the same rank;
conflicting values for one key cannot. Host restrictions constrain resolved values
outside the preference hierarchy. Removing an override exposes inheritance;
reset is a distinct explicit contribution of the library default. Equal effective
values with changed explicit origin are not automatically complete identity.

## Owned activation and retained work

Settings requests bind invocation, execution profile, bounded changes, keymap intent
and extra read dependencies. A settings change names the exact layer and expected
generation, registered key and set/remove/reset intent. Caller dependencies union
with mandatory engine dependencies; callers cannot erase or weaken required scope.
The shared dependency validator is the actual annotation-operation reference helper.

Preparation resolves the required candidate profiles and captures applicable target/
layer dependencies plus schema, restriction and membership interpretation. Owned
plans bind engine owner, recipient and profile. Final admission rechecks layer
authority, expected context/dependencies, current bounds/retention/interpretation,
stop state and fresh invocation eligibility. Publish all changed layers and affected
profiles together or preserve the immediately current state. Preserve unrelated
current settings and authored/effect state, not a complete old staged registry copy.

Old held interpretations remain intact; insufficient required retention refuses
activation. Domain generations change for actual effective source/view/analysis/host
changes, not simply because the global activation metadata advanced. A cosmetic
view change does not alone invalidate source interpretation. Retained provider code,
compatibility truth and actual physical reclamation remain separate obligations.
Complete identity needs no unused version or new retained old context. Rollback is
a new activation with fresh generations, not source-history reversal.

## Executable evidence and limits

configuration-products.mjs composes the actual baseline replacement resolver and
dependency union. It checks 128 final gate cases, 18 equal-rank/order cases, 192
query release cases, 24 hidden-origin comparisons and 63 controls. These include
typed replacement/merging, masked peer conflicts, distinct reset/removal, nested
value equality, scoped current authority and caller generations, retained-profile
capacity, unrelated source/separate-target activation, current read dependencies,
origin projection and literal registered keys without JavaScript prototype effects.

Eight mutants must load then fail assertions: mask peer conflicts with a higher
override, ignore host restrictions, omit held retention, ignore current layer
authority, let cosmetics invalidate source, accept a copied plan, expose raw
origins and ignore caller generations. Authored text/comments/history and unresolved
effect frames remain unchanged by settings activation in the normalized fixture.

Fixture keys/defaults/types and numeric limits are examples, not a selected public
setting catalog or tab/indent/host default. Full native keymap, registry and provider activation,
recursive per-key merge/rule profiles, actual sensitivity/schema admission, native
codecs/identifiers, full replay/outcome release, live membership/applicability truth,
compatibility and physical ownership/accounting remain gates. The original settings-
only reference is now composed with bounded map/chord helpers under §22.3.2; see
formal/keymap-products.md. Unsupported/malformed maps refuse the whole plan rather
than partially applying settings. Full F16 registry/provider products remain open.

Dependency capture is scoped to written layers and their applicable targets;
source-only changes and separate configuration targets can proceed. The fixture's
schema/restriction/membership interpretation generations cover its declared registry
domain, not a proof of minimum invalidation for every possible host registry.
Typed inputs are normalized finite values; logical input/plan/capture/reply charges
do not prove hostile decoding, pre-allocation cost, bounded recursion, real RSS or
concurrent native ownership. Actual context/retention/authority/capability truth is
a premise, not established by a descriptor. Same-author sensitivity checks are not
independent Cleanroom certification or new solver theorems. Approved specification
§29.4.1 preserves both position and content point profiles explicitly; that storage
choice is no longer pending and does not establish configuration integration.

## Native integration prerequisites

The normalized evaluator is not yet a native settings publication path.
invocation-publication.json names eleven native job kinds, including resource
registration, but none owns engine semantic-settings activation. Resource registration's
owned staging and final current-root checks are an integration precedent, not an
alias through which settings requests already execute. The adopted F16 semantic
variant remains required.

Reuse CMP-02 preparation and CMP-03 publication. Before claiming native closure,
bind the evaluator's configuration layers, target applicability, effective domain
generations to their actual owner in the native root, excluding frontend maps
and chord contexts. The
fixture's `authored` field is a frame-test placeholder, not a second source,
annotation or history authority to install in that root. Current domain generations
must have actual producers before compound read dependencies can name them.

Native conformance must cover owned preparation, current schema/restriction/
membership and per-layer semantic dependencies, unrelated intervening publication,
retained engine interpretations, complete identity and
atomic root/outcome/receipt installation. It must retain current-policy result
release and actual journal/retention floors. Copied or foreign plans, stale or
revoked scopes and insufficient capacity must not publish a partial activation.
Existing normalized checks do not discharge these native obligations.

The native input profile also needs finite schema/value depth and node bounds,
with rejection before unbounded recursive resolution or copying. Existing JSON
byte charges alone do not prove that bound. Registered fixture keys, contexts and
host flags must not become public defaults, actual provider truth or recipient
authority merely by being copied into native metadata.

## Instrumentation

INS-09 observes resolution, rejected peer conflict/type/restriction, staged activation,
changed interpretation domains and accepted generations. INS-01 separates invocation
admission/no-op/refusal; INS-03 current configuration/origin/capability release;
INS-08 retained plans/contexts and actual discharge; INS-12 diagnostic loss. MELT/
golden/RED separate lookup, preparation, conflict/refusal, no-op and activation
populations and latency. USE applies to real staging/retention/transfer resources.
STRIDE/LINDDUN challenge forged plans, stale writes, settings-as-policy, private
origins and captured-scope expansion. STPA/FMEA challenge half activation, lost old
interpretation, spurious source invalidation and rollback of unrelated scopes.
Setting values, keys, workspace/origin IDs and profile versions are not ordinary
metric labels. No callbacks or hidden provider effects enter publication.
