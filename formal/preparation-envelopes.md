# Complete preparation intent envelopes

Specification §17.2.4 requires each selected owned preparation to fit its complete
normalized parent intent before retaining a plan or interpretation lease. A payload
that fits alone may fail once enclosed by kind and plan. Submission already rejects
that larger intent; preparation now refuses before creating the avoidable hold.

## Units and ownership

The reference unit is UTF-8 bytes of JSON.stringify of the full normalized
kind/plan product. Per-product request/value/profile/plan bounds and scoped
retained-reference-vector bounds remain separate. This unit is neither a public
wire choice nor a measurement of Rust layout, heap allocation, RSS or provider cost.
The existing parent resource profile and invocation owner remain authoritative.

[Rust Vec::try_reserve](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.try_reserve)
is precedent for fallible capacity preparation that preserves existing contents
on error. That contract does not supply these reference byte units or prove
Vellum's physical allocation accounting.

Native/scoped registration, relation/container lifecycle, document lifecycle,
Save As activation, completed source-load activation, annotation-load activation
and configured lines check the wrapper. Settings retains its existing wrapper
preflight. No source read/write, provider dispatch or new job occurs at this check.
Failure preserves the root, registration floor, issued-slot preparation state and
existing holds. It does not refund the invocation already issued. Configured-line
failure acquires no additional interpretation lease.

## Executable checks

Run preparation-envelope-checks.mjs with the pinned VELLUM_ICU4J_JAR. The checker
copies the declared project inputs into fresh temporary module graphs and adds an
owner accessor only there, allowing controlled boundary-limit variation. The
project engine exports no such accessor. This is test instrumentation, not a
supported live capacity-mutation API or memory sandbox.

Eight actual fixture paths each exercise one byte below, exactly at and one byte
above the complete wrapper bound, through typed and dynamic routes: 48 cases.
The actual fresh capture confirms the predicted byte count. Checks cover 32
identical preparation retries, 32 opposite-route pending retries and sixteen
recoveries after refusal. Four successful configured-line cases add one lease
each; refused preparations preserve existing lease accounting and leave the new
slot unprepared. Native roots, registration floors and invocation accounting are
framed through preparation, with publication still independently governed.

Each of eight source mutations removes one wrapper guard. An unchanged coherent
graph passes first; only assertion failures count as kills. The existing scoped
registration test chooses a limit that fits both the request and full wrapper but
not retained values plus basis references. This prevents the new guard from masking
its retained-reference mutation; all existing 32 mutation identities remain.

## Instrumentation and remaining gates

INS-01 distinguishes offered preparation, byte/retention refusal and later
submission. INS-02 owns actual publication, INS-09 interpretation holds, INS-12
optional diagnostic loss and INS-13 protected retirement. Count retries separately
from logical invocations. Keep preparation/queue/service latency, normalized bytes
and held leases distinct in MELT, RED, USE and golden signals. Budget saturation is
not allocator exhaustion. Use bounded authorized reason classes, never payloads,
private references or raw resource identities as ordinary labels. STRIDE/LINDDUN
retain exhaustion, quota-reset and disclosure coverage at these boundaries.

Existing conditional resource/capacity laws remain separate abstract evidence;
no new solver condition is added. Full value/result/event products, every other
allocation/queue owner, physical accounting, immutable runtime-profile enforcement,
actual policy/host truth, concurrency/crash and independent refinement remain
open. A full frozen-input run is required before this batch is complete.
