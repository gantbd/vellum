## History grouping and retirement

D13 joins typing only under all declared compatibility/identity/budget conditions;
otherwise the default invocation boundary stays isolated. The 64 Boolean cases
check this conjunction, not actual typing semantics or identity comparison.
D14 retirement is a least fixed point: start with the requested groups, add every
dependent continuation of an included group, and stop when the finite set no
longer grows. Each strict expansion consumes an unincluded group, so closure
halts. Every closed superset contains each inductively added member; therefore
the result is the least dependency-closed superset. Any pin/floor intersection
refuses the whole proposed retirement, preserving unrelated groups and promises.

The three-group fixture enumerates all 64 directed dependency graphs, eight seeds
and eight pin sets: 4,096 cases. An independent oracle intersects all closed
supersets rather than repeating the iterative algorithm. Cycles are allowed in
this private closure test; it is not a proof that actual history dependencies are
cyclic, complete or correctly supplied. One bit denotes one complete group,
including all its actual participants. Inverse payload correctness, frontier
representation, complete-group accounting and floors remain D14/PS-HI refinement.

## Persistence BOM and search

D15–16 preserve exact original captures; the progression predicate permits a
derived baseline only when every causal/current provider premise holds and the
caller condition is not pinned. All 256 Boolean combinations check that gate.
No receipt is produced and no physical write order/host evidence is established.
The existing save/effect slices provide separate partial evidence, not automatic
composition with this guard. Annotation persistence D20 remains host-neutral
with an explicit reference-format gate; staged validation is a required frame
argument, not an implemented codec or selected persistence backend.

D21's signature-consumption profile has a restricted injective domain. If a tuple
has BOM metadata, its encoding begins with one signature; otherwise its allowed
text cannot begin with that signature character. Thus the two cases have disjoint
encodings. Within each case UTF-8's valid-scalar encoding plus prefix cancellation
preserves text identity. Consuming exactly one signature inverts encoding on that
domain; encoding the consumed result recovers every accepted input byte sequence.
The local symbolic string condition checks tuple injectivity and a control exhibits
the unrestricted ambiguity. This is not a complete UTF-8/streaming implementation
proof. Twenty corpus tuples and five invalid UTF-8 byte sequences exercise the
fixture's trusted platform codec, including two leading U+FEFF characters.
Helpers assume valid scalar input strings; arbitrary JavaScript surrogates are
not accepted-domain evidence. Newlines and content are never normalized.

D17 navigation selects a member of the already complete ordered match set. It
includes the start when no current match is named, excludes an identified current
match, and performs at most one explicit wrap. Returning one result halts this
invocation even if a one-match wrapped result names the current match again.
The 240 cases use four fixed match sets and independent filtered-order expectations;
they do not implement matching or prove source-byte/Unicode correctness. D18's
pinned fold mapping remains a supported-capability gate, not an implicit waiver.

## Mechanism precedent

[Emacs atomic change groups](https://www.gnu.org/software/emacs/manual/html_node/elisp/Atomic-Changes.html)
and [Neovim undo blocks](https://neovim.io/doc/user/undo/) motivate explicit grouping;
[CodeMirror transactions and configuration](https://codemirror.net/docs/guide/)
motivate coherent state/context changes. [Helix language support](https://docs.helix-editor.com/languages.html)
and [Tree-sitter injections](https://github.com/tree-sitter/tree-sitter/blob/master/docs/src/3-syntax-highlighting.md)
inform bounded embedded-language integration. [Unicode's UTF/BOM guidance](https://www.unicode.org/faq/utf_bom.html)
anchors encoding distinctions, and [OpenTelemetry error handling](https://opentelemetry.io/docs/specs/otel/error-handling/)
supports containing optional telemetry failures. The exact conservative defaults
in §28 are Vellum choices, not guarantees attributed to these implementations.
