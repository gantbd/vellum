## Precedent and boundary

[Neovim annotation namespaces and extmark APIs](https://neovim.io/doc/user/api/#nvim_buf_get_extmark_by_id())
provide precedent for scoped lookup identities and distinct removal/mapping state.
Vellum uses document/record incarnations and observer-local references, not raw
global IDs, Neovim's storage/undo semantics or a new authorization service.
The shared reference profile becomes `recipient-publication-observation-reference/2`:
exact document scopes now distinguish named records from an explicit collection
facet ceiling. Named mode uses `collection:null`; the modes are mutually exclusive.
This is a versioned internal reference product, not a released wire/API migration.

## Owned visibility preparation

The trusted host supplies a complete finite visibility/facet relation in an approved
projection order. The engine checks exact coverage of actual collection rows,
document/record/incarnation identity, duplicates, fields/Boolean shapes and bounds.
It requires current authorization/continuity, reserved preparation, attested visibility,
complete coverage and approved-order facts before issuing an opaque preparation.
Matching row identities proves coverage, not that a permission decision is true.
Host policy/order/identity and live reservation truth remain explicit premises.

The preparation binds the exact root object, publication and normalized root value,
projection context and policy epoch. It is not a hash equality claim. Cloned handles,
copied roots, stale or mutated roots, mismatched scope/facets/epoch and incomplete
relations cannot authorize a collection. Report-permission narrowing does not change
the data scope. Each root/context-validated projection attempt consumes the preparation;
an abandoned preparation requires explicit retained-owner release. The host must
bound live preparations/reservations; this reference does not prove that host registry
or physical raw-root retention. Preparations are private policy work, never diagnostics
or northbound caller-supplied authorization certificates.

## Visible references and coherent publication

Filter invisible rows before allocating references. Allocate only in the supplied
approved visible order, never a global index/sequence or hidden-row-dependent ordinal.
Intersect each visible row's body/target facts with the captured collection ceiling;
the existing annotation projector then builds permitted values. Observer-local
reference spelling is private fixture encoding, not an adopted public token format.

Retain a bounded document/record/incarnation-to-reference ledger for the observer's
lifetime. Deleting or hiding a record does not recycle its old identity. An unchanged
visible incarnation keeps its reference; a new incarnation gets another. These
references grant no access and do not yet mint F03/read-context selectors.

Stage candidate bindings and issuance together with the whole projected frame.
Only a complete fitting baseline/event/resync commits the candidate ledger; refusal
or gap cannot spend partial bindings. Reserve declared live/candidate ledger bytes,
binding count, lifetime issuance, event/report frames and existing spent markers.
Saturation creates explicit gap/refusal, never silent identity reuse or an empty
complete collection. Recovery needs a fresh visibility preparation and authorized
baseline. Existing context/revocation fences, queue ordering and protected stop remain.

Visible addition/removal changes the permitted full-state projection. A removal
means the item ceased to be visible, not necessarily that its author deleted it.
Hidden-only create/body-update/remove leaves event/generation/binding use unchanged.
Current source-driven target mapping uses the same actual compound publisher.
Create/delete fixtures compose the actual logical authored-field helper with a
normalized root embedding; they do not prove a native all-companion/history publisher.

## Conditional argument and executable evidence

Assume coherent serialized roots, complete truthful fixed-policy visibility/order
facts, non-confusable record incarnations and valid host reservations. Invisible
rows never reach reference issuance or the projected collection, so hidden insertions,
values and removals cannot shift its local identities. The retained incarnation key
prevents reference reuse after visible removal. Staged ledger/frame commit preserves
the previous ledger on refusal. Root/context binding prevents stale facts from
authorizing a different snapshot. Visibility/host truth is not proved by these laws.

Checks include 4,096 preparation-gate combinations, 64 selected hidden-world pairs,
16 facet/ceiling combinations, ten controls and twelve assertion-rejected mutants.
Context controls include semantic document/view uniqueness independent of object
member order. Field-tuple identity keys reject reordered aliases; a mutation that
restores raw object serialization is rejected. This changes private identity
indexing, not authored bytes or a public canonical wire format.
They exercise actual record create/delete helpers, compound mapping and shared
observer/projection/queue paths: visible discovery, hidden suppression, removal,
incarnation changes, exact owned preparation, stale/forged/incomplete input, single
use, ledger/byte pressure and atomic candidate refusal. The previous named-observer
768 gate/24 release/256 paired/two-chain/ten-control/twelve-mutant suite remains.
Finite cases/arguments are not general induction, new SMT laws, categorical closure
or independent Cleanroom certification.
