## Restricted writer inspection and native preparation

One actual source-save registry can issue one stable opaque lifecycle inspection
handle under its existing owner-control/preparation/resource facts. A WeakMap
factory records its real writer, not copied task/fault data. Repeated borrowing
returns that handle; clones, unknown handles and borrowing from an inspection
handle refuse. The stable handle creates no per-call handle history. Its retained
reference has the writer registry's lifetime; owner retirement, distributed
revocation and physical reclamation remain separate contracts.

Registry-authority/disposition inspection, retained and rebind guard preparation,
and pure rebind-candidate preparation accept this restricted handle. None installs
a root or mutates the writer ledger. Write admission,
exports, dispatch and other mutating writer APIs still require the actual registry
owner and do not recognize it. Possession is not an authorization grant: the
ordinary current operation facts, binding/coverage evidence and private lifecycle
frame checks still apply. Raw writer records and sealing functions belong to the
trusted first-party composition boundary, not northbound reflection. Hostile native
code/module monkey-patching is not covered by this JavaScript reference; production
type/module encapsulation remains a refinement gate.

prepareNativeRetainedLifecycleTransition extracts the existing fixed preparation
logic without changing it: exact profiles, current pair/membership, known-empty
scratch enrichment, actual writer guard and closed candidate-frame certification.
The direct native publisher still obtains its actual root and installs only
through the existing final owner. Owned invocations call the same preparer with
their actual current root and restricted inspection. There is no host function
pointer or arbitrary callback inside publication.

## Owned interpretation and atomic service

An initial plan requires an actual issued ticket/full current context, shared
strict admission facts, supported nested request/profile and a same-authority
inspection issued by the actual writer factory. Preparation validates the native
product, discards its temporary certificate/guard and retains only immutable
request/profile plus the inspection reference. The serialized interpretation must
fit actual maxIntentBytes. A slot permits one interpretation: identical preparation
returns it, while a changed profile/request/writer refuses. Plans bind actual
owner/domain/ticket and original invocation; matching strings or copied wrappers
cannot substitute a foreign plan.

This exclusion spans both owned lifecycle preparation products. A slot retaining
a container preparation cannot retain a document-lifecycle preparation, or vice
versa; submission must use that prepared product and exact plan, not another job
family. The slot therefore does not retain two independently bounded preparations
under one preparation charge. Overlapping ownership guards are weakened together
in the foreign-plan mutation variants so redundancy is not mistaken for a test gap.

Typed and dynamic routes admit the same owned interpretation. Pending cancellation
settles notApplied/stopped without changing lifecycle state, discharging a producer
or releasing a writer obligation. Service requires lifecycleInterpretationCurrent
exactly true, exact retained/current lifecycleProfile equality and the identical
lifecycleWriterInspection. Unknown compatibility or another same-authority writer
is not a substitute. Construct a fresh candidate against the actual current root;
preserve unrelated intervening edits and require all captured target generations
and current native obligations again.

Staging uses actual destination/task/fault records, private writer guards and
native frame certificates. New write promises can refuse disposal; late conflicting
writer evidence can refuse key release. Failed guard/profile/native checks settle
notApplied/rejected, not false successful disposal. Root/reply caps and actual
annotation-baseline promise floors still constrain service. Applied and validated
unchanged results both use the common outcome contract. A real unchanged membership
does not replace the root or consume a publication generation.

Before final commit, construct the bounded receipt/common outcome, freeze the
candidate and revalidate exact stage/candidate/receipt, current interpretation and
native certificate/actual writer guard. Carry scratch or retained source journals
according to the existing native product. Root, terminal outcome and private
receipt install together. A trusted contradiction or protocol exception faults
conservatively with unknown publication and no new root/result. Every temporary
certificate and writer guard is consumed or discarded in the same service turn.

The receipt is only invocation, applied/unchanged status, native operation and
document identity. It exposes no source, annotation body, membership list, private
writer record or certificate. Release requires admission's
lifecycleResultIdentifiersAllowed exactly true, complete current invocation context,
common release policy/facts, an available applied/unchanged summary, strict
lifecycleResultReadable/lifecycleResultContextCurrent/historicalDocumentReadable
and current full-envelope bounds. Current denial does not undo mutation; later
grant cannot widen the admission ceiling. Historical identity is not proof of
current liveness or a mutation capability. Raw local allocation encodings are not
authorized for unprivileged remote release; scoped opaque references and
non-linkability remain separate public-contract gates.

Forget removes outcome/receipt without restoring eligibility; authorized retirement
removes slot/preparation. Replay cannot recreate, dispose or release twice. Existing
slot/intent/result/root envelopes bound retained logical products. A single stable
inspection adds no cloned ledger or unbounded per-borrow registry; transient copy,
allocator/RSS/stack/time and complete physical accounting remain explicit premises
and implementation/measurement work, not consequences of those logical bounds.

## Conditional arguments and evidence

Assume supported normalized native state, truthful current host/compiler/policy/
retention facts, the first-party sealing boundary, unique invocation domains and
serialized nonreentrant publication. The nine native algorithms and certificate
frames have their existing scoped evidence; no imported/legacy lifetime is inferred.

1. One immutable owner/domain/ticket-bound interpretation and pending-only service
   give at most one native settlement/publication. Intent equality and plan identity
   prevent typed/dynamic reinterpretation; forgetting and retirement never rewind
   issued coordinates or make stopped/refused work fresh.
2. Initial validation does not retain a replacement root. Current service reconstructs
   the native candidate, so unrelated source state survives and stale target,
   writer, profile or obligation evidence refuses. Native frames and actual promise
   floors preserve ownership, bindings, histories and producer obligations according
   to the selected operation, not a blanket claim that all fields are unchanged.
3. The restricted handle names the actual writer record. Its authority/disposition/
   guard readers observe current records; replacing that record with an empty
   snapshot breaks the late-conflict control. Effect APIs' owner lookup does not
   recognize the inspection handle, so it cannot issue writes through them.
   Actual global coverage and host authority remain premises, not pointer proofs.
4. Candidate, common outcome and bounded receipt are prepared before one final
   callback-free publication. Current context/ceiling/policy intersection prevents
   stale/expanded identity release. Producer quiescence, physical reclamation and
   already disclosed copies are not inferred from lifecycle or observation changes.
5. Nine nested products and the existing finite invocation phases close this
   interpreter's vocabulary. Every call uses bounded validation/scans/copies and
   one commit or refusal. This is conditional per-call halting and trace preservation,
   not scheduler fairness, provider termination, machine-checked induction, global
   categorical completeness or a bounded lattice for arbitrary lifecycle changes.

The existing source-save/continuity/export mutation checks retain their eighteen,
