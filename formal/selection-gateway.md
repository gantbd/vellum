# Decoded selection and navigation gateway

The private F12 gateway binds four existing request forms to issued invocation
tickets and the common local publication owner. It changes neither UI ownership
nor the supported command vocabulary. Source-write authority is unnecessary for
these view-only operations; current source-read and view-write authority remain
required. A successful selection change does not become authored source history.

## Canonical inputs and native evidence

Typed and dynamic tuples select catalog-owned exact fields and profiles. Capture
complete arguments, execution context and caller-supplied byte/node/depth limits.
Opaque occurrence and boundary handles retain actual identity; do not traverse,
serialize or compare them as JSON authority. A structurally valid handle is not
evidence of authenticity: the native producer must resolve its original live
evidence and current source/selection context.

The normalizer's four declarations cover three engine-owned variants, not four
new operations. A tuple for another valid variant cannot reclassify its arguments.
Malformed data/accessors and unsupported declarations refuse or fail construction
before eligibility; hostile reflection/proxy containment and physical input peaks
are not established by these checks.

## One retained candidate and one owner

Reuse the existing invocation slot, preparation-busy marker, domain/ticket plan
binding, canonical-capture charge and protected cleanup. An internal family tag
selects F12 permission validation; it is not caller-supplied authority. Ordinary
edits and selection/navigation cannot retain different preparations on one ticket.
Other preparation ports and legacy submission cannot replace or borrow the plan.

Matching retries before submission, while pending and after completion return the
same native job. Changed arguments, limits or opaque handles refuse; the engine
does not resample current carets or search results. Equal textual invocation
references from different domains do not establish common ownership. Reentrant
preparation, submission or retirement on the busy ticket cannot consume it.

Reserve the complete canonical capture's measured serialized bytes against actual
remaining owner capacity before producer work. Native refusal refunds provisional
capture. Successful preparation retains one charge; replay adds none. Protected
retirement removes private plan records, marks eligibility retired and releases
the charge without refunding lifetime issuance. These are logical bounded-data
reservations, not physical reclamation, transient-copy peaks or complete global
accounting evidence.

## Publication and failure frames

At the one eligible run, validate current exact-true source-read/view-write and
common admission facts. Unicode movement also checks live/retained boundary
evidence. Search navigation checks exact-true current query grant, scope,
continuity, capacity, retention and stop facts before native resolution. None of
these observations proves the host's policy or retention report truthful.

The native decision reads the current shared root. View-only publication preserves
documents and authored groups, and does not restore a preparation-time root over
later comments. Unrelated views remain unchanged. A valid no-op still checks its
assumptions but needs no unused publication/selection version. A completed no-op
stays spent after another command changes the selection.

Pending cancellation does not free or renew the candidate. A fault after private
preparation is retained but before return leaves no delivered job, preserves the
root, fences admission and retains protected cleanup. A publication fault pairs
the old root with the existing Unknown/faulted disposition. No fault permits fresh
re-execution or fabricates an external acknowledgment/quiescence fact.

## Instrumentation and trust boundaries

INS-01 separates first preparation/admission, replay and refusal; INS-02 observes
the actual common run and local disposition; INS-03 observes current release;
INS-05 observes retained search/boundary evidence and INS-10 the view intent.
INS-11 links native-input-initiated submissions where applicable, not mandatory
headless input or UI ownership in the kernel. INS-13 observes capture charge,
busy/refused work and protected discharge. Source/history frame
checks remain distinct from useful-throughput measurements. Separate preparation,
queue, execution and observation latency populations.

STRIDE/LINDDUN cover tuple/scope substitution, borrowed evidence, replay refresh,
disclosure and retention exhaustion at these interfaces. Do not label ordinary
telemetry with source, paths, raw identities, handles or tokens. No production
telemetry installation or provider timing/policy truth follows from the placement
contract. MELT/RED/USE/golden signals retain their existing bounded capture rules.
