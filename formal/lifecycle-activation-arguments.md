# Lifecycle activation argument capture

Nine existing forms cover source load, annotation restore/baseline adoption,
SaveAs activation, pure rebind and view/workspace create/retire. They use four
existing F17 variants. This is ordinary-data capture and reconstruction, not
provider execution, authority creation or a new command/profile.

## Shared declarations and classification

The source-load, annotation-load and SaveAs intake guards use the same immutable
field/profile declarations as capture. Other selected field lists come from the
same rebind and relation catalogs as the native guards. Three legacy wrapper-field
mutation targets are retargeted to those guards without weakening their assertions.

Exact outer/nested fields and fixed variant/contract/operation/profile/phase/action
values determine the form. All 36 row pairs have a common fixed path with different
values. If a record matched two rows it would give that path both values, a
contradiction under ordinary-data comparison. Thus classification is unambiguous
relative to this nine-form vocabulary. Every named form also has a positive native
witness on both routes. This is not completeness of every F17 profile or behavior.

Request/context capture uses the existing bounded finite-worklist copier.
Independent byte/node/depth ceilings and the caller/native maximum constrain
accepted data. Typed/dynamic syntax is excluded from semantic comparison, while
invocation value, form, request, context and limits remain. Caller mutation cannot
change the owned record; producer reconstruction preserves its meaning.

Native authority and writer handles are not serialized into that record.
Original ports must still match the actual prepared native intent. A source-load
capture does not perform a read: its native activation authority refers to already
completed provider work. Native restoration, baseline adoption, binding changes
and container publication remain separate operations with their existing guards.

## Scoped reference evidence

Seven controls cover eighteen actual-owner reuse/publication compositions, 361
refusals, eighteen foreign authority/context-port refusals, nine exact logical
boundaries and 36 discriminator pairs. Fifteen mutations challenge closure,
discriminators, effective limits, ownership, agreement and producer routing.
Only assertions count as semantic detections; module construction and arbitrary
tool/process failures do not. Invalid ordinary-data refusal includes explicit
no-throw checks; unsupported proxy/native-code containment is not established.

Positive compositions reuse an already prepared actual native intent and then
execute/observe through its owner. They do not install the additional forms into
the envelope adapter or prove a first grant from metadata. The larger source-load,
annotation-load, SaveAs and container corpora remain full-suite obligations.

## Remaining gates and instrumentation

Complete F17 envelope-owner integration/results/events/discovery, temporary parent
reservation, physical/global bounds, actual host/workload evidence and independent
assurance remain open. There is no numeric product default or new model component.
The selected source graph is 94 modules without frontend imports; engine/UI variants
remain 76/11.

IF-01/03/04/05/07/08 and INS-01/02/03/04/05/07/08/09/12/13 keep completed provider
work, capture, native binding, publication and recipient release distinct. Ordinary
labels exclude source, annotation bodies, probes, locators, contexts and invocation
strings. Full frozen qualification and endpoint reconciliation are required before
adoption.
