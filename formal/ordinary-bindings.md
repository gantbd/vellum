## Identity and final activation

Apply specification §11.1's existing identity comparison contract: known
equivalence, known distinction and insufficient/incomparable evidence. Different
path spellings, provider IDs, content, formats or identity-domain strings do not
prove distinct resources. For two present ordinary bindings, require current
known distinction under the declared supported host identity profile. Known aliases,
unknown comparison and stale evidence cannot satisfy that requirement. Absence is
an explicitly unbound ordinary role under complete current coverage, not an omitted
row, failed lookup or an unresolved proposed destination.

Binding creation, rebind and SaveAs activation validate the complete current pair
and affected registry together under the existing serialized coordinator. A source
proposal must account for the current annotation binding and vice versa. The host
must not validate two proposals independently against an old unbound opposite and
then publish a colliding pair. Fresh preparation, refusal or bounded deferral uses
the owning operation's existing disposition contract; this policy creates no new
public verb, lock service, queue, error code or implicit migration.

Ordinary save admission/final dispatch preserve the same pair and current binding/
identity obligations. Losing required distinction does not authorize format
replacement. The host identity/continuity profile states its actual guarantee;
this policy does not create an unavailable universal physical-alias oracle.

## Conditional solver evidence

`ordinary-binding-laws.smt2` has eleven exact-manifest conditions. Nine conditions
each require satisfiable premises followed by an unsatisfiable violating case;
two deliberately weakened rules admit satisfiable counterexamples.

| Condition | What is checked |
|---|---|
| OD-KNOWN-DISTINCTION | Given a sound current distinction supplier and the complete-pair gate, two present accepted bindings occupy different actual equivalence classes |
| OD-KNOWN-EQUIVALENCE | Known equivalent destinations refuse even when overwrite authority is true |
| OD-UNKNOWN, OD-INCOMPARABLE | Insufficient or incomparable comparison is not promoted to distinction |
| OD-CURRENT-PAIR, OD-STALE-DISTINCTION | Stale pair validation or stale positive identity evidence cannot authorize activation |
| OD-UNBOUND-ABSENCE | A known-unbound opposite role needs no fictitious comparison evidence; complete coverage and current pair checks still apply |
| OD-SERIALIZED-PAIR | An intervening pair change defeats an old validation epoch |
| OD-WRITE-SKEW-CONTROL | Omitting the final pair check lets two independently valid old-empty proposals collide |
| OD-LOCATOR-DIFFERENCE-CONTROL | Different locators can still identify the same actual resource |
| OD-EXPORT-FRAME | A separately authorized export can target the source destination without changing an already valid ordinary binding pair |

Resource-class integers and logical validation epochs are mathematical variables,
not selected native handles, platform keys or public counters. Sound identity
comparison, complete coverage, current authorization and serialized host validation
are supplied premises. The model does not implement a resolver, binding registry,
native activation, ordinary annotation save/load, or hostile-object decoder. These
are conditional gate/frame and selected race arguments, not implementation proof,
complete transition exploration, physical accounting or independent certification.

Separately authorized explicit exports retain §16.3.2's shared FIFO, overwrite/
create grants, receipt/effect barriers and release checks. An export may replace
external bytes; preserving ordinary bindings proves neither external freshness nor
that their historical saved baselines still describe those bytes. Export is not
ordinary binding activation, and it cannot silently create or bless a shared pair.

## Initial native binding profile

Specification §16.2.4 uses `binding-pairs.json/.mjs`,
`binding-pair-profile.mjs` and `binding-pair-checks.mjs`. These are trusted normalized
reference inputs, not a hostile decoder or public Rust/wire API. An existing writer
owns opaque preparation plans. Its actual authority must match the current root;
another same-authority writer does not acquire a plan by copying its handle.
Matching an authority label is not proof that this is the host's sole writer;
actual writer uniqueness/complete coverage remain supplied host premises.

Initialization explicitly adds `ordinaryBindings: {generation: 1, annotations: null}`
to an existing live document under complete current absence/coverage attestation.
The source role remains the actual existing `binding`, including explicit null.
Unknown legacy annotation state cannot be inferred absent from a missing field.
The private historical source-only primitives remain usable by their older reference
fixtures; they are not evidence that full production v1 pair activation is complete.

The selected phase progression is legacy-unknown to explicitly-unbound to
annotation-bound. Only the first two forward metadata changes apply; a validated
identical bound request returns unchanged and other phase/operation combinations
refuse. Finite registry scans and owned-value bounds govern these helpers, not a
claim that the whole host or an arbitrary caller loop halts.

Initial annotation binding captures a unique full current write registration,
adds one `artifact: annotations` row to the actual resource-owner registry and
advances the inventory/binding generation and metadata publication once. Registry
rows and bindings must agree exactly; known keys cannot collide with source,
foreign owners or pending export reservations. Current trusted comparison binds the
document and both full bindings, with relation `distinct`; different labels/keys
alone do not substitute for the declared sound host comparison. An explicitly
unbound source requires no invented comparison, but still needs current inventory,
coverage, identity and permission facts. Unknown comparison is not known absence.

Owned plans copy the original source/inventory, complete owner/registration basis,
request and finite limits. Caller aliases cannot rewrite intent. Final construction
requires that basis and current grants again; unrelated current source/view fields
are preserved rather than replaced by an old prepared root. The returned root and
registry are one candidate, not two installed writes. Roots, source/comment versions,
history, baselines and provider effects are not mutated during preparation/refusal.
Identical current binding is validated unchanged, without allocating an unused
counter. Annotation rebind/unbind is deliberately outside this initial product:
retained baseline/history/effect transfer must be specified before those operations.

Activated actual source-save admission and dispatch require a valid current native
pair and exact current basis/comparison. Source SaveAs and rebind validate the
proposed source binding against the actual current annotation binding, including
final activation. Structural ownership and current provider evidence are distinct:
check the addressed document's registrations without making an unrelated stale
provider block an independent source save. Whole-registry binding preparations
still conservatively need fresh validation if their captured registry changes.
The existing reader's owner lookup refuses a typed annotation
key, including when a source-read candidate was prepared before annotation binding.
It cannot create another source owner or overwrite the document at later activation.

Document uniqueness uses the canonical authority/id/incarnation tuple, not JSON
member order. The shared writer's common grant sets require exact-true values;
this does not establish a complete decoder for every host fact or future gateway.

Explicit source-copy and native annotation exports still use the actual shared
writer. A typed annotation ownership row is recognized as its same-document owner;
temporary export reservations are removed without deleting that ordinary binding.
No source/annotation saved baseline or external freshness follows. Disposal retains
the binding and full provenance release refuses until a subsequent supported
annotation-binding release path has discharged its obligations. That path is not
fabricated from cancellation, quiescence or removing the source binding.
