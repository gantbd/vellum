# Native read result metadata and discovery

Explicit `owned-contract-discovery/6` describes the existing F02/F03 native
results. It preserves /5's seven rows and six read operations, enriching only
the two read descriptors. Profiles /1–/5 retain their exact products. No operation,
transport, issuer or execution contract is added.

## Result structure and authority

`read-engine-descriptor.mjs` builds six inline JSON Schema 2020-12 schemas from
immutable declarations used by actual result guards. Thirteen branches describe
existing range/line, single/coherent acquisition and annotation page/record/location
values, including each unavailable product. Coverage is
`native-value-structure-only`: schemas describe JSON-compatible shadows, not a
native-token serialization protocol.

Closed fields, safe natural numbers, byte domains, two-element ranges, four
delimiter forms, class sets and participant documents retain their meanings.
Annotation content/location facets may be absent; detached placement is explicit.
Point targets preserve position/content profiles and before/after affinities.
Distinct native record aliases may have identical JSON shadows. Structural array
uniqueness must not replace native identity uniqueness.

Actual guards still bind original requests, opaque identities, captured source
references/bytes, annotation placement, requested classes/participants, fresh alias
publication, current authority and retained lifetimes. Each descriptor names these
runtime bindings and excludes token authenticity from shape, request-dependent
equality, public wire encoding, hostile ingress and physical/global/independent
refinement. Exact fixed metadata recognition admits no callbacks or external
references; no schema resolver is added.

## Disclosure and resources

Existing owner-origin, captured-ceiling, current-recipient, absorbing-withdrawal,
target-advice and protected-retirement rules govern /6. A generic matching
descriptor does not acquire builtin origin. Discovery selectors are not read
contexts or annotation records. Metadata disclosure does not authorize execution.

Entry/variant, row/metadata byte, node/depth, packet and reply bounds remain
independent. The inline descriptors require metadata depth 22; a depth-16 fixture
refuses them without disabling older profiles. A depth-32 test fixture admits them.
Neither fixture selects or raises a product default. No reference resolver bypasses
the envelope. Global/parent/physical accounting remains separate.

## Evidence

`read-result-metadata-checks.mjs` combines 862 standard-validator cases across six
schemas, 78 positive native products, seventeen schema-valid/runtime-refused cases,
four alias non-authority cases, 42 recognition denials and eight product controls.
Thirteen discovery controls cover 42 metadata denials, five loss cases and both
descriptors. Nine envelope dimensions have 27 exact boundary cases. Positive native
assertions precede projection; unavailable replies cannot silently replace successful
native or discovery cases.

`read-result-metadata-mutations.mjs --bank=0` through `--bank=5` partitions 55
semantic mutants into banks of ten/nine/nine/nine/nine/nine. Every bank runs the
entire combined corpus against a coherent copied graph. Construction, syntax,
validator tool/protocol and arbitrary process failures do not count as detections;
the expected failure must be a semantic assertion. Existing standard-validator
tool/protocol controls remain unchanged.

`read-result-discovery-substrate-checks.mjs` preconstructs 21 discovery fixtures
and two annotation fixtures before intercepting 143 filesystem/process callables.
All thirteen selected discovery controls make no baseline calls; injected read,
rename and process calls are each detected. This is selected post-import execution
evidence, not import isolation, production dependency separation or containment of
all host APIs.

Two older annotation-result and three older read-discovery mutation construction
targets follow named declarations while preserving their original challenges.
Older settings-schema, ordinary-edit, search-discovery and builtin banks retain
their seven/seventeen/forty/nine semantic mutations and pass. Full frozen
verification and endpoint reconciliation remain required before adoption. The
reference graph remains 89 engine modules, with 76 engine and eleven presentation
variants. Complete result/event/selector and other-family coverage, host/policy
truth, measurement, physical/global/concurrent/crash refinement and independent
assurance remain open. No whole completion row closes; finite checks do not
establish categorical completeness.
