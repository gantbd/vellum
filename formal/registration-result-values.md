# Existing native registration and created settings result values

F16 has three distinct released result products. Host registration rows contain
native table, provider, resource and generation data under the existing trusted
host release gate. Scoped registration rows contain only basis indices and
present/absent decisions. Created-settings rows carry the original opaque
references issued by an explicit pre-admission result hold. These products must
not be substituted for one another or made public by validating their shape.

Each product is exactly unavailable or a result containing the invocation,
applied/unchanged status and its own row array. Available empty arrays are valid.
Native registration identity incarnations and non-null generations are
nonnegative safe integers, including zero. Host rows have distinct native slots.
Scoped indices form a permutation of the complete zero-based domain, preserving
request order rather than requiring sorted indices. Created indices are dense
and ordered; references are distinct objects whose internals are never inspected.
Copying such an object can preserve shape without preserving native authority.

The finite corpus contains 678 actual native releases: 257 host-registration,
353 scoped-registration and 68 created-settings replies. The selected short
registration corpora and full created-settings corpus retain 63 named controls.
Every intercepted read preserves its root identity and reported invocation
usage. Release-time snapshots preserve opaque references, while separating other
returned data from later alias mutations in the producer tests. Eight structural
positives and 225 malformed cases bring the checker corpus to 911 cases.

Twenty pure-checker mutations use the same corpus after native production.
Construction/import errors do not count as detection. Sparse-array corruption
removes both independent hole checks. Redundant single-guard removals that leave
the same rejection behavior are not presented as detected semantic faults.
The baseline invokes no data accessors and performs no reflection into an opaque
proxy witness. Validation-only substrate checks are separate from producer and
import behavior.

Validation assumes prebounded native frames. Plain/null-prototype records and
dense arrays reject extra, hidden, symbol and accessor fields. Labels are nonempty
lossless UTF-8. This does not select a product-wide integer width, isolate arbitrary
proxies or establish physical accounting. The stateless checker is not installed
in native production or observer admission; it selects no public result route,
codec, disclosure grant, query-time reference minting or retroactive result hold.
Combined-reply reservation, current native release, original roles, protected
cleanup and the distinction between observer fault and producer outcome remain.

IF-01/02, PATH-02 and INS-01/03/08/09/12/13 retain stage-bounded validation,
release, fault and cleanup observations. MELT/golden/RED/USE and STRIDE/LINDDUN/
privacy/hazard reviews must distinguish malformed shape, unavailable disclosure
and native execution failure without logging row identities, reference contents,
configuration values or payload-derived labels. This adds no telemetry pathway
or runtime component. Full frozen qualification and endpoint adoption remain
required; public mapping, integration and operational/independent gates remain.
